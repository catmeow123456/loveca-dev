## 实验提示变化

作者在[第 141 次决定调查](2026-09-10-188ba3ad-141.md)后明确要求增强 prompt，并强调自送回收属于通用策略。本轮在 `assets/ai-battle/tutorial.md` 补充：

- 满场时检查自送回收带来的空位与资源入口，计入离场损失。
- 回收资源成员后，比较填空位、其他位置换手、先用手牌补同伴条件等后续动作，核对整段净支付及最终收益。
- 区分成员回手再登场、能力直接登场与直接回收 LIVE，不能假设回手即登场或已经获得后续 LIVE。
- 比较单/多 LIVE 的合计需求和分数竞争，以及平局后的场面；不能把单张能唱成当作足以赢下本轮。
- 结束主要阶段前说明放弃的具体可见路线；留能量须有下次恢复前的实际用途，也不要求为花费而行动。

`src/server/ai-battle/model-client.ts` 的控制提示同步强调自送回收、腾位、同伴条件、跨位置换手和分数竞争。策略没有绑定具体卡号或构筑手册，所有构筑共用。教程仍在创建对局时冻结，既有对局不会自动替换教程。

## 固定输入对照

使用 `qwen3.8-max`，`temperature=0.2`、`max_tokens=2048`、`enable_thinking=false`。每版五个局面，每个局面原材料和新提示各重复三次；同一轮逐局面交替发送两种材料，第二次重复反转先后顺序。三版共 **90 次实际 HTTP 请求**，全部正常 `stop`、选择协议合法，无重试。

每对输入只替换控制提示和通用教程。原规则、构筑手册、己方卡组、完整决策输入、历史意图、候选顺序与引用均保持相同；准备脚本核对原请求及四份来源的完整性和 SHA-256，汇总脚本再次核对实际 HTTP body、模型参数及冻结消息。没有执行所选命令，也没有将这 90 次采样当成连续对局。

## 各版本与最终结果

| 版本 | 新提示在 141 的三次选择 | 保留情况 |
| --- | --- | --- |
| V1 | 3 次支付 7 能量直接换手；0 次自送 | 存在回能与获胜说明错误；回手再登场的措辞未明确限于成员 |
| V2 | 2 次结束，1 次自送 | 增加组合示例及来源条件检查后仍不稳定，未保留额外段落 |
| V3 | 3 次结束 | 当前版本：保留简洁通用策略，明确只有成员回手再登场才需登场预算，直接回收 LIVE 用于设置 |

每版相配的原材料均为 3 次结束。V1 的行动改善没有在措辞更准确的最终 V3 中复现，不能把早期结果作为当前版本修复成功的证据；小样本也不能证明哪一处措辞单独导致变化。

141 的直接换手候选是 `PL!HS-sd1-001` 费用 9「日野下花帆」替换右侧 `PL!HS-PR-014` 费用 2「日野下花帆」，支付 7 后实际剩余 2 能量。V1 三次自述均错误套用回能效果，声称剩余 4 能量；选择合法不能证明预算正确。

最终 V3 仍有明显事实错误：141 的一次输出为未登场的 `PL!HS-sd1-006` 费用 15「安养寺姬芽」预留 LIVE 开始费用；另一次把该能力归给中央的 `PL!HS-bp5-001` 费用 11「日野下花帆」，并称“唱成5分即可获胜”。它也仍忽略可以先补同伴再兑现资源成员收益的顺序。μ's 样本保持发动 `PL!-sd1-005` 费用 2「星空凛」直接回收 LIVE，但这是首步选择，不能据此宣称后续补场、判心或整局强度通过。

当前 prompt 的知识覆盖已扩大，**空费、自送回收完整路线、能力来源绑定和分数竞争仍未通过策略验收**。此前独立 `GameSession` 已证明替代路线可执行；本轮没有再重演表演或完整比赛。下一步应围绕回手后的合法登场预算与组合收益提供可核验事实，不能仅靠继续追加提示句来宣称问题解决。
