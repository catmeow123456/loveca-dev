本机已建立仅启动 API 的恢复脚本（仓库外，无凭据内嵌）：

```text
../ai_battle/AI对战基础设施/restart-local-codex-api-20260913.sh
```

当前 API 窗口使用该脚本，明确设置已核验 Node 的 PATH、读取并验证现有本地测试配置，再启动 API。若需再次重启当前已恢复的窗口，可执行 `tmux respawn-pane -k -t loveca-test:api`；这仅适用于当前已替换的启动命令，会中断 API 和内存对局。脚本不执行数据库重建、迁移、种子导入或卡库同步命令。它临时将 API 对象存储指向本机，避免接触 `.env` 中的远端存储；本机 MinIO 未运行，所以上传功能暂不可用，未修改 `.env` 或 Vite 图片代理配置。

若以后使用当前版本启动脚本重新建立测试环境，下面的 `.env` 方式也可用，因为当前脚本已在启动命令中加上 `--env-file-if-exists=.env`。不要把磁盘上新版脚本的行为等同于仍在运行的旧进程。

开关默认关闭。现有测试 API 使用的本地 `.env` 或启动环境需明确包含：

```dotenv

```

同时要求 `NODE_ENV=development`、`DATABASE_URL` 指向回环主机，以及 `FRONTEND_URL` 为本机 HTTP 地址，例如 `http://localhost:5173`。当前磁盘上的测试启动脚本会显式传入这些原测试环境参数，并让 API 读取 `.env` 中的额外设置。修改后需重新加载 API 进程；不要为了开关调用会重建数据库、同步卡库的全套测试环境脚本。本批没有修改 `.env` 或创建真实对局；当前 API 启动参数已通过上述恢复脚本明确启用。

启用后，API 实际绑定指定回环地址；所有 `/api` 请求还检查原始 socket 对端、Host、Origin 和代理来源，覆盖可能间接唤醒 AI 的共享对局命令入口。前端 Origin 只允许配置的本机端口（localhost/127.0.0.1/::1 别名），或者 API 自身 origin。Vite API 代理开启 `xfwd`，追加真实对端；非回环来源、跨站来源或不明确的 Forwarded 头被拒绝。

这些条件是明确的部署约束，不是自动证明“机器上没有生产数据”。不得把本机生产转发端口伪装成测试库，也不得用会丢失真实来源信息的代理暴露入口。当前已核实的测试库是 localhost:5432/loveca，0039/0040 已迁移；不需要平台 Qwen 上游配置就能创建 Codex 对局。

前端从受权限保护的 `/models` 获取可用模型。关闭开关只提供 Qwen，伪造 Codex 创建请求也会被服务拒绝；开启后默认选 Luna，可手动选择其他已登记的 Codex 模型或 Qwen。现有管理员权限和对局所有权检查继续生效。

创建请求可选 `reasoningEffort: low | medium`，仅对 Codex 有效；不提供时沿用服务端默认。前端明确提交选定值，服务端校验并冻结到本局 provider、会话及模型配置观察，不改写全局环境变量。Qwen 不显示此选项，也拒绝携带该字段的创建请求。降低强度不减少每次发送的上下文。

## 调用、观察与用量

- CLI 版本暂限已验证的 `0.153.4`、`0.154.0-alpha.6.2`；后者于 2026-09-14 重新验证严格参数、临时目录外文件读取拒绝及真实结构化返回后加入。其他版本仍拒绝；升级后应先重新核验隔离选项，不自动降级。每次调用检查 ChatGPT 登录，子进程环境采用白名单，不传 API Key、数据库凭据、桌面线程路由等变量。`forced_login_method=chatgpt` 阻止切换 API 认证。
- 默认每请求使用新临时目录、stdin 与结构化输出，`model_instructions_file` 替换 CLI 默认编码指令；忽略用户配置和规则，不加载项目 AGENTS 或主机技能。禁用 shell、MCP 配置、插件、应用、浏览器、计算机操作、代码执行宿主、记忆等入口。权限配置只开放最小运行路径与当前临时工作目录，命令网络关闭。禁止工具访问的提示词仅作为补充。
- 固定知识与紧凑玩家观察复用作者输入。CLI wire schema 固定描述 ACTION/CARDS 输出形状，当前引用只放在输入中，原始完整 `responseSchema` 仍留在请求正文；分组、数量、去重、跳过等合法性由原响应解析与权威规则链裁决。CLI 返回 JSON 不表示动作已执行。
- 单次 Codex 窗口上限 90 秒；取消会终止进程组，500 ms 后仍未退出则强制终止。超时或 CLI/认证失败停止 AI，不自动重试模型、不转 Qwen/API。已返回的非法候选仍由作者原有失败/兜底策略处理。Qwen 原超时和重试策略保留。
- CLI 的启动 `item.error` 是诊断记录，不当作工具执行；`turn.failed`、缺失完成事件、工具执行记录或超限输出拒绝。日志不导出 CLI stderr。真实烟测已出现并覆盖“代码执行宿主已禁用”诊断。
- Codex 的 `ai_billing.prices`、`pricingDate` 与投影 `estimatedCny` 为 null，前端显示 ChatGPT 订阅及 token 用量，不显示 ¥0。输入与缓存输入分开累计；缺失或矛盾 usage 保持未知。当前未确立缓存写入的计量口径，出现非零 `cache_write_input_tokens` 时记为未知，不静默套用 Qwen 口径。调用次数指 provider 决策请求：默认一次 exec，实验模式一次 app-server turn；不宣称等于内部 HTTP 请求数或套餐剩余额度。
- Qwen 既有记录格式及价格保持原样。新增 Codex JSON 记录需要本分支的读取代码；旧作者分支不了解订阅计费格式。不要为切分支删除历史记录，也不要把 Codex 用量伪装成 Qwen。

### 临时会话实验开关

仅需要继续验证此方案时，在现有本地环境显式设置 `AI_BATTLE_CODEX_SESSION_REUSE=1` 并重新加载 API，新建的 Codex 对局才采用实验模式；省略或 `0` 保持独立 exec。本批没有修改 `.env` 或替用户开启实验。前端“本局模型配置”观察中，`EPHEMERAL_EXEC` 与 `EPHEMERAL_APP_SERVER_EXPERIMENT` 可区分两种路径。保持原回环、开发环境和 ChatGPT 登录门禁。

实验实现使用每局每席独立线程、一次在途 turn；静态知识首轮发送，后续追加完整当前脱敏观察。REQUEST 记录 `sessionTurn`、`includesStaticKnowledge` 和 `contextMode`；历史选择不表示已执行，原规则链决定实际结果。固定 schema 允许 ACTION/CARDS，变化的候选、数量与分组约束留在当前输入。

app-server 使用独立空白 CODEX_HOME 和工作目录，不复制用户配置、规则或 auth.json。通过官方 `chatgptAuthTokens` 接口把现有 CLI 登录的 access token 与 account ID 传入子进程内存，凭据不进入模型输入、日志或 trace，不读取其他对局资料。该认证接口为实验接口；现有登录必须可从 CLI auth.json 读取，不支持只有 keyring 的登录。账号变化会停止；如上游要求刷新，只接受桌面/CLI 已更新的同账号 token，至多提供一次，绝不自行改写原登录或切换 API Key。实际调用已验证此路径可用。

拒绝工具执行、审批 RPC 和异常输出；终局、显式结束、停止、超时、取消与初始化失败均关闭进程组并清理临时目录。服务正常退出或收到 SIGTERM/SIGINT 时也清理进程；被 SIGKILL 或机器断电无法保证清理，因此仍不把敏感历史写入持久 rollout。每轮用量取 `tokenUsage.last`，缺失仍为未知，不重复累加线程 total。

当前实验不自动压缩历史：发送前以累计输入/输出正文 1 MiB、上一轮已知输入 token 加本轮 UTF-8 字节的保守上界 150,000、以及报告上下文窗口的 75% 为限，超限停止且不自动新建会话恢复。这是调试边界，尚未完成长局容量验收。

原始账本、虚构请求、离线请求对比及复跑脚本在仓库外 `ai_battle/AI对战基础设施/cache-diagnostic-20260914/`。官方参考：[app-server 与外部 ChatGPT 认证](https://learn.chatgpt.com/docs/app-server)、[缓存规则](https://developers.openai.com/api/docs/guides/prompt-caching)、[配置](https://learn.chatgpt.com/docs/config-file/config-reference)。
