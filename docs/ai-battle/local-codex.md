# 本地 Codex 订阅对战接入

> 类型：部署专题说明；适用范围：已有本地测试环境的开发者；状态：本地试用，非生产服务。

在作者 AI 对战链路上增加本机 Codex provider，保留原 Qwen/API 配置与权威规则链。模型只收到 AI 席位观察和合法选择，输出仍经过作者原有校验与执行。推荐使用 Luna medium、同线程续接及达到上下文水位后换线程；这些能力需显式配置，不能把“代码已拉取”当作“进程已启用”。

## 本机准备

先检查现有仓库、启动方式、Node/CLI 路径、API 与前端端口、环境变量来源和测试库，不照搬其他机器的目录、tmux 名称或凭据。沿用已能运行作者 AI 对战的测试环境；本增量没有新增依赖包、数据库迁移、卡库或对象存储操作。作者 AI 功能自身需要的 `0039/0040` 迁移应已完成；缺失时先按原迁移说明核对测试库，不为启用 Codex 重建数据库或重新初始化卡库。

- 使用仓库 `package.json` 要求的 Node/pnpm；依赖安装沿用锁文件。
- API 进程必须能执行本机 Codex CLI，并使用该进程所属用户自己的 ChatGPT 登录。程序拒绝 API Key 认证，不会回退到 Qwen。该用户需有可用的目标模型权限与额度。
- `AI_BATTLE_CODEX_PATH` 必须是 CLI 可执行文件的绝对路径。源码兼容默认值为 `/Applications/ChatGPT.app/Contents/Resources/codex`，其他安装位置需明确覆盖，不能假定该路径存在。
- 显式启用的本地测试不限制 CLI 版本，应用更新后无需逐版修改白名单；启动仍要求 CLI 可执行且 `login status` 确认为 ChatGPT 登录。实际调用继续使用 `--strict-config`、文件/工具隔离及原响应校验；若升级导致参数或协议不兼容，调用失败即停，不自动移除隔离参数或切换 API。可用 `--version`、`login status` 排查，不产生模型调用。历史真实调用实证来自 macOS（0.153.4 与 0.154.0-alpha.6.2）及 Linux（0.154.0），允许新版本尝试不等于逐版兼容性已验收。
- 同线程模式读取进程环境 `CODEX_HOME` 或默认用户目录下的 `.codex/auth.json` 中现有 ChatGPT 登录，仅将所需 token 送入子进程内存。仅钥匙串登录暂不支持。只检查存在性、可读性与登录状态，不输出或发送文件正文；不要复制他人凭据，不覆盖原 Codex 配置。
- 使用已有本地测试账号及 `rules.manage` 权限进入 AI 对战。这里沿用作者的测试入口，不要求访问生产管理页面。

## 服务端环境配置

在现有 API 启动器、进程管理器或其实际读取的本机未跟踪环境文件中设置。以下是配置示例，路径和端口须按本机实际值填写；不要原样执行占位路径，不提交个人环境文件。

```dotenv
NODE_ENV=development
API_HOST=127.0.0.1
FRONTEND_URL=http://localhost:5173
AI_BATTLE_LOCAL_CODEX=1
AI_BATTLE_CODEX_PATH=/absolute/path/to/codex
AI_BATTLE_CODEX_REASONING=medium
AI_BATTLE_CODEX_SESSION_REUSE=1
AI_BATTLE_CODEX_THREAD_ROTATION=1

# 推荐长局测试预算；每项独立可调，未配置的项不参与限制
AI_BATTLE_CODEX_MAX_CALLS=120
AI_BATTLE_CODEX_MAX_INPUT_TOKENS=18000000
AI_BATTLE_CODEX_MAX_UNCACHED_INPUT_TOKENS=3000000
AI_BATTLE_CODEX_MAX_OUTPUT_TOKENS=100000

# 可选：只提供归档复选框，建局时默认不选
AI_BATTLE_LOCAL_ARCHIVE=1
AI_BATTLE_ARCHIVE_DIR=/absolute/path/outside/repository/loveca-ai-archives
```

保留自己的 `DATABASE_URL`、JWT 等原配置。数据库必须是回环地址上的本地 PostgreSQL 测试库，`FRONTEND_URL` 必须是本机 HTTP origin；`API_HOST` 只接受 `127.0.0.1` 或 `::1`。不要把远端生产库隧道视为测试库。开启本地能力后整个 AI 路由还检查真实连接来源、Host、Origin 和代理头；不支持把入口经公网/局域网代理开放给其他机器。

端口不必与示例一致，但必须核对实际 API 监听和前端代理目标。当前仓库的 Vite 配置使用本地 3007 API；若本机不同，沿用并核对已有代理安排，保留真实来源校验，不通过放宽门禁解决连通问题。Docker 中的 localhost 是容器自身：CLI、登录文件与 API 用户需处于可访问的运行环境，数据库仍须满足现有回环条件；不要复制宿主默认值后直接声称容器可用。

环境文件中填写展开后的绝对路径，不假定 `.env` 自动展开 `$HOME` 或 `~`。如果在 shell 启动器中设置，则可用 `export AI_BATTLE_ARCHIVE_DIR="$HOME/loveca-ai-archives"`；应确认该目录位于仓库外。

配置必须进入真正启动 API 的进程。另开终端执行 `export` 不会改变已经运行的 API 或既有 tmux 窗口。注意启动器显式环境变量可能覆盖 `.env`。

## 构建与首次检查

先结束并导出当前内存对局，再执行 `pnpm build:server`，通过本机原有方式重启 API；开发前端沿用现有启动方式，若使用构建产物则按原流程更新前端。服务端使用 `--watch` 时，构建本身也可能触发重启。不要为了开启 Codex 运行会重建测试库、导入种子或同步子模块的全套环境脚本。

刷新本地建局页，本地 Codex 可用时默认选择 **gpt-6-luna**，也可选择 gpt-6-sol 或 gpt-6-astra；5.6 系列不再列入可选模型。测试时可选择中等（medium）强度；前端当前初始强度是 low，并显式提交选项，服务端 medium 默认不能覆盖前端的 low。新局冻结模型、强度、速度、资料、预算与归档选项，进行中对局不随配置变化。

本地 Codex GPT 建局页可勾选“快速模式”，默认关闭，不影响 Qwen/API。开启时向隔离 CLI / app-server 请求 `priority` 服务层级，每次续接与换线程沿用本局设置，记录为 `fastMode` 与 `requestedServiceTier`；这表示请求的层级，不保证上游实际加速。关闭时不继承个人 Codex 快速模式配置。按[官方速度说明](https://learn.chatgpt.com/docs/agent-configuration/speed)，GPT-6 快速模式消耗标准模式的 2.5 倍 credits；不是 token 数翻倍，现有 token 预算也不等于套餐额度上限。快速模式不改变思考强度，不压缩输入。

“本局模型配置”应显示：

- `transport: EPHEMERAL_APP_SERVER_EXPERIMENT`
- `staticKnowledge: FIRST_TURN_OF_EACH_GENERATION`
- `threadRotation: true`、`reasoningEffort: medium`
- `budget` 四项为本机所选值；使用推荐配置时为 120、18000000、3000000、100000。

只看到 `EPHEMERAL_EXEC` 表示未启用续接。未设置本地总开关时不显示 Codex；只开总开关仍默认独立 exec，不等于推荐配置。先做配置、版本、登录和本地连通检查；真实建局前由本机用户确认消耗其订阅额度及测试范围，不将他人历史授权当成本机授权。短测确认正常后由用户继续长局，无需另行调用合成模型实验。

用量显示为“ChatGPT 订阅”及输入/缓存/输出 token，不折算为人民币、套餐百分比或账户剩余额度。同一线程的后续窗口可命中缓存；首轮、换线程首轮可为零，续轮也不保证每次命中。UI 决定记录含等待/机械推进，不等于模型调用次数。机械动作与批量 LIVE 设置沿用作者实现。

## 用量、隔离与停止行为

推荐值是本地启动配置，不是源码强制默认。四项分别限制本局调用次数、含缓存总输入、非缓存输入、输出，任一达到阈值就不再发送下一次请求。token 在响应后结算，最后一次可能超过阈值；换线程不重置预算，新建对局重新计数。没有每日/账户级总预算，也没有套餐百分比止损。一个 API 进程只允许一局未结束 Codex 对局，不限制其他进程或项目的消耗。

单请求超时 90 秒，用量未知、调用失败或环境/认证检查失败即停止，不自动重试或切换到付费 API。真人思考时间不计入该 90 秒模型请求时限。

同线程模式使用隔离的临时 `codex app-server`，首轮传固定资料，续轮追加当前观察；模型上下文仍包含历史，缓存不是免计输入。达到 CLI 报告上下文窗口的 80% 后，下次请求前换线程，携带固定资料、当前输入及此前本席实际收到的公开事件；不复制旧完整快照或模型摘要，不自动原生压缩。历史副本按唯一事件 JSON 的 UTF-8 字节累计，最多 256 KiB（原 128 KiB 已在正常 T6 长局触及）；重复事件不重复计数，整批校验后才写入，不裁剪旧证据。缺失、冲突或超限仍停止。历史容量报错与 `HISTORY_STOP` 材料会列出本次累计字节和上限；包含固定资料、历史及当前观察的单请求仍独立受 512 KiB 限制，请求过大通过 `CONTEXT_STOP` 列出实际大小，均在模型调用与计费开始前停止。这两个字节上限不等于模型 token 上下文或调用次数预算。

CLI 尚未报告窗口大小时使用既有 150000 token 水位，报告后按窗口更新。历史扩容不保证任意长局永不触限，上游仍可能拒绝超大请求，也不构成下一轮 token 的硬保证。扩容回归已用 T6 停止局的 56 个相关窗口离线重放：343 条历史事件完整保留，强制频繁换线程的最大请求 294453 字节；将历史补到新上限的合成样本，换线程请求为 419985 字节，低于 524288 字节。回放使用假模型运输，不执行对局命令，不代表该局已续打终局或模型策略重新验收。

子进程禁用模型的文件操作、shell、网络工具、MCP、插件等外部能力；模型服务连接由 CLI 自身完成。临时工作目录及同线程模式独立 CODEX_HOME 不复制用户项目、个人规则或历史。ChatGPT 认证接口依赖 CLI 的实验能力，因此版本升级可能需要重新验证。账号变化停止，不自动换号；不记录认证文件正文或 CLI stderr。

## 完整复盘归档

开启上述两个归档环境变量后，在建局页勾选“完整归档到本机”。它独立于模型供应方，不增加模型调用。`AI_BATTLE_ARCHIVE_DIR` 必须是 API 用户可写的仓库外绝对目录；首次使用创建目录，每局保存 `loveca-ai-<matchId>.jsonl`。未勾选不创建归档，旧局不能补录。

观察面板“导出当前缓存”仍是有限 JSON；“导出完整归档”是持续采集的 JSONL，缓存淘汰不影响已归档内容。每局256MiB、待写队列8MiB；超限或写入失败标记不完整，不停止对局。目录没有总容量限制或自动删除。重启后文件保留但不恢复内存对局/HTTP会话，崩溃可能丢失待写尾部。优先对局结束后下载，完整性、格式及访问契约见[运行与观测说明](runtime-and-observation.md#可选的本地完整归档)。

材料包括 AI 私有视角与策略，只供授权复盘，不上传公开仓库；公平试打时先结束对局再查看对手私有观察。源码、通用配置示例可提交，个人 `.env`、登录凭据、归档和实验产物不可随分支分发。

## 常见接入问题

| 现象 | 优先检查 |
| --- | --- |
| 页面连接不上 | API 是否启动、Node 路径、构建输出、实际端口与前端代理；先看本地错误，不重建数据库 |
| 没有 Codex 选项 | 运行进程是否收到本地开关与合法回环配置，是否仍在运行旧构建 |
| CLI/登录检查失败 | 指定路径可执行性、同一进程用户的 ChatGPT 登录与 auth.json 可读性；本地测试不再检查版本白名单 |
| 续轮仍反复完整输入 | 模型配置是否为 app-server 同线程模式，而非默认独立 exec；同时核对实际强度 |
| 归档复选框不存在 | 运行进程是否启用归档能力，目录是否按环境文件语法填写 |
| 归档建局失败 | 目录是否在仓库外、可写、磁盘是否可用；符号链接指向仓库内也拒绝 |
| 达到预算 | 导出当前材料并检查实际累计；不要自动重开或无上限重试 |

已完成一局内存自然终局（含水位换线程）及4次真实前端短测；不代表不同机器已验收或策略强度合格。完整归档目前通过假模型/隔离浏览器验证，尚未完成真实模型自然局归档验收。已知展示问题：批量 LIVE 的命令摘要可能显示“等待或未执行”，结束后的观察仍提示真人牌桌继续运行；执行成败以权威结果和会话状态为准。

实现入口：`src/server/ai-battle/local-codex-config.ts`、`codex-process.ts`、`codex-session.ts`、`codex-model-client.ts`、`local-archive.ts`。CLI 接口背景见[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)；实际支持范围以本分支代码与测试为准。
