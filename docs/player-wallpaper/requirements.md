# Loveca 玩家自定义游戏桌壁纸需求与安全边界

> 文档类型：专题说明
> 适用范围：个人中心、共享游戏桌、玩家图片上传、MinIO 对象存储
> 当前状态：首版实现基线；生产上线仍需完成第 18 节运维确认
> 创建日期：2026-08-13
> 维护说明：本文维护产品规则、隐私与安全边界及验收项；实现架构由同目录 `design.md` 维护

## 1. 背景

Loveca 当前所有对局模式复用 `GameBoard` / `PlayerArea`。游戏桌根层使用统一背景图，并在背景上叠加牌桌遮罩、舞台光效、区域、卡牌和规则交互。登录用户已经可以在个人中心维护公开身份、登录邮箱、密码和个人徽章。

玩家希望在不改变规则桌布局和对局信息的前提下，为自己看到的游戏桌设置个性化壁纸，并在保存前预览宽屏牌桌和紧凑牌桌的实际效果。宽屏牌桌通常对应 PC、笔记本和平板横屏，紧凑牌桌通常对应手机纵屏，但资源选择必须跟随现有 `GameBoard` 的响应式布局判定，而不是根据设备名称、User-Agent 或屏幕方向另做推断。两种布局的画幅差异较大，应支持分别上传图片；同时不应强迫只想快速设置一张图的玩家准备两份素材。

该能力属于玩家个人视觉偏好，不属于权威对局状态。它不应改变卡牌规则、命令权限、玩家视图投影、隐藏信息、历史记录或回放内容。

## 2. 产品目标

### 2.1 核心目标

1. 登录用户可在个人中心设置自己看到的宽屏牌桌和紧凑牌桌壁纸。
2. 宽屏与紧凑布局使用两个独立展示槽位，允许选择内置纯色或分别上传图片；图片可以调整主体位置。
3. 紧凑布局默认继承宽屏选择：纯色直接继承预设，图片则生成独立的紧凑展示资源；宽屏为系统默认时紧凑也回退默认。
4. 保存前使用接近真实游戏桌的预览展示卡牌、区域、遮罩和壁纸之间的关系，并可切换日间／夜间牌桌效果。
5. 每个账号按北京时间自然日最多成功发布一次新壁纸配置。
6. 图片由服务端校验、重新编码后存储于 MinIO，不接受任意外部图片 URL。
7. 自定义壁纸只影响当前观看者，不向对手、观战者或回放记录传播。
8. 自定义图片加载失败时，游戏桌自动使用系统默认背景，不影响进入对局和继续操作。

### 2.2 成功标准

- 玩家无需上传图片即可选择内置纯色，也能完成选图、双布局预览、裁切和一次统一保存。
- 宽屏和紧凑牌桌都不会因壁纸设置出现明显拉伸、错位或主要操作不可读。
- 只上传宽屏图片的玩家无需额外上传紧凑图片，也能通过“跟随 PC 壁纸”获得可用的紧凑牌桌效果。
- 同一天同时或快速重复提交时，服务端最多接受一次有效配置变更。
- 上传失败、图片处理失败、MinIO 写入失败或数据库保存失败均不消耗当天更换次数。
- 联机双方可以在同一局中看到不同的个人壁纸，且不产生任何对局状态差异。
- 观战、历史回放、对墙打、本地调试和正式联机继续复用同一套游戏桌背景展示边界。
- 页面不暴露 MinIO 写入凭据、可枚举对象列表、其他用户的壁纸配置或可用于访问其他用户资源的内部标识。若最终采用短期签名 URL，浏览器可以看到仅代表本人资源、不可猜测的 opaque 路径标识；该标识不得作为公开业务字段返回。

## 3. 非目标

首版不包含：

- 让对手、观战者或公开个人主页看到玩家上传的壁纸。
- 将壁纸写入 `GameState`、玩家视图投影、权威 checkpoint、对局历史、回放、聊天或积分数据。
- 按玩家席位把一张游戏桌拆成上下两块不同壁纸。
- 壁纸商城、交易、赠送、收藏、点赞、分享码或公开展示页。
- 管理员运营主题壁纸目录或赛季限定壁纸解锁。
- GIF、动画 WebP、APNG、SVG、视频、音频、Lottie 或交互式背景。
- 从互联网 URL、社交平台或第三方图床导入图片。
- 首版为离线访客提供云端壁纸；未登录或纯离线模式继续使用系统默认壁纸。
- 使用图片识别自动判断版权归属、人物身份或内容是否合规。
- 为自定义壁纸建立与规则桌不同的第二套 `GameBoard` / `PlayerArea`。

## 4. 用户与可见性边界

### 4.1 登录玩家

登录玩家可以：

- 查看自己的当前壁纸配置和下一次可更换时间。
- 为 PC 和手机分别选择图片。
- 将同一张源图复用到两个槽位。
- 在保存前反复选择、移除、重新裁切和预览图片。
- 每个自然日成功发布一次发生变化的壁纸配置。
- 随时恢复系统默认壁纸。

登录玩家不能：

- 读取其他玩家的壁纸配置或对象地址。
- 指定任意外部 URL 作为游戏桌背景。
- 绕过服务端格式、大小、内容和每日次数校验。

### 4.2 对手与观战者

- 对手始终看到对手自己的壁纸配置或系统默认壁纸，不看到上传者的壁纸。
- 授权观战者看到观战者自己的壁纸配置或系统默认壁纸。
- 壁纸不成为玩家身份、席位、房间或对局快照的一部分。
- 对手壁纸加载状态不得通过网络协议、DOM 文案、错误反馈或日志暴露给其他参与者。

### 4.3 历史回放与只读桌面

- 历史回放继续使用当前查看者此刻的个人壁纸，而不是记录对局发生时的壁纸。
- 更换或删除壁纸不会改变已封存对局的内容哈希、checkpoint 或回放投影。
- 若产品后续需要可复现的公开录像主题，应另行设计平台主题背景，不能复用玩家私人壁纸字段。

### 4.4 未登录与离线用户

- 未登录用户、离线访客和无法读取个人偏好的客户端使用系统默认背景。
- 首版不把用户上传图片写入 `localStorage`、IndexedDB 或离线卡组资产。
- 登录状态失效时立即停止请求新的个人壁纸授权读取句柄；已经加载的背景可自然结束当前页面生命周期。

## 5. 产品定义

### 5.1 两个独立展示槽位

壁纸配置包含：

- `PC / 宽屏壁纸`：用于现有牌桌判定为非紧凑布局的场景。
- `手机 / 紧凑壁纸`：用于现有牌桌判定为紧凑布局的场景。

界面可以继续使用玩家更容易理解的“PC”和“手机”简称，但实现、接口和测试必须以现有响应式牌桌布局判定为准。当前判定边界为 `isMobileBattlefield` 使用的 `(max-width: 767px)`；后续若牌桌统一调整断点，壁纸资源选择必须随同一入口变化，不能保留第二份常量。

两个展示槽位属于同一份壁纸配置和同一次发布操作。它们使用明确的判别状态：

- 宽屏槽位：`DEFAULT | SOLID | CUSTOM`。
- 紧凑槽位：`INHERIT_PC | SOLID | CUSTOM`。

`SOLID` 只能引用服务端和客户端共享的固定纯色预设标识，不接受任意 CSS 颜色值，也不创建图片资源。`INHERIT_PC` 表示紧凑槽位继承宽屏选择：宽屏为 `SOLID` 时直接使用同一预设；宽屏为 `CUSTOM` 时复用规范化母版，但仍生成独立紧凑展示资源并保存独立裁切和主体焦点。宽屏槽位为 `DEFAULT` 时，`INHERIT_PC` 自然回退到系统默认壁纸。

更换任意源图、调整任意布局的裁切，或同时修改两种布局，都只产生一次配置发布。

首版回退顺序如下：

| 当前牌桌布局 | 首选资源                      | 第一级回退                          | 最终回退     |
| ------------ | ----------------------------- | ----------------------------------- | ------------ |
| 宽屏牌桌     | 宽屏 `SOLID` 或 `CUSTOM` 成品 | `CUSTOM` 加载失败时跳过该成品       | 系统默认壁纸 |
| 紧凑牌桌     | 紧凑 `SOLID` 或 `CUSTOM` 成品 | `INHERIT_PC` 纯色或独立派生图片成品 | 系统默认壁纸 |

不使用紧凑壁纸反向填充宽屏槽位。只上传紧凑图片而没有宽屏图片时，宽屏牌桌继续显示系统默认背景，避免把竖图强制放大为低质量横向背景。

### 5.2 “跟随 PC 壁纸”

- 玩家可通过明确的“手机端跟随 PC 壁纸”操作将紧凑槽位设为 `INHERIT_PC`。
- 复用不等于两个预览使用同一裁切参数或同一展示对象；两种布局仍分别保存裁切区域、主体焦点并生成成品。
- 紧凑槽位处于继承状态时，界面应明确显示“跟随 PC”；宽屏纯色和图片都可继承，不能伪装成紧凑槽位保存了第二份预设或文件。
- 玩家可以随时在未保存草稿中把紧凑槽位改为独立图片或恢复复用。
- 替换宽屏源图时，旧紧凑裁切不能直接套用到新图片；处于 `INHERIT_PC` 的紧凑预览应以居中默认值重新初始化，并要求玩家在保存前确认紧凑预览。

### 5.3 一次统一保存

- 页面只有一个主操作：“保存壁纸”。
- 纯色预设、宽屏图片、紧凑图片、槽位模式及两种布局的裁切和主体焦点参数作为同一份候选配置提交。
- 保存前必须展示“今天保存后将不能再次更换壁纸，明天 00:00 后可再次更换”的明确确认。
- 没有任何资源或裁切变化时，“保存壁纸”不可用，不消耗次数。
- 保存成功后，两种布局资源作为同一配置版本生效；不得出现宽屏已更新而紧凑仍处于半完成状态。

### 5.4 恢复默认

- “恢复默认壁纸”用于清除当前账号的纯色预设和所有自定义图片引用，并立即回退到系统默认背景。
- 恢复默认不消耗当天更换次数，也不恢复当天已经消耗的发布额度。
- 玩家当天刚保存壁纸后仍可恢复默认，但必须明确提示“恢复后今天不能再次保存新壁纸”。
- 恢复默认需要二次确认，因为该操作会清除当前配置中的纯色选择和全部自定义图片引用。
- 对象存储中的旧资源按保留和清理策略异步删除，不要求在用户等待期间同步完成物理删除。

## 6. 个人中心体验

### 6.1 设置入口

- 在个人中心新增独立设置区“游戏桌外观”。
- 该设置区与公开身份、登录邮箱、密码等账户设置保持同一视觉系统，但不与公开身份字段混在同一表单中。
- 设置区首先展示预览主题切换和当前双布局预览，再展示纯色／图片选择、裁切和保存状态。
- 页面加载个人偏好失败时只在该设置区显示内联重试，不阻断个人中心其他设置。

### 6.2 页面状态

设置区至少覆盖以下状态：

1. 从未设置：显示系统默认背景、纯色预设和“选择图片”。
2. 已设置且今日可更换：显示当前配置、下一步操作和可用保存额度。
3. 已设置且今日额度已用：允许查看和预览当前配置；禁用新的发布操作，并显示下一次可更换时间。
4. 未保存草稿：显示本地候选图片、裁切状态和明确的未保存提示。
5. 图片处理中：禁用重复保存，保留当前预览，不用全页遮罩阻断个人中心。
6. 保存失败：保留候选草稿，并在设置区内说明失败原因和可执行的下一步。
7. 当前资源失效：预览使用系统默认背景，并提供重新加载或下次可用时重新上传的说明。

### 6.3 图片选择

- 宽屏和紧凑槽位均提供同一组有名称的固定纯色预设；选中纯色不需要文件上传、裁切或对象存储。
- 宽屏和紧凑槽位分别提供明确的文件选择入口和拖放区域。
- 文件选择器只提示支持 JPEG、PNG 和静态 WebP，但服务端仍必须验证真实格式。
- 选择文件后先使用浏览器本地对象 URL 预览，不在每次选择或拖动裁切时上传 MinIO。
- 编辑当前已保存配置时，可以从仅本人可读的规范化母版重新裁切，无需重新上传原文件；若母版因保留策略已不可用，界面必须要求重新选择源文件，不能把已裁切成品伪装成完整源图。
- 玩家可以在保存前移除候选图片、重新选择文件或撤销回当前已保存配置。
- 浏览器离开页面或候选文件被替换时，应释放本地对象 URL，避免长期占用内存。

### 6.4 双布局预览

- 宽屏页面同时展示宽屏牌桌预览和紧凑牌桌预览，便于直接比较主体位置。
- 窄屏页面使用“PC / 手机”分段控件切换宽屏与紧凑预览，不把两张缩小到无法辨认。
- 预览必须包含真实牌桌使用的背景层、遮罩层和光效层，并使用代表性的卡牌、区域轮廓和状态控件展示可读性。
- 预览提供明确的“日间 / 夜间”切换；切换只改变预览实例，不修改账号的全局主题。两种状态必须复用正式牌桌对应主题的同一遮罩 token，夜间继续使用暗色遮罩，日间使用浅色遮罩。
- 预览不启动真实 `GameSession`，不读取真实对局、卡组或隐藏卡牌，也不渲染一套可操作的假对局。
- 预览和正式牌桌必须复用同一个背景展示组件；代表性卡牌、区域轮廓和状态控件可以使用不可交互的预览 fixture，但不能复制另一套背景、遮罩和舞台光效样式。
- 裁切可以通过拖动画面主体或可访问的方向/位置控件完成；不得只依赖拖拽。
- 预览应显示安全区域提示，帮助玩家避免把人物脸部、文字或 Logo 放到主要卡牌区和控制区下方。
- 裁切结果除保存裁切区域外，还应保存归一化主体焦点。正式牌桌继续使用 `background-size: cover` 时，应以该焦点映射 `background-position`，减少非标准比例下的二次裁切损失。
- 标准预览以宽屏 16:9、紧凑 9:16 为主要画幅；验证还必须包含至少一种超宽或接近 4:3 的宽屏容器，以及现有断点两侧的 767px / 768px 场景。预览文案不得承诺所有设备都具有完全相同的可见裁切范围。

推荐宽屏结构：

```text
┌────────────────────── 游戏桌外观 ──────────────────────┐
│ 今天可保存 1 次                      下次重置：明天 00:00 │
│                                                        │
│ ┌────────── PC / 宽屏牌桌预览 ──────────┐ ┌ 手机/紧凑 ┐ │
│ │ 牌桌遮罩、区域轮廓、示例卡牌与候选背景 │ │ 纵向牌桌层级 │ │
│ └──────────────────────────────────────┘ └────────────┘ │
│                                                        │
│ PC / 宽屏壁纸：[选择图片] [调整位置] [移除]            │
│ 手机 / 紧凑：  [选择纯色] [选择图片] [跟随 PC 壁纸]   │
│                                                        │
│ JPG / PNG / 静态 WebP，每张不超过 8 MB                 │
│                                      [恢复默认] [保存壁纸]│
└────────────────────────────────────────────────────────┘
```

### 6.5 牌桌可读性

- 玩家不能关闭规则桌原有遮罩、舞台光效和区域背景。
- 纯色与自定义图模式应具有固定的最低遮罩强度，确保明亮、高对比和复杂背景不会遮没卡牌边缘、区域名称或合法目标反馈。
- 自定义壁纸使用的有效遮罩强度不得低于系统默认背景在同一布局下的可读性基线；具体 token 应在实现前通过代表性明亮、暗色、高对比和高细节图片的截图评审冻结，玩家不能把它调低到该基线以下。
- 首版不提供完全透明遮罩选项。
- 若后续提供“壁纸亮度”或“背景明暗”设置，其允许范围必须受服务端或固定前端边界约束，并纳入双布局预览。
- 壁纸不能覆盖规则弹窗、Active Effect、Public Reveal Dwell、判定面板、错误反馈、卡牌详情或拖放目标层。
- 壁纸资源加载和切换不应产生影响操作的闪白；新图片完成下载和解码前继续显示旧背景或系统默认背景，准备完成后再原子替换。若使用短暂淡入，应遵守既有 reduced-motion 设置。

## 7. 每日更换规则

### 7.1 时间口径

- “每天一次”按北京时间 `Asia/Shanghai` 的自然日计算。
- 当日时间范围为北京时间 00:00:00 至次日 00:00:00 之前。
- 接口返回权威的 `nextChangeAt`；客户端不得自行根据本机时区推断是否可保存。
- 页面显示具体可再次更换时间，例如“明天 00:00 后可再次更换”。
- 每日一次是产品发布规则，不代替上传安全限频。上线前应以处理成本、滥用风险和小范围体验确认其必要性；后续如调整，必须修改服务端规则和公开文案，不能只在客户端放宽。

### 7.2 消耗额度的操作

以下操作在成功生效后消耗当天一次额度：

- 首次发布任意自定义壁纸。
- 替换宽屏壁纸。
- 替换或新增紧凑壁纸。
- 从独立紧凑纯色／图片切换为“跟随 PC 壁纸”，或反向切换。
- 修改任意一端的裁切结果并保存。
- 在同一次保存中同时修改上述多项。

以下操作不消耗额度：

- 选择文件、本地预览、调整尚未保存的裁切或取消草稿。
- 提交与当前配置完全相同的无变化请求；此类请求应直接拒绝或作为 no-op 返回。
- 文件格式、尺寸或内容校验失败。
- 图片处理、MinIO 写入、数据库写入或网络响应失败且新配置未生效。
- 查看当前配置和下一次可更换时间。
- 恢复系统默认壁纸；但恢复默认不会返还已经消耗的额度。

### 7.3 服务端权威与并发

- 每日额度只能由服务端校验，前端禁用按钮不是安全边界。
- 多标签页、多设备或并发请求同一天只能有一个配置版本成功生效。
- 服务端必须使用数据库原子条件或等价并发控制写入新配置，不允许“先查询、后无条件更新”。
- 成功判定以新对象已经可读取且数据库活动配置已经切换为准。
- MinIO 与 PostgreSQL 不共享事务；实现必须处理对象已上传但数据库竞争失败、数据库成功但旧对象删除失败等补偿场景。
- 活动配置版本、北京时间发布日占用记录和本次成功结果必须在同一 PostgreSQL 事务中提交；对象写入应先完成并验证可读，再尝试切换活动配置。
- 客户端重复点击和网络重试应使用幂等提交标识，不能把同一次保存误算为多次尝试。
- 幂等记录至少按 `userId + idempotencyKey` 唯一，并保存规范化请求指纹、处理状态和最终配置版本。同一幂等键携带不同请求内容必须返回稳定冲突错误。
- 成功幂等记录至少保留到对应 `nextChangeAt` 之后的合理网络重试窗口；处理中重试应返回同一处理状态或等待原任务，不能重复启动 Sharp 编码和对象写入。
- 如果数据库已经成功提交但响应在网络中丢失，使用同一幂等键重试必须返回原成功结果和同一个 `nextChangeAt`，不能返回“今日额度已用”。使用不同幂等键提交另一份配置时才按每日规则拒绝。
- 与当前活动配置完全相同的规范化请求应在占用每日额度前作为 no-op 返回。
- “恢复默认壁纸”同样携带当前配置版本和幂等标识；它不占用每日发布额度，但不得在并发时静默覆盖另一页面刚发布的新配置。

### 7.4 上传尝试限频

- 每日成功一次不代替上传接口的安全限频。
- 服务端应同时限制单账号和单来源地址的上传尝试频率、并发处理数和单位时间输入总字节数。
- 无效图片、超大图片和冷却期内的请求应尽早拒绝，避免进入完整 Sharp 解码和 MinIO 写入流程。
- 具体软限额可在实现阶段根据实际资源确定，但不得高于部署硬上限，也不得只依赖浏览器限制。

## 8. 图片资源要求

### 8.1 支持格式

- 支持 JPEG、PNG、静态 WebP。
- 不支持 SVG、GIF、APNG、动画 WebP、视频或其他容器格式。
- 不接受外部 URL、Data URL、Base64 JSON 字段或压缩包。
- 不信任文件扩展名和浏览器上传的 MIME；服务端按实际解码结果判定格式。

### 8.2 输入限制

- 每张源文件最大 8 MB。
- 应用 EXIF 方向后，源图每边至少 720 像素。
- 单边最大 8192 像素。
- 解码后总像素量不得超过 32 MP。
- 最终裁切区域必须具有足够的有效像素：宽屏 16:9 裁切区域至少 1280 × 720，独立紧凑图的 9:16 裁切区域至少 720 × 1280；紧凑槽位为 `INHERIT_PC` 时允许最低 540 × 960，以保证推荐的 1920 × 1080 宽屏图能够完成纵向派生。仍不满足时拒绝保存并指出对应槽位。不能只根据源图总尺寸判断清晰度。
- 宽屏槽位推荐横向 16:9，推荐尺寸 1920 × 1080 或更高。
- 紧凑槽位推荐纵向 9:16，推荐尺寸 1080 × 1920 或更高。
- 图片不符合推荐比例但满足安全尺寸时可以进入裁切预览，不直接按比例拉伸。

具体上限在实现前应使用目标服务器内存、Sharp 并发和移动端加载性能进行验证；如调整，必须同步更新前端提示、服务端校验和本文档。

### 8.3 服务端处理

- 服务端必须重新解码并编码所有上传图片，不把原文件直接作为在线资源。
- 自动应用 EXIF 方向，转换到受支持的 sRGB 表达，并移除 EXIF、ICC 中不需要的隐私元数据和其他附加内容。
- 原始上传文件只存在于本次受控处理生命周期，成功生成规范化母版或处理失败后都应及时删除，不得作为在线资源或长期对象保留。
- 当前活动配置可以为每个仍被引用的独立源图私有保留一份重新编码、去元数据且受尺寸上限约束的规范化母版，用于以后重新裁切。紧凑槽位为 `INHERIT_PC` 时复用宽屏母版，不重复保存。规范化母版仍属于用户私有资源，不能被游戏桌直接读取，也不能进入公开图片路径。
- 裁切区域和主体焦点使用应用 EXIF 方向后的坐标系，并以与源尺寸无关的归一化值保存；服务端必须校验范围、比例和最小有效像素，不能信任客户端裁切结果。
- 根据用户确认的裁切区域和主体焦点生成宽屏与紧凑展示资源。紧凑槽位为 `INHERIT_PC` 时，两种布局共享规范化母版，但仍输出两个不可变展示对象。
- 宽屏输出建议不超过 1920 × 1080，紧凑输出建议不超过 1080 × 1920。
- 最终资源统一使用静态 WebP；质量和体积上限由实际视觉验证确定，首版目标为两种布局成品合计不超过约 2 MB。
- 透明图片可以保留静态 Alpha，但共享背景组件必须在预览和正式牌桌使用同一个固定 `--board-wallpaper-base` 底色和混合方式；该底色不能因页面主题或预览容器不同而产生意外差异。若实现阶段决定服务端铺底，则必须使用同一冻结色值并同步删除客户端二次铺底差异。
- 服务端处理超时、内存上限或编码失败时拒绝本次发布，不保留可被访问的半成品配置。

### 8.4 版权与内容要求

- 上传入口应明确提示玩家只能上传自己有权使用的图片，不要上传隐私照片或包含个人敏感信息的内容。
- 禁止违法内容、色情内容、仇恨内容、骚扰性内容和恶意视觉内容。
- 即使首版只有上传者自己可见，平台仍实际存储用户内容，必须保留按账号停用、移除资源和配合投诉处理的运营能力。
- 首版不承诺自动内容审核准确性；是否接入自动审核服务应在上线前根据用户规模和运营风险另行决定。
- 管理员移除违规壁纸后，服务端应立即把活动配置切换为默认并停止签发新的读取句柄；已打开页面在下一次偏好刷新或现有授权句柄到达约定失效边界时回退默认。浏览器已经下载和解码的像素无法被服务端追回，文档和运营流程不得承诺绝对即时撤回。管理员操作不应使用户突破当日次数限制。

## 9. MinIO 存储与隐私

### 9.1 Bucket 边界

- 玩家壁纸不得直接放入当前公开读取的卡牌图片 bucket 并被描述为私密资源。
- 推荐使用独立的私有 bucket，例如 `loveca-user-assets`，或使用具备同等私有读取边界的独立存储配置。
- 私有 bucket 不设置匿名 `s3:GetObject` 权限。
- 当前 `minio-service.ts` 的默认 bucket 初始化会设置公开读取策略；玩家资源必须使用独立 bucket 配置、独立初始化入口和显式私有策略，不能把私有 bucket 传入现有公开 bucket 的 `ensureBucket()`。
- 浏览器只通过登录后的本人接口取得短期授权读取句柄，不获得 MinIO Access Key、Secret Key、真实对象键字段或可枚举对象列表。
- 授权读取方式必须在实现前从以下方案中明确选择并记录：同源鉴权资源端点配合服务端流式读取或内部代理；受保护 CDN / Nginx 鉴权读取；或短期 MinIO/S3 签名 URL。前两种方案向浏览器只暴露 opaque asset ID；签名 URL 方案会把仅代表本人资源的不可猜测路径作为短期 bearer 能力暴露给浏览器，必须明确有效期、日志脱敏、缓存和撤销边界。
- 如果生产 S3 API 端口继续只允许主应用或可信网络访问，则不能直接把指向该内部端点的 MinIO 签名 URL 返回给浏览器；应使用同源鉴权代理或受保护的外部读取层。
- 若最终决定使用公开资源地址，必须在产品文案中明确披露，并经过单独隐私评审；不得默认为当前方案。

### 9.2 对象键与缓存

- 对象键使用服务端生成的不可猜测版本标识，不把用户名、邮箱、显示名称或原始文件名写入对象键。
- 新版本使用新对象键，不覆盖旧对象，避免 CDN、浏览器和签名 URL 缓存继续展示旧图。
- 活动配置只保存对象键和资源元数据，不保存 MinIO 凭据或长期公开 URL。
- 玩家接口以 opaque asset ID 或短期授权 URL 表达可读资源，不把对象键作为独立 JSON 字段返回。若使用签名 URL，浏览器能够查看自己的短期 URL 不视为泄露，但该 URL 不得进入公开接口、前端持久化状态、分析事件或未脱敏日志。
- 授权读取句柄过期后，客户端重新读取自己的偏好获取新句柄；过期不得导致对局中断。
- 已加载图片可以继续使用浏览器缓存；新进入或刷新页面时必须以服务端当前活动配置为准。
- 私有资源应使用 `Cache-Control: private`、内容版本标识和合适的 ETag；不得因刷新授权句柄而无条件重复下载内容完全相同的活动图片。

### 9.3 保留与清理

- 首版只长期保留当前活动配置引用的规范化母版和处理后展示资源；不长期保存用户提交的原始上传文件。
- 新配置成功生效后，旧配置的规范化母版与展示资源一起进入短暂保留或异步清理队列。
- 上传成功但数据库未引用的孤立对象必须有定期清理机制。
- 清理任务删除对象前必须再次确认没有活动配置引用，避免并发发布或补偿流程误删当前资源。
- 恢复默认、封禁账号或删除账号后的资源清理应遵守统一数据保留政策。
- 对象存储备份、容量告警、失败重试和灾难恢复由生产对象存储运维边界负责。

## 10. 数据与接口边界

### 10.1 私有偏好模型

壁纸配置建议使用独立的玩家私有偏好表，不直接增加到公开 Profile 投影。至少需要表达：

- `userId`。
- 当前配置版本。
- 宽屏槽位模式 `DEFAULT | SOLID | CUSTOM`。
- 紧凑槽位模式 `INHERIT_PC | SOLID | CUSTOM`。
- 两个槽位各自的纯色预设标识；仅对应槽位为 `SOLID` 时非空，`INHERIT_PC` 不复制紧凑预设。
- 当前活动配置所引用的规范化母版集合，包括内部对象引用、宽高、字节数和内容摘要；宽屏与紧凑均为 `CUSTOM` 时可以各自引用一份母版，`INHERIT_PC` 必须复用宽屏母版，不能复制出含义不明的第二份“源图”。
- 宽屏和紧凑展示资源各自的内部对象引用、宽高、字节数、裁切区域和主体焦点；未启用的槽位字段必须为空并由模式约束。
- 最后一次成功发布时间。
- 按北京时间计算的发布日占用记录或等价原子限制字段；应由数据库唯一约束或等价事务条件保证同一账号同一发布日最多一次。
- 创建时间、更新时间和可选的管理员移除信息。
- 与配置发布分离的幂等请求记录，至少包含用户、幂等键、规范化请求指纹、状态、最终配置版本和必要的过期时间。

公开个人资料接口不得返回壁纸对象键、签名 URL、裁切数据、最后更换时间或审核状态。

### 10.2 概念接口

详细路径可在实现设计中调整，首版至少需要以下能力：

- 读取自己的当前壁纸配置、槽位模式、短期授权读取句柄、当日额度和 `nextChangeAt`；只有个人中心编辑投影可以读取当前活动规范化母版，游戏桌投影只能读取当前布局的展示成品。
- 上传并原子发布一份包含宽屏、紧凑、槽位模式、纯色预设、裁切区域和主体焦点的候选配置。
- 恢复系统默认壁纸。
- 管理员按账号移除违规壁纸并记录原因。

接口要求：

- 所有玩家读取和写入接口必须登录。
- 玩家接口只能操作当前认证账号，不能接受任意 `userId` 作为授权依据。
- 上传使用受限 multipart 文件字段；拒绝未知字段和超出数量的文件。
- multipart 中的配置 JSON 必须通过严格 schema 校验，明确槽位模式、纯色预设、当前资源复用、裁切区域和主体焦点；服务端不能根据缺失文件字段猜测槽位语义，也不能接受预设之外的任意颜色值。
- 响应只返回前端展示需要的私有投影，不返回内部 MinIO 配置。
- 保存和恢复默认请求都携带当前配置版本和幂等标识；版本冲突时要求重新读取，不能静默覆盖另一设备刚保存的配置。
- 冷却期拒绝应返回稳定错误码、权威 `nextChangeAt` 和可用于 `Retry-After` 的时间信息。

### 10.3 与认证状态的关系

- 登录、刷新会话或进入个人中心时可以按需读取私有壁纸偏好；不要求把完整壁纸字段加入公开 Profile。
- 进入共享 `GameBoard` 前可以并行读取壁纸偏好，但读取失败或超时不得阻止牌桌渲染。
- 登出、切换账号或会话失效时必须清除内存中的上一账号壁纸配置和签名 URL。
- 客户端持久化状态不得让同一浏览器的下一账号短暂看到上一账号壁纸。

## 11. 游戏桌集成要求

### 11.1 展示层边界

- 自定义壁纸只进入前端展示偏好层，不进入 `GameSession`、`GameService`、command、`projector` 或任何规则状态。
- `GameBoard` 根据当前观看者的私有偏好选择背景资源。
- 紧凑资源选择必须复用现有牌桌的 `isMobileBattlefield` 判定，不使用另一套 User-Agent、屏幕方向判断或宽度常量。断点切换时允许重新选择并预加载对应资源，但不能重建或改变权威对局状态。
- 对墙打、本地调试、正式联机、远程调试、观战和历史回放继续复用同一个背景展示组件。
- `PlayerArea`、卡牌区域、拖放目标、Active Effect 和其他规则 UI 不感知壁纸对象键。
- 背景展示组件只接收展示层需要的授权资源 URL、主体焦点、加载状态和是否为自定义图等最小属性；它不得接收规范化母版引用、内部对象键或每日额度状态。

### 11.2 加载与降级

- 牌桌先以系统默认背景立即渲染；个人壁纸完成下载和解码后再原子切换，不在中间显示空背景或浏览器破图。
- 可在进入牌桌前预加载当前响应式布局对应的处理后资源，但预加载失败不得阻塞对局。
- 图片请求返回 401/403、授权句柄过期、404、解码失败或超时时回退系统默认背景。
- 回退只产生展示层可观测日志，不向对手发送任何错误或状态。
- 壁纸错误不能导致 React 错误边界替换整个 `GameBoard`。

### 11.3 视觉层级

从低到高至少保持：

1. 系统默认背景或玩家壁纸。
2. 牌桌遮罩、舞台光效和区域底色。
3. 卡牌、区域、牌堆和玩家信息。
4. 动画与局部反馈。
5. 规则确认、效果处理、公开展示、判定和关键错误。

壁纸不能通过定位、透明度、滤镜或堆叠上下文越过上述层级。

## 12. 错误与反馈文案要求

错误应在对应图片槽位或设置区内就近显示，并说明下一步，不以模糊全局提示代替。

至少区分：

- 文件过大：“图片不能超过 8 MB，请压缩后重新选择。”
- 格式不支持：“请选择 JPG、PNG 或静态 WebP 图片。”
- 像素不足：“图片分辨率过低，无法生成清晰的游戏桌壁纸。”
- 动画图片：“游戏桌壁纸暂不支持动画图片。”
- 处理失败：“图片处理失败，请重新导出图片后再试。”
- 当日额度已用：“今天已经保存过壁纸，明天 00:00 后可以再次更换。”
- 配置冲突：“壁纸已在另一页面更新，请重新载入后再编辑。”
- 存储失败：“壁纸暂时无法保存，当前游戏桌没有改变，请稍后重试。”
- 当前资源失效：“自定义壁纸暂时无法加载，已使用系统默认背景。”

按钮和结果文案保持一致：

- 主按钮：“保存壁纸”。
- 处理中：“正在保存”。
- 成功反馈：“壁纸已保存”。
- 默认操作：“恢复默认壁纸”。

## 13. 安全要求

- MinIO 写入权限只存在于服务端或受控任务，浏览器不能持有对象存储长期凭据。
- 上传使用服务端内存、临时文件或流式处理时必须具有明确的请求体、文件数、字节数、解码像素、处理超时和并发上限。
- 使用维护中的图片解码库，并对畸形图片、解压炸弹、异常颜色配置和伪造格式进行拒绝或安全失败。
- 重新编码后只向对象存储写入平台生成的 WebP，不直接公开原始上传内容。
- 日志不记录图片二进制、授权 URL 查询参数、MinIO 密钥、原始文件名或完整对象键。若使用签名 URL，反向代理、CDN 和应用访问日志必须关闭或脱敏 query string，并避免通过 `Referer` 传播 bearer 参数。
- 监控可以记录账号内部 ID、处理阶段、错误码、输入/输出字节数和耗时，但必须遵守隐私与日志保留政策。
- 管理员移除接口需要管理员鉴权、操作原因和审计记录。
- 禁止通过公开 Profile、应用公开配置、对局快照或前端源码下发其他用户资源地址。

## 14. 性能与可访问性

- 自定义壁纸不应显著增加个人中心首屏和非对局页面加载体积；图片选择和预览资源按需加载。
- 游戏桌只请求当前响应式布局需要的首选资源，不默认同时下载宽屏与紧凑两张大图；个人中心双布局预览不受此限制。
- 处理后资源尺寸应覆盖高像素密度设备，但不上传或下发无上限原图。
- 双布局预览在键盘操作下可选择槽位、调整位置、切换布局和保存。
- 所有图标按钮具有可访问名称，焦点可见，点击目标符合移动端尺寸要求。
- 壁纸为装饰性图片，不进入读屏顺序，不要求提供替代文本。
- 不仅依靠颜色表达当前槽位、保存状态、错误或每日额度。
- 壁纸是静态资源，不新增需要 reduced-motion 分支的背景动画；牌桌既有 reduced-motion 行为保持不变。

## 15. 运营与可观测性

首版可以记录不包含图片内容的聚合信号：

- 有自定义壁纸的账号数和占活跃账号比例。
- PC、手机独立图和“手机复用 PC 图片”的使用比例。
- 上传请求成功率，以及格式、大小、解码、存储、冷却和并发冲突错误占比。
- 输入和处理后图片的字节分布、处理耗时和 MinIO 错误率。
- 自定义壁纸加载失败和回退默认背景的比例。
- 孤立对象数量、清理任务结果和私有 bucket 容量趋势。

这些数据只用于产品、容量和故障评估，不进入排位、匹配、账号评分或对局裁判。不得采集或生成图片视觉内容标签作为首版默认分析数据。

## 16. 验收标准

### 16.1 个人中心

1. 登录用户可在个人中心看到“游戏桌外观”设置区。
2. 宽屏槽位只存在 `DEFAULT | SOLID | CUSTOM`，紧凑槽位只存在 `INHERIT_PC | SOLID | CUSTOM`，接口和界面不会产生含义不明的空状态。
3. 用户可以不上传文件而选择纯色，也可以只上传宽屏图并让紧凑槽位继承、只上传紧凑图而让宽屏使用默认背景，或分别上传两张图。
4. 宽屏页面可同时预览两种布局，窄屏页面可通过明确控件切换预览。
5. 预览包含与真实牌桌一致的背景、最低遮罩和舞台光效，并使用不可交互 fixture 展示代表性区域，不启动真实对局；用户可独立切换日间／夜间预览，两者使用正式牌桌同一主题遮罩 token。
6. 替换宽屏源图时，继承该图的紧凑裁切会重新初始化并要求确认，不会静默套用旧图片裁切。
7. 当前活动规范化母版仍在保留期内时，用户可以重新裁切当前图片而不必重新上传原文件。
8. 文件选择和裁切不会在保存前向 MinIO 写入对象；无变化请求不会消耗每日额度。

### 16.2 图片与存储

9. 合法 JPEG、PNG 和静态 WebP 可被服务端重新编码为受限 WebP。
10. 超大、像素过多、裁切有效像素不足、伪造格式、动画或损坏文件被明确拒绝，服务端不信任客户端裁切参数。
11. 原始上传文件只存在于本次处理生命周期，元数据不会进入规范化母版或展示对象；原始文件不被长期保留。
12. 当前活动配置可以保留去元数据、重新编码且受限的私有规范化母版；游戏桌无法直接读取母版。
13. 紧凑槽位为 `INHERIT_PC` 时，两种布局共享母版但生成两个独立、不可变的展示对象。
14. 玩家壁纸存储在独立私有读取边界中；没有有效授权读取句柄时不能读取对象，当前账号不能取得其他用户的读取句柄。
15. 客户端无法获得 MinIO 长期凭据、真实对象键业务字段或可枚举对象列表。
16. 新配置使用新对象键和内容版本，缓存不会在保存后继续展示旧图，也不会因刷新授权句柄无条件重复下载相同成品。
17. 透明图在个人中心预览和正式牌桌使用同一个固定底色与混合规则。

### 16.3 每日限制与一致性

18. 当天第一次有效保存成功后，服务端返回次日北京时间 00:00 的 `nextChangeAt`。
19. 同一天从另一设备、标签页或并发请求提交另一份配置时被服务端拒绝。
20. 同一次请求同时修改宽屏和紧凑图片只计算一次发布。
21. 格式校验、图片处理、对象存储或数据库失败且活动配置未切换时不消耗次数，当前配置不变。
22. 数据库已成功提交但响应丢失时，携带同一幂等键重试会返回原成功配置版本和 `nextChangeAt`，不会误报每日额度错误。
23. 同一幂等键携带不同规范化请求内容时返回稳定冲突错误，不会重放或覆盖原结果。
24. 恢复默认随时可用且不返还当天已经消耗的额度；恢复请求使用版本校验和幂等键，不能覆盖另一页面刚发布的新配置。
25. MinIO 成功但数据库保存失败时不会形成活动半成品；未引用对象可由清理任务识别和删除。
26. 活动配置版本、北京时间发布日占用和成功结果在同一数据库事务中提交，任何可见活动版本都只引用已确认存在的对象。

### 16.4 游戏桌

27. 登录玩家在所有共享 `GameBoard` 使用场景中看到自己的当前响应式布局壁纸。
28. 联机双方可看到不同壁纸，服务器权威状态和玩家视图投影保持完全相同。
29. 观战者和回放查看者使用自己的壁纸，不读取参赛玩家壁纸。
30. 紧凑槽位为 `SOLID` 时使用自身预设、为 `CUSTOM` 时使用紧凑成品；为 `INHERIT_PC` 时继承宽屏纯色或使用宽屏图片独立派生的紧凑成品；宽屏为默认时使用系统默认背景。
31. 宽屏槽位为 `DEFAULT` 时使用系统默认图，不把独立紧凑竖图反向填充宽屏背景。
32. 资源选择与现有 `isMobileBattlefield` 共用同一断点；767px / 768px、窗口缩放和方向变化不会产生第二套判断或改变对局状态。
33. 标准 16:9、9:16 以及至少一种超宽或接近 4:3 的容器中，主体焦点会映射到 `background-position`，`cover` 二次裁切不会无条件退回居中。
34. 图片 401/403、404、授权过期、超时或解码失败时自动回退默认背景，不阻塞对局，也不显示空白或破图。
35. 明亮、暗色、高对比或复杂壁纸下，卡牌、区域、合法目标、效果处理和关键错误仍保持可读。
36. 自定义壁纸不会出现在 `GameState`、checkpoint、回放 bundle、公共 Profile 或对局日志中。

### 16.5 账号与隐私

37. 登出或切换账号后，下一账号不会短暂看到上一账号壁纸或继续使用上一账号的授权读取句柄。
38. 未登录与离线模式使用系统默认背景。
39. 管理员可移除指定账号的违规壁纸并留下审计记录，玩家随后看到系统默认背景，且该操作不会使玩家突破当日发布次数。
40. 日志、公开接口和错误响应不包含授权 URL 查询参数、完整对象键、原始文件名或图片内容。
41. 若采用短期签名 URL，只有登录后的本人接口可以签发；复制该 URL 在有效期内具有 bearer 读取能力，此边界已在安全说明、有效期和日志策略中明确记录。

## 17. 建议实施边界

该功能不改变 `GameBoard` / `PlayerArea` 的规则布局，但会新增玩家内容上传、私有对象存储和个人偏好读取链路，属于独立产品增量，不应被视为当前“只收束对局外层 UI”工作的自然附带项。确定实施时应显式调整项目优先级，并按以下边界拆分。

### 17.1 数据与服务端

- 新增玩家私有壁纸配置表及对应停机迁移。
- 扩展对象存储服务以支持独立私有 bucket、独立初始化策略、选定的授权读取方式和安全删除，不复用现有公开 bucket 初始化入口。
- 增加原始文件受控解码、规范化母版、双布局成品生成、每日原子限制、持久幂等和补偿清理服务。
- 增加玩家私有读取/保存/恢复接口，以及最小管理员移除接口。
- 增加孤立母版和成品对象清理、私有资源日志脱敏及容量可观测性。

### 17.2 前端

- 在个人中心新增“游戏桌外观”设置区。
- 新增宽屏 `DEFAULT | SOLID | CUSTOM`、紧凑 `INHERIT_PC | SOLID | CUSTOM` 槽位、固定纯色预设、本地文件预览、双布局裁切和每日额度反馈。
- 预览增加不影响全局主题的日间／夜间切换，并复用正式牌桌主题遮罩 token。
- 从 `GameBoard` 抽取可复用的牌桌背景展示层，供真实桌面和预览共同使用。
- 新增私有壁纸偏好加载与账号切换清理，不写入权威 game store。
- 为所有共享 `GameBoard` 场景接入同一响应式资源选择、主体焦点和默认回退路径。

### 17.3 验证

- 服务端 focused tests 覆盖格式、大小、裁切有效像素、动画、母版生命周期、并发、每日边界、丢响应后的幂等重试、补偿和权限。
- 前端组件测试覆盖判别槽位状态、草稿状态、双布局回退、断点切换、账号切换和失败保留，不把普通说明文案当作主要断言。
- Playwright 覆盖个人中心纯色与上传闭环、宽屏/紧凑预览、日间/夜间遮罩、保存后牌桌显示、次日限制、恢复默认和 767px / 768px 资源切换。
- 视觉截图覆盖标准宽屏、紧凑、超宽或接近 4:3、日间/夜间、默认/纯色/明亮/高对比/复杂壁纸及自定义图片加载失败。
- 联机与回放验证以双方权威状态一致、各自壁纸独立和隐藏信息不泄漏作为结束条件。

## 18. 生产上线前待确认

以下事项在进入实现前需要完成一次产品与运维确认：

1. 生产 MinIO 是否建立独立私有 bucket，以及最终采用同源鉴权代理、受保护 CDN/Nginx 还是短期签名 URL；现有公开 bucket 初始化不得作用于该 bucket。
2. 每张 8 MB、32 MP、规范化母版尺寸上限及两种布局成品合计约 2 MB 的候选限制是否适合当前 API 实例内存、对象存储容量和 Sharp 并发。
3. 授权读取句柄的有效期、刷新策略、私有缓存、ETag、日志 query 脱敏和 `Referer` 策略。
4. 当前活动规范化母版、旧版本母版与成品、孤立对象和删除账号资源的具体保留时间。
5. 用户内容条款、违规投诉入口和管理员移除流程是否满足上线规模。
6. 每日一次是否在小范围体验后继续保留；若后续调整，只能发布新的明确规则，不在客户端静默放宽。
7. 系统默认 `deck.png` 是否继续作为唯一最终回退资源，或是否同步提供针对紧凑布局优化的系统默认图。
8. 自定义壁纸最低遮罩 token、固定透明底色、主体焦点映射和首批视觉截图基线。

## 19. 结论

自定义游戏桌壁纸与现有个人中心和共享游戏桌边界匹配；对象存储已有基础能力，但私有 bucket、授权读取和规范化母版需要作为独立增量设计后才能实施。首版应坚持以下边界：

- 宽屏槽位使用 `DEFAULT | SOLID | CUSTOM`，紧凑槽位使用 `INHERIT_PC | SOLID | CUSTOM`；纯色使用受控预设，图片继承只共享规范化母版，不共享成品裁切。
- 两种布局作为一份配置统一预览、统一保存，每个北京时间自然日最多成功发布一次，并以持久幂等和数据库事务保证重试及并发语义。
- 壁纸只属于当前观看者的展示偏好，不进入对局规则、投影、历史或回放。
- 原始上传文件不长期保留；当前活动配置保留私有规范化母版和宽屏/紧凑不可变成品，用于可靠重裁切与展示。
- 图片由服务端校验和重新编码，存入独立私有对象存储边界，并通过明确选择的授权读取方式提供给本人。
- 预览和真实牌桌复用同一背景展示层、响应式断点、主体焦点及主题遮罩 token；预览可独立切换日间／夜间，并保留最低遮罩强度和可靠默认回退。

完成上线前八项产品与运维确认后，该功能不会形成第二套牌桌或联机状态分叉，存储、隐私、并发和视觉风险也能够被明确验证。
