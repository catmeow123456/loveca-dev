# 海克斯成长、声援判定与成功区移动

> 文档类型：实现说明
> 适用范围：标准规则中的六项海克斯、真人候选与本地双人调试
> 当前状态：已接入共享规则；选择流程见[联机海克斯](hextech-online.md)

## 效果口径

| 稀有度 | 海克斯     | 当前效果                                                                                                     |
| ------ | ---------- | ------------------------------------------------------------------------------------------------------------ |
| 银     | 拒绝赌博   | 己方印刷费用为 5、7、9 的成员，声援判定整体替换为 1 个灰心；原本空判也适用。灰心只补总心数，不能补指定颜色。 |
| 金     | 压根没漏儿 | 本次声援公开的牌全部具有有效判定时，每满 5 张给成功 LIVE 的玩家合计分数加 1；抽卡判、加分判也属于判定。      |
| 彩     | 恶魔形态   | 取得时按第 1／2／3 轮获得 1／2／3 棒，此后每经过一个完整回合再增加 1 棒。                                    |
| 彩     | 来财       | 取得时按第 1／2／3 轮抽 1／2／3 张；从下一回合起，在自己的通常抽牌阶段额外抽 1 张。                          |
| 彩     | 关键暴击   | 己方持有判定的 LIVE，整组判定替换为加 2 分，原判抽和判心不再执行；原本空判的 LIVE 保持空判。                 |
| 彩     | 掀桌       | 取得时将双方成功区的全部 LIVE 放入各自休息室。双方都锁定选择后一次性生效。                                   |

第 1／2／3 轮对应回合区间 1–2／3–4／5 及以后，本地预设授予按第 1 轮处理。「恶魔形态」和「来财」的取得当回合只给即时收益，后续增长从下一回合开始。同名持有实例各自计算取得时间，成长棒数、额外抽牌和条件加分可叠加；判定替换是设置结果，多份同名替换不会叠成多个灰判或加 4 分。

「压根没漏儿」使用当前 LIVE 的声援事实，追加声援合并计算，整批重新声援后使用新的批次。声援牌后来被回收或移动仍属于已公开事实；非声援的解决区卡片和未公开卡片不计入。任一空判使这项加分变为零；「拒绝赌博」产生的灰判可满足条件。分数只在 LIVE 成功时计入，不将失败改为成功。

## 共享规则与展示

定义沿用 `src/domain/hextech/catalog.ts` 和 `HEXTECH_V1`。成长及条件加分由现有持有实例、取得回合和声援事实派生；「来财」接入通常抽牌入口，即时抽牌与后续抽牌均沿用既有更新、无牌时尽量执行的规则。恢复不重放取得效果，也不新增成长或抽牌计数。

判定替换由 `src/domain/hextech/bonuses.ts` 计算，接入 `getCheerCardBladeHeartResolution`：先处理海克斯替换，仍为空判的成员再接受普通能力授予，最后应用颜色替换。「压根没漏儿」同样读取包含授予的有效判定，普通 modifier 先完成收集，避免计算条件分数时递归收集自身。实际声援的即时判抽、判定成败、加分和声援选卡查询共用这条链路。已公开声援牌沿用 `liveResult.effectiveCheerBladeHearts` 投影，`frontInfo.bladeHearts` 保留印刷值；普通与表格判定面板、授予来源及声援演出沿用同一投影。隐藏牌不进入有效判定映射，前端不自行根据海克斯名称重算。橙判心的条件身份和临时无色心贡献沿用基础规则。

「掀桌」通过既有成功区到休息室移动，双方区域完成变更后才为真实移动产生进入休息室事件并排入卡效队列；持有海克斯来源和公开卡牌移动沿用会话记录。成功区条件加成随当前区域重新计算，标准规则的胜利门槛仍由基础规则集决定。

本次扩充目录与派生视图，没有新增权威持久字段或数据库迁移。部署仍需同步前后端；房间入口依赖的迁移与生产验收边界见[联机说明](hextech-online.md#持久化与本地部署)。

## 验证边界

规则测试覆盖费用与玩家隔离、替换顺序、真实声援与 LIVE 分数、空判和灰心边界、追加／重新声援、移动后保留的公开事实、取得时点、逐回合成长、重复取得、抽牌更新、命令重试及 checkpoint 恢复。六项都经过真人候选的双方选择命令验证；「掀桌」覆盖单方确认等待、双方成功区移动及公开日志。

浏览器使用共享牌桌和隔离本地测试卡池，验证预设取得、有效判定、普通与表格视图、接受判定后的权威分数。正式账号全链路与生产环境不在这组验证范围内。
