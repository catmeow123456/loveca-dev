# 海克斯真人对战与回合选择

> 状态：共享规则、娱乐大厅入口和双端选择流程已实现；尚未发布到生产。

## 入口与规则

对战大厅的「娱乐模式」统一列出「自由构筑」「开盒战」「海克斯」的公开房间。点击玩法标签将该类房间前置并强调，其他房间仍可加入或观战；「全部」恢复默认顺序。标签同时预选建房／找人的玩法，操作弹层内可以调整；从列表加入始终采用目标房间的实际玩法。自动匹配仍按玩法隔离。

海克斯使用玩家已有卡组，不限制 PT；牌数、同名上限等普通构筑约束与标准对局胜利条件保持有效。开房、找对手、房间号加入、开局确认和猜拳复用现有流程。换组、再战和继续公开等人保留海克斯玩法。

用户确定的流程：第 1／3／5 回合开始时，系统自动随机生成共同稀有度与双方各 3 项候选，直接展示，无须玩家点击随机按钮。双方同时选择，没有先后顺序；每项可以重抽 1 次，然后各选 1 项并确认。先确认的一方等待，双方都确认后继续。第 1 回合位于双方完成换牌之后；第 3／5 回合位于上一回合结算完毕之后。选择及取得后的检索期间暂停活跃恢复、通常抽牌和回合开始效果。双方锁定后先登记并公开持有，再按先攻顺序完整处理取得效果；需要选牌时暂停，完成后继续其余取得效果。

未指定的细节采用以下首版默认值：

- 银／金／彩各为 1/3，同一轮双方使用相同稀有度，随机数由权威运行时生成。
- 双方独立抽取，初始三项互不重复，不从共享有限库存扣除。
- 每个位置独立拥有一次重抽。优先排除当前三项；同档条目不足时允许与其他位置重复，但始终排除该位置原项。重抽次数不跨轮保存。
- 后续轮次可以再次取得同名能力，以不同持有实例叠加；已持有能力不从后续候选中移除。
- 候选及本人锁定项只投影给本人。对手仅看到是否锁定，观战者只看到稀有度和双方进度。双方锁定后在一次权威状态提交中取得并公开能力，取得抽牌等收益此时结算。
- 锁定后不可更改；随机、重抽和锁定不能撤销。沿用普通娱乐对局的等待与认输规则，本版不新增海克斯选择倒计时或超时默认选择。

候选仅来自已实现的 24 项目录：银 9、金 7、彩 8。效果清单见[首批](hextech-first-batch.md)、[第二批](hextech-second-batch.md)、[第三批](hextech-third-batch.md)、[成长、判定与成功区移动](hextech-fourth-batch.md)和[质变、起动与取得检索](hextech-fifth-batch.md)。后续扩池与平衡调整按试打反馈推进。

## 权威状态与命令

- `HextechState.draft` 保存已完成轮数、当前轮次、稀有度、双方候选、各格重抽标记和锁定位置。候选与随机结果是权威事实；弹窗收起、尚未提交的单选位置属于 UI 状态。
- 权威流程打开窗口时一次性生成稀有度与双方候选，不存在玩家随机稀有度命令或等待先攻步骤。`REROLL_HEXTECH` 和 `SELECT_HEXTECH` 验证轮次、归属、位置、预期定义和锁定状态，双方都可独立提交。旧候选、旧轮次及额外重抽被拒绝，重复请求沿用命令幂等机制。
- `GameService` 在新回合的 ACTIVE 入口暂停，恢复时执行该阶段入口，不再次增加回合数。独立的换牌结束路径同样打开第一轮选择。中央命令策略与自动阶段推进共同阻断其他操作，认输仍可提交。
- `GameSession` 在窗口开启时记录系统事件 `HextechSelectionStarted`（回合、共同稀有度），重抽和锁定仍记录玩家行为。候选及选择细节只进密封审计和权威 checkpoint。取得能力使用既有 `HextechAcquired` 事件。
- 玩家 projector 仅构造本人候选；真人观战投影移除候选。共享 `GameBoard` / `HextechSelectionPanel` 提交正式命令，重连后读取现有候选，不重新随机。回放为只读。

## 持久化与本地部署

房间使用 `CASUAL_HEXTECH_V1` 环境标识，`format: HEXTECH` 和 `ruleMode: UNLIMITED` 必须配套，账号卡组 ID 必填。迁移 [0048_add_hextech_casual_format.sql](../drizzle/0048_add_hextech_casual_format.sql) 扩展房间环境检查约束；不重置已有房间或更改账号卡组。

部署需在目标数据库应用迁移后同步前后端。当前 checkpoint 中缺少 `hextech` 仍表示普通玩法；预设授予与随机选择为不同入口，不能同时配置。恢复时验证版本、定义、实例、轮次和候选形状，不增加运行时旧格式兼容。迁移顺序为 `0047_deck_classifier_recent_window` → `0048_add_hextech_casual_format`；曾执行开发分支旧编号海克斯迁移的本地库，需先核对迁移记录与实际结构，不能据此认定当前迁移链完整。生产发布、迁移和验收另行处理。

## 验证与剩余范围

规则与服务测试覆盖第 1／3／5 回合自动开启、三档候选、逐格重抽、双方不同确认顺序及同时提交、过期命令、身份校验、重复提交、锁定与收益时点、撤销、复水、认输及对手／观战信息隔离。PostgreSQL 隔离 schema 验证统一娱乐列表、标签优先与分页、迁移、匹配隔离、换组、正式开局和再战，相关普通及开盒流程同时回归。

浏览器使用真实 `OnlineMatchService` 和共享真人桌面，隔离 HTTP 传输与持久化；覆盖 390×844 与 1024×768、浅色与深色、自动显示候选、后攻先确认、选择等待和重连，另验证娱乐标签置顶、全类型保留、跨标签加入和选组创建参数。卡图使用测试素材，不代表生产账号全链路或历史页面端到端验收。

已支持质变额外取得、两项起动能力和取得后检索；持有替换、复杂胜利条件及 AI 海克斯决策仍未纳入。主动能力与取得检索的口径及验证边界见[第五批说明](hextech-fifth-batch.md)。
