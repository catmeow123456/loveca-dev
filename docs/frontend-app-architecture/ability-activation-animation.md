# 起动效果的七彩流光与旧版对比

共享 `GameBoard` 内的 `AbilityActivationProvider` 接管 `PlayerArea` 的舞台、手牌与休息室手动起动入口。玩家点击后，真实卡牌用 CSS 透视与 Web Animations 沿 Z 轴整体抬起，始终保持平行于桌面的姿态，不做 X/Y 轴倾斜或屏幕平移；独立投影留在桌面平面，结合均匀的透视放大表现离地距离。

默认边缘材质为 `abilityActivationRainbow.ts` 绘制的七彩流光：保留上一版两道光沿圆角牌缘环绕的路线、方向和 1.5 倍移动速度，只把珠光褶皱材质换为简洁的七彩光线。亮芯贴近牌缘，尾部逐渐变细、淡出，色彩随光线一起移动；未经过的位置保持透明，卡面内部不叠色，不改变人物或卡图。

沿边流光与墨染继续作为本地对比选项保留。流光仍有原速及 1.5 倍速两种，原来的尾迹与配色不变。四种材质都使用原卡节点内的透明 Canvas，共用浮起、投影、整体透明度包络和命令时序，没有增加依赖或规则状态。

`AbilityActivationStyleContext` 只提供表现层选择：`rainbow` 为默认七彩流光，`flow` 为旧版珠光材质的沿边流光 1.5 倍速，`flow-original` 为相同画笔的原速，`ink` 为保留的当前墨染。起动时将选择固定在当前演出中，本地对比页切换材质或速度会重新准备内存场景，从而取消未提交的旧演出。

墨色由贴在原卡节点上的 Canvas 2D 绘制，`abilityActivationInk.ts` 只负责局部边缘画面。整条卡边是连续的墨色来源，按离卡边的距离与空间上连续的染料场计算浓淡。半透明浅灰底形成完整墨面，局部炭黑墨块经灰色过渡融入其中；大尺度浓度分布决定块面，较细的流场变化只修饰内部浓淡和边界，不再描绘孤立的白色等值线。浅色墨面衬出深色区域，改善黑墨在深色桌面上难以辨认的问题，同时让背景仍可透出。整片墨面随同一缓慢流场向外铺开、弯曲、稀释；边界自然起伏并淡出，不将整圈提亮成不透明白光，也不逐个生成烟团或沿边循环波纹。

材质参考了 Macro Room 的实拍 [Ink In Motion](https://www.youtube.com/watch?v=ICxC5ekWnUc)，运动参考 [Jamie Wong 的流体平流讲解](https://jamie-wong.com/2016/08/05/webgl-fluid-simulation/)。实现只在缓存的局部旋流速度场中对连续纹理做一阶反向采样，是轻量视觉近似，不是完整流体物理求解；没有引入参考项目的代码或依赖。黑白颜料用普通透明度合成，不做加色发光。墨色与投影均为中性灰阶，画布使用固定的 328×408 采样范围，外沿渐隐，卡面内部保持透明；不读取、复制或滤镜处理卡面，不变形人物，也不引入 Three.js。

总时长 1000ms：前 250ms 抬起，接着悬浮至 800ms，最后 200ms 落稳并淡出；之后才调用原 `gameStore.activateCardAbility`。动画不是规则成功事实，费用、可发动次数和结算仍由原命令验证，拒绝沿用既有提示。原卡的横置、手牌扇形角度和祖先缩放保留；起动菜单与原有高亮描边短暂收起，其他桌面操作不被整页锁定。休息室窗口在提交后关闭，避免动画期间来源被提前卸载。

用户认可的完整水墨块面基线保存在提交 `5667ba55`。当前调优相对该版本将 Z 轴高度从 105px 增至 115.5px，悬浮后的显示宽高各增加 10%，显式缩放已补偿透视放大；桌面投影同步增加分离距离并保留平面尺寸。墨面沿卡边法线压缩重采样，补偿卡牌放大后，悬浮时从牌边向外的显示距离约为基线的三分之二，保持原浓淡与流动形态。舞台与手牌来源在悬浮期间提升局部层级；手牌以底边为缩放锚点，休息室网格预留扩张空间，避免放大后遮挡或裁切，结束时恢复原层级与姿态。

同一时刻只保留一个未提交的起动意图。对局、视角、seq、公开展示 epoch、会话或只读状态改变，取消尚未提交的命令；重复点击不会重复发送。组件卸载、来源消失或页面进入后台也不会产生迟到命令。动画完成与取消均清理帧回调、计时器、transform、阴影与标记；撤销后再次发动相同卡牌不依赖旧去重记录。

减少动态模式仅播放约 80ms 的静态边缘明暗，不倾斜或抬起。只选择投影中已经正面可见、可操作的来源节点，详情浮窗与牌背不是动画来源。找不到合适节点时直接走原命令。

这是发起方手动点击后的客户端预演，不是新的权威结算屏障：AI、直接调用 store 的自动流程、对手收到命令结果、观战与回放不额外播放该段；尚未实现联机双方同步预演。网络仍使用原命令协议与服务器校验。

## 验收

`/activation.html` 默认显示“七彩流光 · 新版”，顶部“边缘特效”可切换沿边流光 1.5 倍速、原速和墨染。也可使用 `?edge=rainbow`、`?edge=flow`、`?edge=flow-original` 或 `?edge=ink`；切换后自动重新准备，再点击卡牌和原生起动按钮播放。四项使用相同的浮起高度、缩放、投影和 1000ms 时间轴。

复用 [本地回收验收环境](../../client/tests/recovery-review/README.md) 的 Vite 配置，打开 `/activation.html`。场景分别使用 `PL!N-bp5-014-N` 费用 4「中须霞」、`PL!HS-bp6-014-R` 费用 2「安养寺姬芽」、`PL!N-bp1-002-P` 费用 2「中须霞」的真实起动命令。仅准备本地内存初始局面；操作使用共享对战组件，不连接生产账号或卡组。

```sh
node client/node_modules/vite/bin/vite.js --config client/tests/recovery-review/vite.config.ts
node client/node_modules/@playwright/test/cli.js test --config client/tests/recovery-review/activation.playwright.config.ts
```

浏览器检查包含命令前等待、连续帧边缘像素变化、浮起前后宽高比、卡牌与桌面投影分离、重复点击、撤销重做、对局/视角/其他命令取消、桌面/窄屏、窗口尺寸变化、减少动态，以及手牌和休息室来源。七彩流光及加速流光采样 250、450、650、800ms，墨染保持 450、750ms；七彩流光、墨染、原速流光、加速流光逐一核对相同浮起及 1000ms 后仅执行一次命令。原速画笔的 4 个采样帧另与恢复前的流光第二版备份逐像素比对，确认还原一致。

截图默认在 `output/playwright/ability-activation/`。连续帧检查同时核对七彩光线存在透明间隔、多种光色和沿边位移。低端设备性能与真实双客户端网络延迟未单独验证。
