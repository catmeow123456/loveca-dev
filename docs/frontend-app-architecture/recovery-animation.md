# 二维休息室回收动画

共享 `GameBoard` / `PlayerArea` 的 `BattleAnimationLayer` 在真实投影出现 `WAITING_ROOM → HAND` 后播放。规则、结算、命令和公共展示期限保持作者主分支实现；不读取卡文推测回收成功。实现参考 `origin/feat/card-effect-feedback-next` 的 `c35b7970` 中三维回收节奏，二维只使用 DOM、CSS / SVG 与已有 Framer Motion，无 Three.js 依赖。

## 时间轴与落点

每张卡蓄亮 80ms、弹起 180ms、静止悬停 400ms、飞回 400ms，总计 1060ms；同批多张每张错开 60ms。弹起以三次 ease-out 减速、宽高放大至牌堆卡面的 1.5 倍；飞回恢复真实手牌的尺寸与扇形角度。柔光聚在休息室内部，光束随升起伸展，卡沿只有两条短尾光，休息室余光在 660ms 飞回前熄灭，无白色粗框或环绕边缘的光晕。

`recoveryCardMotion.ts` 提供纯时间轴采样及几何测量；`RecoveryCardMotion.tsx` 用一个帧回调同时更新卡牌和光效。起点优先取当前牌堆锚点，避免展开的休息室选牌窗口成为起点。己方终点每帧测量 `data-recovery-hand-card` 内实际卡牌边界，反解扇形旋转后的宽高，保留祖先缩放；选择窗口收起、手牌重排或窗口尺寸变化不会沿用旧终点。最后一帧直接交还真实手牌，无退出缩放或淡出。

移动遮挡沿用统一事件时长与 120ms 兜底缓冲，并在组件完成／目标离开手牌时立即释放。减少动态沿用 120ms 区域提示，不隐藏真实手牌。公开选牌展示与公开弃牌展示保留原时长及各自队列，不缩短为回收动画时间。

## 时间线与可见性

`battleAnimationHistory.ts` 只在同一前进时间线内去重；对局、座位、只读模式、公开演出 epoch 变化或 seq 回退时清空，并分配新的本地代际 ID。撤销不播放反向回收／弃牌，旧计时器、旧遮挡及退出子组件一起清理，旧完成回调无法命中同牌重做。多张回收延迟不被无关前进状态更新吞掉；目标不再位于当前手牌时结束演出。

动画图片仍由既有投影正反面逻辑提供，组件不解析卡号、不读取对手私密数据。己方只跟踪已渲染的手牌节点；匿名背面只使用允许的公共区域终点，不为隐藏手牌建立对象映射。没有合法移动的无目标、跳过与非法命令均不生成成功回收。

## 本地验收与回归

[验收入口说明](../../client/tests/recovery-review/README.md)提供真实卡效局面和启动命令。页面仅加载共享 `GameBoard`，测试按钮只准备初始局面或调用真实命令；不连接账号、生产 API 或数据库。视觉是否达到认可标准由用户判断。

- `tests/unit/recovery-card-motion.test.ts`：阶段边界、静止悬停、放大、实时终点、扇形几何、多张延迟和撤销去重。
- `tests/integration/recovery-animation.test.ts`：真实卡效回收 A → 撤销 → 同一 A 再回收，双张回收、公开展示期限、非法／无目标和对手隐藏投影。
- `client/tests/recovery-review/recovery.spec.ts`：原生选牌、完整遮挡时限、最终 DOM 边界误差、双张、窄屏变化、对局／视角取消、减少动态、悬停期间撤销后重做。逐帧采样避免固定等待与测试轮询错过短动画。

真实双客户端网络延迟和低端设备性能未单独实测。大批量移动沿用主分支现有超过 8 张时的区域提示降级；本次不扩展该策略。
