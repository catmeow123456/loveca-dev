# 生产对局锁定卡组使用分析

> 文档类型：专题说明
>
> 适用范围：生产线上对局锁定卡组的只读统计口径与结果
>
> 当前状态：数据截止 2026-08-01 15:09 UTC（北京时间 23:09）的分析快照

本文是当前真人线上环境的原始统计附录；入口式环境说明见[当前比赛环境、常用特色卡组与主流卡组](./MATCH_ENVIRONMENT_AND_ARCHETYPE_GUIDE.md)。

## 1. 结论摘要

1. **用户感受到的集中现象存在，但范围比“Cerise Bouquet / Edel Note 两套”更大。** 在可分析的 1,950 个线上锁定卡组中，Cerise Bouquet 为 **17.8%**、Edel Note 为 **11.6%**，两者合计 **29.4%**；加上 DOLLCHESTRA 与 Mira-Cra Park! 后，莲之空四个小队合计 **47.2%**。前四个主轴（Cerise Bouquet、5yncri5e!、DOLLCHESTRA、Edel Note）已占 **60.0%**。
2. **这不是“只剩两副牌”的环境。** 数据中仍识别到 18 个主小队/并列主轴、378 个精确卡表；问题是对局量高度向少数体系集中，而不是没有其他可用构筑。因此，活动预组池应有意识地覆盖不同玩法与较低使用率体系，而非简单抽取“当前最热门卡组”。
3. **“绿莲”可高置信度映射为 Cerise Bouquet；“蓝莲”在本次线上锁定样本中没有出现。** 后者仅在玩家保存卡组中出现 2 份，均以 DOLLCHESTRA 为主，因而可暂列为“DOLLCHESTRA 候选”，不能把它与绿莲或 Cerise Bouquet 混为一谈。
4. **当前原始快照质量需要成为后续运营指标。** 3,110 个线上锁定快照中，只有 1,950 个是非 `INVALID` 且恰好 48 张成员的标准卡表；其余 1,160 个（37.3%）不应混入体系使用率。未来排位应在锁组时明确记录可分析标记、体系版本和核心组件标签，避免事后靠名称猜测。
5. **原始胜率不足以支持平衡结论。** Edel Note（55.2%，194 个已结算锁定）、Cerise Bouquet（53.1%，286）与 5yncri5e!（55.4%，278）并非显示出同一量级的单一压制；但这没有控制对局配对、先后手、玩家重复使用、版本时间、非完成局和具体构筑，不能据此作禁限用或削弱决定。

## 2. 数据与统计口径

### 2.1 使用的数据

| 文件 | 用途 | 本次是否作为使用率分母 |
| --- | --- | --- |
| `data/match_records.csv` | 对局来源、状态、开始时间、胜者席位 | 是，用于筛选线上对局与结果联结 |
| `data/match_deck_snapshots.csv` | 每位玩家在开局时锁定的主卡组、卡牌摘要、来源与校验状态 | **是，唯一的卡组使用事实** |
| `data/decks.csv` | 玩家保存的卡组及名称 | 否；只用于在没有线上锁定样本时辅助核对别称 |

`decks.csv` 表示“玩家曾保存过什么”，不是“实际拿去对局过什么”，故不能替代快照计算环境份额。

卡牌归类沿用 `src/scripts/sync-cards-loveca-excel.ts` 的权威口径：卡牌类型、**真实团体**、**真实小队**。分析以锁定时 `card_summaries` 的成员小队归属计算；不使用易产生混淆的作品名或玩家输入的卡组名称作为主分类。

### 2.2 筛选链路

| 阶段 | 快照数 / 对局数 | 说明 |
| --- | ---: | --- |
| 全部对局记录 | 9,016 场 | 2026-06-19 17:11 UTC 至 2026-08-01 15:09 UTC |
| 全部卡组快照 | 18,034 | 其中 18,032 可联结到对局记录 |
| 线上运行时锁组 | 3,110 | `source = ONLINE_RUNTIME_DECK`，对应 1,555 场线上对局 |
| 可分析标准锁组 | **1,950** | `validation_state != INVALID` 且成员数恰为 48；以下使用率分母 |
| 可用于原始胜率的锁组 | 1,710 | 对局已完成或认输，且已有胜者席位 |

按锁组状态，线上快照来自已完成 2,062、认输 428、中断 534、进行中 74、损坏 12 个玩家—对局快照。状态数字是快照数而非场次数。筛除的 1,160 个快照可能包含测试、早期数据、非标准卡表或校验失败数据；在明确原因前，不应将它们解释为某个体系的缺席或低使用率。

### 2.3 “主轴”定义

一条记录代表一位玩家在一场线上对局中锁定的一副卡组。对其 48 张成员卡按真实小队计数，数量最多的小队标为**主轴**；第一、二名张数相等时标为 `HYBRID_TIE`。这是一种可复算的运营标签，不等于社区完整构筑名称，也不否认混色资源卡、LIVE 卡或跨作品组件的重要性。

因此本文的百分比是“玩家—对局锁组份额”，不是独立玩家数、独立卡组数、报名份额或线下环境份额。

| **合计** | **1,950** | **100.0%** |

可以从三个层次读这张表：

- Cerise Bouquet + Edel Note：573 次，**29.4%**；这直接支持玩家对这两个体系频繁出现的观察。
- Cerise Bouquet、DOLLCHESTRA、Edel Note、Mira-Cra Park!：921 次，**47.2%**；应把它作为“莲之空集中度”持续监控，而非只看两个别称。
- 前四个主轴：1,170 次，**60.0%**；这已经足以让随机匹配中的体感重复显著升高。

卡组并非仅有少数精确抄表：1,950 次锁组覆盖 **378** 个不同的完整成员表签名。不过，“不同签名”不能直接证明对局体验多样，因大量微调签名仍可属于相同引擎与相近对局模式。

| --- | ---: | ---: | ---: |

| 5yncri5e! | 278 | 154 | 55.4% |

| 并列主轴 / 混合 | 116 | 67 | 57.8% |

## 6. 对产品决策的含义

1. **先上观测，不以名称作为判定基础。** 在新一局锁组时持久化分析用的 `archetypeVersion`、小队计数、核心组件标签和完整成员表签名；界面可显示别称，但统计必须可由卡表重算。每次卡牌更新或分类规则变化都新建版本，禁止悄悄重写历史。
2. **用两个浓度指标进入运营看板。** 至少同时显示“Cerise Bouquet + Edel Note”与“莲之空四小队”的使用率、前四主轴份额、镜像率、主轴×主轴对局矩阵、完成率和分层胜率。前者响应玩家感受，后者避免遗漏 DOLLCHESTRA / Mira-Cra Park! 的替代集中。
3. **轮换主题牌桌可把数据用于选池，而不用于随机惩罚。** 首版 6～8 副预组应保留少量热门体系作为认知锚点，同时刻意挑选玩法明显不同、当前使用率较低且内部对局质量合格的体系；随机单位应是已测过的双方**对局组合**，而非从热门列表独立抽两副牌。详见[轮换主题牌桌策划与设计](./ROTATING_THEME_TABLE_DESIGN.md)。
4. **排位不应因本报告改变为强度匹配或强制随机卡组。** 排位仍以玩家自带合法卡组、单一队列和公平规则为基础；若后续的充分分层数据确认某一核心组合长期跨对手压制，再单独审查竞技环境、卡效正确性与禁限用，而不是把活动模式当作平衡补丁。
5. **补齐快照可分析性监控。** 对 37.3% 被排除的线上快照应建立原因码与告警：成员数异常、卡组校验失败、历史格式、测试流量或记录缺字段分别统计。这个问题比再细化别称更优先，否则后续排位环境报告会有不可见的样本选择偏差。

## 7. 与外部调研的关系

本报告替代外部公开卡组库作为“本平台实际使用率”的证据。DeckLog、有公开赛果的官方/社区来源仍有价值：它们可以发现外部构筑、补充社区别称并帮助挑选主题预组候选；但不能覆盖平台内真实的玩家—对局使用份额。两者的边界与可复现抓取记录见 [DeckLog 公开数据与主流构筑调研](./DECKLOG_AND_META_RESEARCH_2026-08-01.md)。
