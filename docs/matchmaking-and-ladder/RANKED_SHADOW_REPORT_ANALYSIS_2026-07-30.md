> 文档类型：历史决策记录

> 分析日期：2026-07-30
> 数据来源：生产 `match_records` 的只读匿名报告

## 1. 结论

赛季天梯作为当前休闲娱乐向卡牌游戏的下一阶段 POC 仍然合理。生产样本证明现有公共牌桌已经能形成足够的真人对局流水，可用于验证排位结算实现；样本也没有给出必须引入按分匹配、反重复跳过或复杂段位的理由。

首轮数据支持保留：

- 单一排位池和纯 FIFO；
- Glicko-1；
- `1500 / RD 350` 初始状态；
- 每局结束后即时结算；
- rating 原值排序，不增加隐藏 MMR、保守分或活跃度加分；
- 无高价值奖励的实验赛季定位。

首轮数据要求调整：

- 定位和排行榜资格从 5 场提高到 10 场；
- `GLICKO1_PER_MATCH_SHADOW_V1` 原样保留用于复现本报告；
- 当前候选改为 `GLICKO1_PER_MATCH_SHADOW_V2`，只改变定位门槛，Glicko 数学参数不变；
- 赛季环境必须增加独立的全局卡牌目录/竞技环境版本与哈希，不能复用 `match_records.cardDataHash`；
- 后续报告必须拆分被排除记录的实际状态，不能只汇总为“未完成或未认输终局”。

因此当前判断是：

> 可以进入 R2 的赛季 schema、原子 rating 流水和异常结算设计；在可靠性指标、赛季环境身份、断线弃权和暂停/收口能力完成前，不开放玩家入口。

## 2. 样本范围

报告筛选了 525 条 `PUBLIC_TABLE` 记录，其中：

| 指标         |                     数值 |
| ------------ | -----------------------: |
| 合格计分样本 |                   491 局 |
| 匿名玩家     |                    50 人 |
| 数据时间     | 2026-07-24 至 2026-07-29 |
| 正常完成     |                   360 局 |
| 主动认输     |                   131 局 |
| 被排除       |                    34 条 |

纳入样本全部满足 `ONLINE + FULL + COMPLETED/SURRENDERED + sealedAt + endedAt + winnerSeat + 双方玩家不同`。131 局认输占纳入样本的 26.68%；认输本身是已有的权威终局，不应被视为异常或额外扣分依据。

34 条被排除记录占 SELECT 结果的 6.48%，V1 报告只能确认它们未处于 `COMPLETED/SURRENDERED`，不能再区分等待、进行中、中断或平台故障。该比例不能直接解释为故障率，也不能用来证明排位可靠性已经达标。

## 3. Rating 与定位门槛

491 局回放后的总体分布为：

| 指标             |   中位数 |      P90 |   最大值 |
| ---------------- | -------: | -------: | -------: |
| 每名玩家局数     |      8.5 |     53.7 |       95 |
| Rating           | 1494.935 | 1692.468 | 1937.695 |
| RD               |  138.736 |  257.780 |  290.231 |
| 单方每局绝对分差 |   21.072 |  117.028 |  306.680 |

玩家场次数量：

| 场次    | 玩家数 |
| ------- | -----: |
| 1～4    |     15 |
| 5～9    |     14 |
| 10～19  |      5 |
| 20～49  |      9 |
| 50 以上 |      7 |

V1 的 5 场门槛暴露了明显的展示问题：原始榜首只完成 7 局并取得 7 胜，Rating 为 1937.695，但 RD 仍为 194.485。这个结果在数学上符合高 RD 新玩家快速变化的设计，却不适合作为玩家看到的稳定榜首。

| 资格门槛   | 合格人数 | RD 中位数 | RD > 100 | RD > 150 |
| ---------- | -------: | --------: | -------: | -------: |
| 至少 5 场  |       35 |    94.315 |       17 |        6 |
| 至少 10 场 |       21 |    80.685 |        3 |        0 |

10 场不会让 rating 完全稳定，但在当前样本中已经排除了 RD 高于 150 的公开排名。它也仍让 21/50 的样本玩家具备榜单资格，适合作为首季 POC 的简单门槛。

不采用 `rating - 2 × RD` 等保守分排序。保守分会改善这一次样本的短期榜首问题，但会给玩家增加一套难以解释的隐藏排序公式；10 场公开门槛已经能以更低产品复杂度处理当前问题。

## 4. 首后手与对手重复

先手赢 237 局，后手赢 254 局，先手胜率为 48.27%。该比例的 95% Wilson 区间约为 43.88%～52.69%，当前样本没有显示需要为首后手结果增加 rating 补偿。每周先手胜率分别为 50.86% 和 46.84%，仍应在正式 Beta 中持续观察。

对手构成为：

| 指标                   |             数值 |
| ---------------------- | ---------------: |
| 不同玩家组合           |              226 |
| 重复交手组合           |              105 |
| 属于重复组合的对局     |    370（75.36%） |
| 单一组合最多交手       |            13 局 |
| 连续再次遇到上一位对手 | 102 局（20.77%） |

“属于重复组合”会把一个组合的第一次交手也计入，因此 75.36% 不等于 75.36% 的配对当场重复。更直接的连续重复率是 20.77%，在 50 人的小池中值得监控，但还不足以证明应破坏 FIFO：跳过上一位对手会延长等待、降低成局率，并使匹配顺序变得难以解释。

首季继续纯 FIFO，同时记录等待时间、连续重复、单一对手占比和取消率。只有真实排位开放后证明连续重复明显损害参与或结果可信度，才评估新匹配策略。

## 5. 赛季环境身份

报告中的 491 局只有一个 `cardDataVersion`：`ONLINE_RUNTIME_CARD_DATA_SNAPSHOT`，却出现 453 个不同的 `cardDataHash`，单一哈希最多只对应 3 局。

代码路径确认，`buildRuntimeCardDataHashInput(match)` 会把双方本局主卡组和能量卡组中的卡牌数据连同席位一起哈希。因此：

- `match_records.cardDataHash` 用于证明本局两副卡组快照的重放数据一致；
- 不同卡组在同一全局卡牌环境下通常产生不同哈希；
- 它不能表达“本赛季使用哪一版完整卡牌目录”；
- 它不能直接作为部署时是否允许排位候场的环境校验值。

R2 应新增独立的全局卡牌目录/竞技环境身份，并与赛季、每局排位记录和 rating 结算流水绑定。对局级 `cardDataHash` 继续保留原有重放完整性职责，两者不能混用。

## 6. 本报告不能验证的内容

这份影子报告使用休闲公共牌桌结果，不能验证：

- 玩家是否愿意主动参加可见 rating 的排位；
- 固定开放时段能否提高总真人对局，而不是搬运休闲对局；
- rating 压力是否降低部分玩家的参与；
- `FREE` 使用率和规则争议率；
- 断线逾期弃权与平台故障的真实比例；
- 365 天 RD 增长常数是否合适；
- 跨赛季软重置是否合适；
- 4～6 周赛季结束时的榜单稳定性。

因此 RD 增长与软重置仍只是候选参数。首季开放前需要补齐可靠性与 `FREE` 指标，首季结束后再用完整赛季数据复核长期参数。

## 7. R2 进入条件

R2 可以立即开始，但玩家入口继续关闭。R2 至少应交付：

1. 赛季生命周期、开放窗口、暂停和 `FINALIZING` 收口；
2. 独立的全局卡牌目录/竞技环境版本与哈希；
3. 双方原子 rating 结算和 `matchId + algorithmVersion` 幂等；
4. 追加式作废/替代流水与可重建当前分；
5. 正常终局、认输、断线弃权和平台故障的结构化分类；
6. `FREE` 请求、同意、切换和恢复记录；
7. 10 场定位与排行榜资格；
8. 等待、确认、开局、完成、重复对手和异常结算指标。

完成这些能力并跑通测试环境后，才能把通过验证的候选参数提升为不含 `SHADOW` 的正式算法版本，再进入 R3 的玩家可见 Beta。
