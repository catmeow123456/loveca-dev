# 赛季排位首版当前状态与上线边界

> 文档类型：专题说明
> 适用范围：赛季排位首版玩家、匹配、结算、管理能力与上线边界
> 当前状态：代码已实现，尚未执行生产迁移或开放首季
> 最后更新：2026-07-30

## 1. 玩家闭环

玩家从首页进入“赛季排位”后可以：

- 查看当前或历史公开赛季；
- 查看开放状态、当前窗口结束或下次开放时间；
- 首场结算后查看积分和本局积分变化，达到赛季门槛后再显示排名；
- 选择合法云端卡组并加入独立排位候场；
- 跨页面维持候场、确认配对并自动进入现有正式联机房间；
- 查看最近排位对局和达到参榜场次门槛的排行榜。

页面只突出赛季状态、当前积分、参榜进度、卡组和一个主要操作。没有数据时不渲染空
排行榜。对局桌面继续复用现有 `GameBoard`，不持续强调双方排名。

玩家 API：

| 方法   | 路径                          | 用途                                   |
| ------ | ----------------------------- | -------------------------------------- |
| `GET`  | `/api/ranked/seasons`         | 读取可见赛季                           |
| `GET`  | `/api/ranked/overview`        | 读取赛季、个人、候场、最近对局和排行榜 |
| `POST` | `/api/ranked/queue/join`      | 以合法云端卡组加入排位候场             |
| `POST` | `/api/ranked/queue/heartbeat` | 维持票据并读取最新状态                 |
| `POST` | `/api/ranked/queue/confirm`   | 确认配对                               |
| `POST` | `/api/ranked/queue/cancel`    | 取消候场或放弃尚未开局的配对           |

## 2. 赛季与匹配

- 新赛季默认使用 `GLICKO1_PER_MATCH_V2`，初始 `1500 / RD 300`；V1 的
  `1500 / RD 350` 保留用于既有赛季重建。积分和每局变化从首场结算后显示；排行榜
  资格由赛季独立配置，默认 10 场，可设置为 1–100 场。
- 排位票据必须绑定 `seasonId + competitiveEnvironmentId`。
- 配对只在同一排位赛季和环境内按 `joinedAt + ticketId` 做稳定 FIFO。
- 排位和休闲公共牌桌共享底层状态机，但使用独立 `queueKind` 和跨模式玩家占用。
- 开放窗口结束或候场暂停后停止新票据并结束仍在等待的排位票据；已经形成的配对和
  已开局对局继续处理。
- 排位房间来源固定为 `RANKED`，正式对局创建后立即绑定赛季；绑定失败会删除刚创建
  的运行态对局，不留下未计分的“伪排位”。
- 排位正式开局后拒绝整局重开。

## 3. 结算与运行时

- 权威记录完整封存后自动结算；失败保持 `PENDING`，运行时任务继续幂等重试。
- 正常终局、主动认输和单方超过 3 分钟重连期限的断线弃权使用同一评分公式。
- 断线判负先写持久结果标记，再执行服务端权威认输命令；命令失败时撤销标记并重试。
- 双方都超过期限且最后在线时点无法区分时，不按用户 ID 随机判负，记为
  `VOIDED / PLATFORM_NO_CONTEST` 并保留结构化日志。
- 排位进行中不再沿用休闲房间的 60 秒双方离线销毁规则。
- 对局时间线出现双方同意进入 `FREE` 的记录时，结算写入 `usedFree=true`；结果仍正常
  计分。
- 计划结束后赛季自动进入 `FINALIZING + PAUSED`；到达最长收口期限仍无法形成可靠结果
  的 `PENDING` 对局显式转为平台无结果。
- 新赛季激活时，从最近封存赛季按冻结配置生成软重置种子；所有迟到结算和更正重建
  都从同一组种子开始。

## 4. 管理闭环

管理员页面只有“赛季”和“对局处理”两个一级区域：

- 创建/编辑赛季草稿；
- 配置进入排行榜所需场次；
- 开始赛季；
- 修改进行中赛季的名称、开放日、每日开放时段和参榜场次门槛；
- 开放或暂停匹配；
- 结束赛季，并在所有对局计分后完成结算；
- 查看待结算与已结算对局；
- 重试待结算对局；
- 预览并执行 `VOID / REPLACEMENT`，使用流水 revision 防止陈旧预览落库。

参榜门槛只影响排行榜资格，不参与积分计算，因此进行中赛季也允许调整；保存后按现有
场次立即刷新排行榜。算法、环境哈希和赛季时间等计分规则仍保持冻结。完整审计信息
保留在 API 与日志，不堆入日常管理页面。

## 5. 数据库迁移

必须停机执行单一迁移：`0010_add_ranked_system.sql`。

迁移不会创建赛季、不会回填旧公共牌桌积分，也不会自动开放玩家候场。生产迁移和
部署属于单独发布动作，本次实现没有执行。执行与校验步骤见
`drizzle/migration-notes/ranked-system.md`。
