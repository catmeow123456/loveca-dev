# 卡牌登场演出：作者部署与验收说明

本文件交给有生产服务器权限的作者执行。当前开发窗口只完成代码与本地验证，没有连接生产管理员页面、修改生产数据或部署服务。发布版本／镜像标签由作者按实际合并结果确定，不使用本文日期代替版本号。

## 本批行为

正式联机与对墙打按登记开放当前二十五张卡牌的演出（二十五张均已获用户观感认可，本批五张包括局部修复及梨子固定睡姿），所有罕度按基础编号匹配；具体卡号、费用、名称及素材对应关系见[卡牌清单](../client/src/components/game/card-entrance/README.md#卡牌清单)。关联能量卡不是触发对象。教程、AI 调试、观战、回放暂不播放。本地及远程 DEBUG 保留单操作者验收。

右上角夜间模式旁的「登场动画」默认开启，本机站点记忆开关；不写账号设置。人物与落场合计约 2.74 秒，首次资源准备最多 2 秒。素材动态加载，二十五张人物 PNG／图集与二十一张眼部图集共计约 73.94 MB（约 70.51 MiB），其中眼部图集约 33.73 MB；只在对应角色演出时按需加载人物与眼部图集，不会在进入对局时下载全部角色 PNG，也没有将它们加入 PWA 安装预缓存。现有带哈希静态资源缓存即可使用，无需上传至卡牌管理、MinIO 或数据库。

联机流程：完成合法登场与费用支付 → 权威暂停后续检查时机／卡效 → 双方播放或跳过 → 双方确认结束后继续结算。关闭的一方立即确认本方结束，必要时显示“等待对方演出结束”；双方关闭时不加载人物素材。客户端只控制本方确认，不能替对手结束。动画期间桌面操作与撤销锁定，认输仍可在权威层结束对局；不拆开费用或当前原子效果步骤。

服务器每张卡提供 6 秒等待预算，单次批量登场按卡数累计。独立服务器计时器到期自动继续，快照轮询与维护扫描提供补充兜底；素材失败、WebGL 失败、缩放／滚动使落点失效时，客户端结束本方演出。正常播放无需等满期限。等待期间不消耗排位操作期限，后续公共展示窗口的阅读时间从恢复后开始。

## 部署要求

1. 前端与 API 必须来自同一个最终提交版本。本次新增 `ACK_CARD_ENTRANCE` 命令、`match.entrance` 投影和 checkpoint 中的可选演出运行态，不能只发布前端静态文件。新前端连旧 API 不会获得演出等待；旧前端连新 API 不会确认，服务器只能等超时。
2. 按现有发布流程完成 CI、备份和版本确认；先停止新对局进入，让正在进行的联机对局正常结束，再一起更新 API 镜像与完整前端产物。不要在活跃演出或待处理卡效中间强制重启。
3. 本动效分支不新增数据库迁移、字段、环境变量或管理员配置。管理员全站动效开关及其迁移已移除，作者无需为本功能执行数据库操作，也不需要管理员卡牌数据操作。保持现有 `API_RUNTIME_CLEANUP_INTERVAL_MS`（默认 10 秒）即可，主要超时推进使用独立计时器而非依赖该间隔。
4. 前端应发布完整 `client/dist`（含全部登记角色的带内容哈希 PNG、动态模块、`sw.js`），不要只拷贝入口 JS。保留现有 HTML／Service Worker 更新策略和静态资源缓存头。确认客户端加载的是新构建，提示旧页面／PWA 用户刷新后再进入对局。当前构建仍有既有大 JS chunk 警告，非本批构建失败。
5. 现有历史归档保持只读，不补播动画、不批量迁移卡牌数据。没有演出运行态的旧存档不追补演出；新存档若保存了当前等待，恢复时保留其实例与原截止时间，已过期则在恢复后的服务器调度／快照读取时继续。建议部署后创建新对局验收。

仓库 `Dockerfile` 负责 API 构建；前端单独由 `pnpm --dir client build` 生成。部署命令、目录、镜像标签请使用作者现行 runbook，本文件不猜测生产机器布局。

## 作者生产烟测

使用普通玩家页面与真实卡组，在两台设备／两个玩家会话中检查：

- 双方开启：合法登场后各自完整播放，结束前不能进行规则操作，之后双方同步继续；不要只用无卡效卡验证。
- 一开一关：关闭方显示等待，不能提前操作；开启方跳过后，双方继续。交换双方开关再验一次。双方关闭应直接继续，不出现角色图。
- 使用费用 20「叶月恋」换手一名 Liella! 成员：演出时被换下成员仍在休息室，演出结束后才按真实卡效放到恋下方；存在多候选时应结束后再显示选择窗口。费用支付失败不演出。
- 使用费用 15「安养寺姬芽」在舞台存在相关成员且休息室有『莲之空』LIVE 时登场：等待结束前不回能、不弹回收选择；结束后只回能及回收一次。费用 15「钟岚珠」各罕度应匹配同一演出，PL!N-bp1-033-SECE 能量卡不触发。无光效查看姬芽抬臂及岚珠持麦靠近嘴边，手机下确认手、脸与姓名可读。
- 刷新／短暂断线时不能重复执行卡效、重放已完成历史；另一方不返回时等待有界。检查演出前后排位操作倒计时，不能在看动画时判操作超时。
- 桌面、窄屏、减少动态各验一次；结束后真实卡牌可见、横置方向正确、邻卡无残留形变。查看普通浏览器网络面板确认角色 PNG 与动态模块没有 404；不能通过管理员 API 探测。

## 回退与排查

若生产出现卡住、资源缺失或同步异常，玩家可先关闭个人「登场动画」或点击跳过；若仍异常，作者应停止新对局，记录普通玩家可见的时间、对局标识、构建版本、模式与复现步骤。资源失败通常会自动跳过；没有完成消息也应在权威截止时间到期后继续。检查 API 日志中的 `entrance timeout continuation failed`，以及静态 PNG／模块是否发布齐全。

需要回退时让活跃对局结束，再成套回退 API 与前端，刷新客户端缓存版本；不要单独把带新运行态的活跃 checkpoint 交给旧 API 继续写入，也不要手工修改 pending 能力或数据库来解除等待。回退不包含卡牌数据回滚，因为本批未修改卡牌数据。本动效分支不涉及数据库结构回退。
