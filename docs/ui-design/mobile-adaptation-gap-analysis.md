> 文档类型：现状差距清单
> 适用范围：移动端适配需求与当前前端实现之间的差距
> 最后更新：2026-07-31
> 当前状态：现行事实清单；只登记仍影响交付的差距
> 对照需求：[移动端适配需求](mobile-adaptation-requirements.md)

本文不重复目标设计，也不保存阶段性线框稿。目标和验收标准以移动端适配需求为准，视觉与页面外壳以[产品视觉系统](product-visual-system.md)为准；这里仅回答“当前还差什么”。

## 维护规则

- 状态只使用 `未满足`、`部分满足`、`基本满足`、`待验证`。
- 完成页面适配后，删除已经闭环的细节，只保留仍影响用户完成任务的缺口。
- 代码和最新验收结果优先于本文；发生偏差时必须更新本文。
- 不在本文保存组件方案、CSS 片段、逐次验证流水账或排期。

## 当前结论

公开首页、认证、游戏准备、卡组管理、卡组编辑器和卡牌管理已具备响应式基础。当前最高风险仍是对战页的完整触屏操作路径，其次是覆盖层、软键盘和安全区的专项验证。

| ------ | ---------------- | -------- | --------------------------------------------------------------- |

| P1     | 覆盖层体系       | 部分满足 | 背景滚动锁定、内部滚动、安全区和多浮层遮挡尚未统一验收          |

## 页面差距

### 公开产品首页与认证

状态：基本满足

已具备：

- 公开首页在 390、430、768、1024 宽度下无页面级横向溢出。
- 品牌、价值主张、主 CTA 和任务入口在手机端保持清晰层级。
- 卡组管理、开始游戏等入口的登录后目标可继续执行；离线试玩可直接进入准备流程。
- 认证页具备窄屏滚动与安全区基础。

仍需验证：

- 登录、注册、找回密码和重置密码在真实软键盘弹出时，当前输入框和提交按钮始终可达。
- 长用户名、错误信息和系统公告同时出现时不挤压关键操作。

### 玩家大厅与游戏准备

状态：基本满足

已具备：

- 玩家大厅与公开首页职责已分离。
- 游戏准备页在窄屏下使用单列步骤和稳定的底部操作区。
- 公开首页发起的游戏意图可延续到准备页。

仍需验证：

- 小高度手机上，长卡组列表、步骤内容和底部操作区不会互相遮挡。
- 返回、取消和退出后的落点符合用户进入当前流程时的意图。

### 卡组管理与卡组编辑器

状态：基本满足

已具备：

- 卡组列表、编辑头部和 DeckLog 导入具备手机布局。
- 编辑器以卡牌库为手机主视图，筛选、当前卡组和详情使用移动端任务层。
- 加卡和减卡存在触屏可见入口，不以 hover 作为唯一入口。

仍需处理：

- 详情任务层需要提供与卡牌单元等价的编辑入口，或明确返回卡牌库操作的路径。
- 部分加减卡微按钮低于 44 × 44 CSS px，需扩大热区或提供等价动作入口。
- DeckLog 长警告、抽屉叠加、背景滚动锁定和软键盘状态仍需专项验收。

### 对战页

状态：部分满足

已具备：

- 手机竖屏已有“己方主战场 + 对手摘要 + 底部任务入口”的第一版结构。
- 阶段操作使用手机底部 dock，判定区使用全屏任务层。
- 卡牌详情在窄屏下具备遮罩、关闭入口、内部滚动和背景滚动锁定。
- 桌面和平板横屏保留完整双方面对面牌桌。

仍需处理：

- 为登场、放置 LIVE、成员状态、移动和资源处理提供稳定的点击式动作路径；拖拽只作为增强交互。
- 移除手机核心流程对双击和 hover 的依赖。
- 把解决区的翻牌、选牌、移动和完成流程整理为可连续完成的手机任务层。
- 为换牌、卡效选择、公开展示、分数确认、LIVE 结果、详情和阶段 dock 建立统一遮挡矩阵。
- 验证平板横屏下日志、判定、详情和阶段面板不会互相遮挡。

### 卡牌数据管理

状态：基本满足

已具备：

- 搜索、筛选、分页和编辑具备手机专用结构。
- 编辑、上线和下线操作不以 hover 作为唯一入口。
- 手机编辑层具备独立内容滚动和底部操作区。

仍需验证：

- 长表单与软键盘同时出现时，当前字段和保存按钮始终可达。
- 密集微按钮满足触控要求，或具有等价操作路径。

### 联机、共享与管理辅助页

状态：部分满足

已具备：

- 创建/加入房间、共享卡组和管理状态页已有响应式单列或分组结构。
- 房间监控在窄屏下不再依赖固定宽表格。

仍需验证：

- 手机端完整完成创建或加入房间、选组、锁定、准备和退出。
- 共享卡组长清单、复制入口和返回路径在窄屏下保持可达。
- 多房间、多玩家和长状态文本下，管理员操作不被折叠或遮挡。

## 横向基础差距

### 覆盖层与滚动

- 轻任务统一使用 bottom sheet，重任务统一使用全屏任务层；旧页面仍需逐步收口。
- 每个覆盖层都需验证显式关闭、ESC 或返回语义、背景滚动锁定、内部滚动和安全区。
- 同一时刻出现两个以上覆盖层时，必须有明确的所有权和关闭顺序。

### 触控

- 核心操作目标以 44 × 44 CSS px 为建议下限。
- 小尺寸卡牌内部按钮无法放大时，必须在详情、动作条或菜单提供等价入口。
- hover、长按和双击只能作为增强能力，不能成为手机端唯一完成路径。

### 断点

- 通用设备层级以移动端适配需求中的 640、768、1024 为主。
- 420、480、560、767、960 等过渡断点必须对应明确页面问题，并在组件或验收记录中说明用途。
- 不为单个视觉微调持续新增断点。

## 验收缺口

当前 `client/tests/e2e/mobile-layout.spec.ts` 已覆盖 390 × 844、430 × 932、768 × 1024、1024 × 768 的基础布局与页面级横向溢出检查。

仍需补充：

1. 真实或等价软键盘状态下的表单可达性。
2. 覆盖层背景滚动锁定、内部滚动和安全区断言。
3. 卡组编辑器抽屉叠加与触控热区验收。
4. 对战页从换牌到结果确认的手机基础流程。
5. 平板横屏的对战浮层遮挡矩阵。

## 推荐推进顺序

1. 先补覆盖层、软键盘和安全区的通用验收能力。
2. 收口卡组编辑器与后台的触控热区。
3. 为对战页建立点击式核心动作与统一任务层。
4. 以完整手机对局和真实联机房间流程收束验收。
