# 对局入口卡组选择现状与未落地项

> 文档类型: 专题说明
> 适用范围: 游戏准备页、休闲对战大厅、联机调试页的卡组选择与开始/锁组路径
> 最后更新: 2026-10-24
> 当前状态: 描述当前实现事实与明确未落地能力；代码行为以相关代码路径为准

## 当前范围

对局入口选组体验覆盖以下页面：

- 对墙打和本地双人调试准备页，代码路径为 `client/src/components/pages/GameSetupPage.tsx`。
- 休闲对战大厅的找人、建房、加入、换组与赛后选组弹层，代码路径为 `client/src/components/pages/CasualLobbyPage.tsx`。
- 联机调试准备页，代码路径为 `client/src/components/pages/OnlineDebugPage.tsx`。
- 共用卡组选择控件，代码路径为 `client/src/components/common/DeckSelector.tsx`。

当前目标是降低进入对局前的重复选择和长列表滚动成本，同时保持锁组、准备和开始对局仍由玩家显式操作。

## 当前已实现

### 入口级上次使用卡组

前端会在本地记录部分入口的上次成功使用卡组：

- 休闲大厅：参与、换组或赛后选组成功后，按账号与标准／娱乐模式分别记录当前云端卡组；玩家大厅延续同一偏好。
- 对墙打：成功开始对墙打时记录己方卡组；离线会话记录浏览器本地卡组 ID。
- 本地调试：成功开始本地调试时分别记录 Player 1 / Player 2 卡组；离线会话记录浏览器本地卡组 ID。
- 联机调试：成功锁定调试卡组时按 match 和 seat 记录。

卡组列表加载完成后，页面会按当前入口尝试恢复默认选择。默认选择只更新选中状态，不会自动锁组、自动准备或自动开始。

默认选择的回退顺序为：

1. 上次使用卡组仍存在且合法。
2. 只有一副合法卡组时选中该卡组。
3. 多副合法卡组时选中列表中的最新合法卡组。

### 共用卡组选择

`DeckSelector` 支持 `comfortable` 和 `compact` 两种密度，以及默认卡图网格和建房使用的单列列表。对局入口当前使用紧凑模式。

紧凑模式的当前行为：

- 条目高度更低，列表可在有限高度区域内滚动。
- 条目保留卡组名、选中态、上次使用标记和 PT。
- 合法卡组上下文中不重复展示“可用”标签。
- 对局入口按当前场景校验卡牌池与构筑；自组娱乐允许超 PT，标准与练习仍遵守 PT 上限。标准选择器可只读识别「娱乐模式可用」的超限卡组，其余构筑错误不可提交。
- 卡图网格中的选中卡组有强调边框和勾选图标；建房列表使用淡色背景和勾选图标。

`DeckSelector` 刷新或默认选中变化时不会播放整列入场动画。

### 休闲大厅选组

休闲准备在大厅按任务打开选组弹层，复用紧凑 `DeckSelector`；开局和正式桌面仍由 `OnlineRoomPage` 承担。

当前行为：

- 找人、建房和加入时选择合法云端卡组，提交后服务端冻结快照；选组本身不占座。
- 按房间标准／娱乐规则校验当前卡池与构筑后才可选择；默认显示已选卡组摘要，点击“更换”展开列表，选定后收起。
- 等待阶段可通过“换组”打开弹层；配对后需先取消配对，再重新选组。
- 赛后发起或同意再战时分别选组，再进入双方重新确认的新轮次。
- 弹层标题保持可见，内容内部滚动，确认区吸附在底部；提供 Escape 关闭与焦点返回，无合法卡组时可进入卡组管理。

创建房间中的“更换”进入同一弹层的选组子视图：

- 单列条目使用固定 40×56px 封面、最多两行名称、PT 与选中标记；其他入口继续使用原有卡图网格。
- 卡组达到 6 副时提供名称搜索；不可用卡组折叠展示当前卡池与构筑验证返回的原因，超 PT 卡组保留切换娱乐模式的入口。
- 列表随内容增高，由弹层内容区承担滚动；选组期间隐藏房间表单，保留房间号、备注、访问方式和观战设置。
- “返回房间设置”保留原选择；选定卡组后直接返回设置。展开时聚焦当前卡组，返回或选定后聚焦“更换”。未选卡组时提供“选择卡组”入口。

弹层使用共享遮罩、表面、圆角和间距 token，控件复用 `ActionButton` / `TextInput`；移动端保留底部抽屉布局。

房间准入、再战与公开范围见[社区对战大厅设计](../online-mode/community-lobby-design.md)。

### 联机调试准备页

联机调试页与正式联机页使用相同的信息层级：

- 当前 match 和 seat 状态优先展示。
- 当前调试卡组摘要和锁组/重置操作位于卡组列表之前。
- “更换调试卡组”列表使用紧凑模式和有限高度滚动。

### 对墙打与本地调试准备页

`GameSetupPage` 在同一页面选择卡组并开始：

- 对墙打选择己方卡组后直接开始；不设独立确认页。
- 本地双人调试在桌面并排选择双方卡组，窄屏通过玩家页签切换；底部保留双方选择摘要和开始操作。
- 已登录在线会话从云端卡组选择；离线会话从当前浏览器的本地卡组选择，不把本地记录用于服务端对局准入。
- 离线会话没有合法本地卡组时，空状态可直接进入卡组管理，从空白、YAML 或内置示例创建卡组。
- 卡组选择器使用紧凑模式，列表独立滚动，底部操作保持可达。
- 页面会按入口和玩家位恢复默认卡组。
- 模式切换与对局说明按需打开浮层，不推移开始操作；失败保留选择并允许重试。

## 当前未落地

### 服务器端用户偏好

上次使用卡组目前只保存在浏览器本地。不同设备、不同浏览器或清空本地存储后不会同步。

### 折叠式更换卡组入口

休闲大厅在任务弹层默认显示已选卡组摘要，按需展开列表；对墙打、本地调试和联机调试仍在当前选组步骤直接展示紧凑列表。

### 推荐卡组摘要区

当前默认选中会显示在现有摘要和列表中，但没有单独的“推荐使用”摘要卡。

### 大列表筛选

创建房间的选组子视图在卡组达到 6 副时提供名称搜索；其他对局入口尚不提供入口内搜索、“只看最近更新”或其他轻量筛选。列表仍依赖 `buildDeckDisplayItems` 的排序结果，并优先显示上次使用的可用卡组。

### 联机调试的常驻主操作区

联机调试把主操作提前到列表之前，但没有为所有视口提供始终吸附的操作栏。

### 对局入口专项 Playwright 视口验收

`client/tests/e2e/casual-lobby-layout.spec.ts` 覆盖休闲大厅 320／390／768／1440 宽度、两种主题、200% 文本及弹层焦点；`casual-lobby-real.spec.ts` 提供显式启用的双登录选组、再战和认输退出流程。`setup-and-mulligan.spec.ts`、`battle-entry.spec.ts`、`product-page-recovery.spec.ts` 与 `mobile-layout.spec.ts` 覆盖对墙打和本地调试的直接开始、短屏操作可达、失败保留选择与说明展开后的布局稳定；Excel 选组由 `excel-mode.spec.ts` 覆盖。页面级 mock 验证不能替代真实服务端验收。

待覆盖的视口场景包括：

- 1366 x 768 下联机调试卡组列表不会把主操作区挤出视口。

### 玩家大厅 C 布局

`HomePage` 只展示当前玩法的一副合法卡组，按需打开共享 `DeckSelector` 与只读构筑详情。首页选组临时保留；进入对战大厅、赛季排位、对墙打或双人调试时，分别写入既有 `publicTable`、`ranked`、`solitaire`、`localDebugPlayer1` 偏好，后续准备页继续校验并采用该选择。娱乐模式使用平台预组，不展示自建卡组选择器。首页不创建、导入或保存账号卡组。

选组弹层标题旁提供“卡组管理”，构筑详情标题旁提供“编辑卡组”，后者直接打开当前云端或本地卡组的既有编辑器，不自动保存。正常选组时按过期策略自动读取，移除常驻刷新按钮；读取失败时显示“重试读取卡组”。选组列表随内容增高，达到视口上限后在列表内滚动，标题与快捷入口保持可见。
