# 海克斯质变、起动与取得检索

> 文档类型：实现说明
> 范围：共享权威规则、真人海克斯与本地双人调试；基础流程见[联机说明](hextech-online.md)。

## 效果口径

| 稀有度 | 海克斯       | 效果                                                                                                                 |
| ------ | ------------ | -------------------------------------------------------------------------------------------------------------------- |
| 银     | 质变：金     | 保留自身，取得时随机额外获得一个已实现的金色海克斯。                                                                 |
| 金     | 质变：彩     | 保留自身，取得时随机额外获得一个已实现的彩色海克斯。                                                                 |
| 彩     | 会玩         | 自己主要阶段每回合一次，弃至少一张手牌，抽等量；弃光发动前的原有手牌时额外抽一张。空手不能发动。                     |
| 金     | 好好睡好好睡 | 己方顶层舞台有待机的近江彼方时，玩家合计分数加二；自己的主要阶段每回合一次，可令己方一名活跃成员待机。两段独立生效。 |
| 银     | 我为歌狂     | 取得时弃掉手牌中的全部成员，保留其他类型手牌，再从主卡组或休息室检索等量 LIVE 加入手牌；不足时尽量执行。             |

质变使用权威随机源，不排除已持有条目。金→彩连锁允许发生，当前定义的稀有度严格递增，因此最多两层。每次额外取得生成独立来源实例，沿用当前回合的取得阶段，取得收益正常执行；随机结果随持有记录、动作及 checkpoint 保存，恢复不重新随机或重发收益。

每份「会玩」「好好睡好好睡」实例分别计算每回合次数。次数来自权威 `HEXTECH_ACTIVATED` 动作中的实例和回合，不额外维护可漂移的次数副本。选择尚在客户端时不支付或占次数，命令通过完整校验后一次性提交；随机取得、检索和本批起动不提供撤销。

## 取得顺序与选牌

双方锁定后，在同一个权威提交中登记并公开双方持有，再按先攻顺序处理完整的取得效果。`acquisitionQueue` 仅保存尚未处理的持有实例 ID；`pendingSearch` 保存当前检索来源和数量。遇到「我为歌狂」时，弃牌发生一次，后续取得收益及通常回合入口等待检索完成。中途恢复直接续办选择，不重复弃牌或发放收益。

检索必须选择当前可取得数量，即请求数量与可用 LIVE 数量的较小值。没有候选时仍可确认继续。候选包括自己的主卡组与休息室，按卡号及对象标识中性排序，不能推断牌堆顺序；确认后主卡组洗切。候选、准确可选数量仅投影给处理者，其他玩家与观战者只看到公开来源和等待方。回放按授权视角只读展示。

主动命令 `ACTIVATE_HEXTECH` 和检索命令 `RESOLVE_HEXTECH_SEARCH` 使用真实持有实例作为来源。它们通过 `GameSession` 校验归属、阶段、数量、候选、次数和幂等性，复用已有弃牌、抽牌、区域移动与待机动作；不创建虚构的来源卡。实际弃牌与待机产生既有规则事件，诱发卡效等待当前效果完整执行后进入检查时点。

共享 `GameBoard` 的海克斯摘要提供起动入口，选牌面板展示卡面、所在区域与可展开的完整资料。选中列表属于客户端临时状态，提交时重新校验；检索中可以收起和重新打开，权威进度保持不变。

## 持久化与验证边界

新增字段仅属于海克斯权威状态与投影，没有数据库结构迁移；部署需同步前后端。回放复水仅在存在海克斯状态时执行相应校验，普通无海克斯最小 checkpoint 不要求提供海克斯校验所需的玩家资料，已存在的海克斯损坏状态仍严格拒绝；没有增加旧格式双读。

规则测试覆盖连锁取得、取得暂停、双方顺序、候选不足、零候选、恢复、拒绝非法输入、独立次数、弃光额外抽牌、待机事件、条件分数与普通玩法隔离。正式服务测试覆盖身份校验、命令重试和观战候选隔离。浏览器使用隔离卡池和真实本地命令验证取得检索、起动与玩家可见结果；不代表生产账号完整链路验收或平衡试打完成。
