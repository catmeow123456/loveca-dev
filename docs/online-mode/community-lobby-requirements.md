# 社区对战大厅需求

> 文档类型：需求文档
> 适用范围：休闲找对手、公开房间、凭链接约战、房间发现和观战入口
> 当前状态：已在本地实现；生产切换与真实账号双端验收尚未完成
> 最后更新：2026-10-23
> 依据：[调研](community-lobby-research.md)；配套：[业务与 UI 设计](community-lobby-design.md)

## 1. 产品目标

「对战大厅」统一提供公开找人、凭链接约战和观战入口。玩家进入后能直接知道谁在等待、谁正在对战，并可选择房间或创建约战。

公开等人房间同时服务自动找人和主动选房。玩家选择的是“帮我找一局”或“和这个人打一局”，不必理解队列、票据或房间引导等内部概念。

## 2. 用户与任务

| 场景             | 玩家目标               | 应有结果                                           |
| ---------------- | ---------------------- | -------------------------------------------------- |
| 熟人约好打一局   | 给对方一个固定入口     | 创建凭链接加入的房间，复制链接或房间号             |
| 想随便打一局     | 尽量少操作地开始       | 选择合法卡组后找对手，由系统加入或创建公开等人房间 |
| 看到认识的人在等 | 直接选择对手           | 从房间列表加入，与房主确认后开局                   |
| 暂时不打         | 看社区正在发生什么     | 浏览公开房间，进入开放的观战视角                   |
| 从对局返回       | 随时回到尚未离开的房间 | 固定的“我的房间”入口，服务端验证后恢复             |
| 低活跃时段       | 知道当前确实没人等     | 真实空态，能够建立一个公开等人房间并分享           |

“熟人”描述使用场景，不代表好友名单、邀请白名单或指定用户鉴权。

## 3. 范围

大厅包含标准／娱乐模式选择、同模式公开找人、建房和加入、双方开局确认、当前房间恢复、公开房间列表、观战入口、赛后再战和失败恢复。

赛季排位与使用平台预组的「主题牌桌」保留独立入口、匹配条件和计分规则，不进入标准／娱乐公开列表或自动找人供给；已有房间号观战能力保留。单人测试、调试、历史回放和管理员房间不进入列表。

当前不提供全站聊天、好友系统、推送、预约、多人房、卡组推荐或完整进行中对局的跨进程持久恢复。

## 4. 业务规则

### FR1 单一目的地

- 自组真人入口及休闲对局返回路径统一进入「对战大厅」。
- 大厅提供找对手、创建房间、输入房间号和公开房间浏览。
- 观战可从进行中房间直接进入；已有观战链接仍有独立访问能力。
- 从房间返回时回到对战大厅；「返回首页」与「返回对战大厅」在文案和行为上区分。
- 浏览不要求先选卡组。参与休闲对局时再选择合法卡组；无合法卡组仍可浏览和观战。

### FR2 同一公开等待供给

- 公开找人房间均接受列表加入和系统自动选择，适用相同的合法性与占用规则。
- 「找对手」优先选择最早开始有效等待的兼容公开房间；没有候选时，为本人建立一个公开等人房间。
- 自动建立的房间立即出现在公开列表中，具有稳定房间号和可分享入口。
- 玩家主动「创建房间」应新建自己的房间，不自动加入其他人的房间。
- 房间的建立方式不构成额外的匹配池。标准／娱乐构筑规则各有公开供给；同规则内不增加级别、水平或卡组标签分池，见 [FR9](#fr9-标准与娱乐模式)。
- 列表搜索仅改变浏览结果，不改变自动找人的范围。
- 公开找人的含义在开始前明确说明，不在创建后才告知玩家会被其他人发现。

### FR3 创建房间

- 创建时选择合法卡组及访问方式；房间号可选填写，留空自动生成。自定义号码为 4–12 位字母或数字，不区分大小写；服务端检查有效号码唯一性，同码并发创建只允许一个成功。
- 访问方式为「公开找人」或「凭链接加入」，在同一表单内选择。
- 公开找人默认选中；玩家在明确看到该选项后提交创建。
- 备注可选，最多 40 字；不强制命名房间或手填房间号。号码格式无效或已占用时保留创建表单并提示修改，不自动加入已有同号房间。
- 创建后进入本房间等人状态，可以复制链接、复制房间号、返回大厅、取消并关闭房间。
- 本人的观战偏好在准备操作中可见，并可独立调整。

### FR4 加入与确认

- 从列表或房间号发起加入时，玩家先选择合法卡组，再确认加入；浏览卡组期间不占用对方空席。
- 真正加入必须原子认领空席。一名玩家成功后，其他人得到房间已满或状态已变的明确结果。
- 无论自动还是手动加入，配对后都由双方确认开局。不得将等待时的操作当成对某个具体对手的永久确认。
- 确认期限默认 60 秒（平台可配置，30–300 秒），显示剩余时间、双方昵称和自己的卡组；这沿用现有公共牌桌的确认窗口。
- 双方确认前可以取消。双方确认后，卡组冻结，进入既有开局流程。
- 换组、取消、离开、确认和期限到达同时发生时，只有一个权威结果；过期页面不能确认新的配对。
- 卡组编辑不影响已经锁定的本局快照。希望更换时，在配对前更换；配对后先取消当前配对。

### FR5 等待与超时

- 每人同时只能占用一个真人候场、房间或对局位置，覆盖标准、娱乐、赛季排位和主题牌桌。
- 返回大厅或访问卡组不会自动取消等待；跨页面显示候场状态。已有联机任务时，大厅不展示练习入口。
- 可在等待期间浏览其他房间和观战。出现自己的配对确认时，须能回到确认操作。
- 想改加入另一间房时，明确执行“取消当前等待并加入”；失败时说明当前落在哪个状态，不能出现隐含双占用。
- 一方取消、失联或未确认后，未造成中断的一方保留原有效等待顺序。
- 仅主动选择「找对手」或「公开找人」的玩家可自动继续公开等待；定向加入者取消后返回大厅，不被擅自重新公开求战。
- 离线玩家的空房不能一直显示为可加入；恢复前必须重新核验在线状态与卡组合法性。
- 休闲对局内没有超时判负：对手长时间不操作时，系统不判对手负，本人也不能单方结束对局或关闭房间。本人不想继续时可自行认输立即结束本局（对手获胜），或直接离线等待双方离线后的无结果清理；排位对局不适用本条，沿用其断线与超时裁定规则。

### FR6 房间列表

- 当前所选标准／娱乐模式的公开房间列表同时显示等待加入、双方准备和正在对战的房间；列表、搜索与计数均按模式隔离。
- 等待、准备、进行中与短时保留的赛后状态在同一列表显示，不设状态分类页签；提供昵称／房间号搜索、刷新和继续加载。
- 默认顺序为等待加入、准备中、对战中、赛后；组内保持稳定顺序。
- 等待房间显示房主昵称、等待加入状态与加入操作，可补充房间号和单行备注；公开行不常驻人数和等待时长，本人等待区保留计时。
- 准备中显示双方昵称及准备状态，不重复禁用的状态按钮；不再接受第三人加入。
- 对战中显示双方昵称及是否可观战；模式在列表标题统一标识，不在每行重复。
- 本人的当前房间始终在独立区域可恢复，不受公开列表搜索影响。
- 房间结束后显示赛后状态；不再可加入或进行中，不继续计入对战中数量。
- 公开列表不展示卡组名、卡组封面、完整构筑、手牌或其他隐藏信息。玩家自己填写的备注需按普通用户文本处理。
- 无房间、搜索无结果、首次加载失败与旧数据刷新失败分别呈现。

### FR7 可发现性与观战

| 访问方式或权限       | 大厅发现                   | 对战加入                             | 观战             |
| -------------------- | -------------------------- | ------------------------------------ | ---------------- |
| 公开找人房间         | 登录成员可见               | 有空席且满足条件时可加入             | 仅开放的玩家视角 |
| 凭链接加入房间       | 不出现在公开列表及公开计数 | 知道有效链接或房间号的登录玩家可加入 | 仍需对应玩家授权 |
| 排位或主题牌桌房间   | 不进入标准／娱乐公开列表   | 不能从大厅占座                       | 凭房间号按原权限进入 |
| 房间两个视角均关闭   | 公开房间仍可显示正在对战   | 不允许以对战身份加入                 | 显示“未开放观战” |

- “知道房间号可访问”与“在大厅公开展示”是不同的产品承诺。
- “凭链接加入”不承诺仅指定好友可入；链接持有人可以转发。
- 每人只控制本人视角；一个人开放不意味着另一个人的隐藏信息也被授权。
- 保留现有独立 token 观战边界；大厅的可观战状态不能替代入场时的权限核验。
- 本人参与的对局使用「返回房间」，不提供绕过身份的观战入口。
- 房间访问方式从创建起固定，通过重新建房改变，避免对手不知情时改变曝光范围。

### FR8 恢复与赛后

- 登录后从权威占用恢复本人状态；浏览器保存的房间号只是线索。
- 换账号后清除上一账号的候场、房间和列表个性化数据。
- 返回大厅保留尚未主动离开的休闲房间；主动离开须真正释放本人占用。
- 结束一局后，双方可同意再来一局，重新选组和确认，继续沿用房间标识、模式与访问方式。
- 一方离开后，不自动将另一方投入公开等待；由剩余玩家选择「继续公开找人」或离开。
- 凭链接房间中的剩余玩家选择「继续公开找人」时，应明确告知将关闭原房间并新建公开房间；不得静默改变原房间的曝光范围。原本公开的房间可沿用标识重新等待。
- 赛季排位和主题牌桌赛后沿用各自已有规则，不能套用自组房间的再战行为。
- 如果实际对局运行态丢失，应明确显示无法恢复并按既有终局政策处理，不能展示一个可进入的假房间。

### FR9 标准与娱乐模式

两种模式使用玩家自组卡组，区别仅在总 PT 门槛；「主题牌桌」是独立的预组活动。

| 卡组状态 | 标准模式 | 娱乐模式 |
| --- | --- | --- |
| 其余构筑合法，总 PT 未超当前上限 | 可用 | 可用 |
| 仅总 PT 超限 | 不可用，提示娱乐模式可用 | 可用，显示真实 PT |
| 卡池、类型、数量或同卡限制不合法 | 不可用 | 不可用 |

- 两种模式均要求 48 张成员、12 张 LIVE、12 张能量，主卡组同基础编号最多 4 张；PT 与同卡数量按基础编号计算，不因罕度不同而另算。卡组可用性由当前构筑和所选规则判断，同一副卡组无需复制或永久分类。
- 没有当前房间且未保存模式偏好时默认标准模式。玩家大厅与对战大厅延续同一选择，按账号和模式保存浏览器内的最近选组偏好，不同步到其他设备。切换不修改账号卡组，也不自动找人。
- 公开列表、搜索、计数、分页与自动找人均按模式隔离；不因等待较久或使用标准卡组而自动跨模式配对。
- 房间创建后模式固定，覆盖等待、配对、猜拳、对战、恢复和再战。等人时可明确取消后切换；其他状态先按当前任务的退出规则处理，不能在房内更改模式。
- 房间号和分享链接可以定位另一模式的房间。加入弹层展示目标规则、按目标规则选组，以「按标准模式加入／按娱乐模式加入」明确接受；取消不改变原偏好，浏览和选组不占座。
- 找人、建房、加入、换组、确认开局和再战均按房间模式校验。标准新开局前按当前 PT 表重验；娱乐仅免除总 PT 上限，仍显示真实点数。进行中的对局不受之后 PT 表变更影响。
- 娱乐沿用正常规则自动化、隐藏信息、开局和命令权限；不授予调试能力，不计入排位评分或主题活动战绩。对墙打与调试继续使用既有 PT 准入。
- 历史记录保留实际模式，不根据卡组 PT 反推；公开模式不代表公开对手 PT、卡组名、封面或卡表，观战仍按玩家视角授权。

## 5. UI 与内容要求

首屏按「我的当前状态 → 找人及建房操作 → 公开房间列表」组织。默认只有「找对手」是全局主操作；本人已有配对或房间时，主操作随状态变为确认或返回。

模式选择使用紧凑图文单选，以固定图形、完整名称「标准模式／娱乐模式」和短下划线表达选中态。已有房间时显示实际模式；列表标题提供统一模式上下文，房间行不重复标签。

列表突出昵称、真实状态与行操作；不常驻人数或计时，只有本人等待区保留已等待时间。备注单行省略，按需打开只读全文。卡组选择按操作展开；创建表单使用紧凑卡组摘要与访问方式单选，省去重复规则长说明。具体布局见[设计文档](community-lobby-design.md#7-ui-方案)。

移动端在 320 CSS px 等效宽度下可重排；主要触屏操作沿用项目 44px 规格。键盘可完成模式选择、搜索、加入、确认和退出，状态不只依赖颜色；后台刷新不抢焦点、不清空已读内容。

## 6. 验收场景

| 编号 | 对应需求 | 验收结果                                                               |
| ---- | -------- | ---------------------------------------------------------------------- |
| AC1  | FR1      | 自组真人入口与休闲对局返回链路都到同一对战大厅                         |
| AC2  | FR2      | 手建公开房可被「找对手」选中；自动等人房可从列表加入                   |
| AC3  | FR2      | 两人同时点找对手且原无房间，最终形成一对，不留下两个永久互等空房       |
| AC4  | FR3、FR7 | 私房不出现在他人的列表、搜索或计数中，链接可按规则加入                 |
| AC5  | FR4      | 两人竞争同一空席，恰有一人成功；失败者没有占用残留                     |
| AC6  | FR4      | 双方确认前不进入正式对局；超时后旧确认不能影响新配对                   |
| AC7  | FR5      | 跨页面保持有效等待，取消后停止保活并释放占用                           |
| AC8  | FR5      | 一方未确认，无过错方按原等待顺序恢复；定向加入者不自动公开             |
| AC9  | FR6      | 同模式等待、准备和进行中可同屏被发现；搜索不隐藏我的房间               |
| AC10 | FR6      | 房间真实结束后不计入进行中，也不能继续点击加入                         |
| AC11 | FR7      | 只开放一方视角时只能进入该视角，关掉后旧页面也无法继续授权入场         |
| AC12 | FR7      | 摘要和列表响应不含卡组与对手隐藏信息                                   |
| AC13 | FR8      | 刷新、换标签页和换账号后，恢复身份与权威占用一致                       |
| AC14 | FR5、FR8 | 排位或活动已有占用时无法重复建立休闲房间                               |
| AC15 | FR8      | 休闲再战重新准备，排位与活动仍遵守原来的赛后规则                       |
| AC16 | FR6      | 断网不显示“当前无人”，重试后可恢复最新列表                             |
| AC17 | FR1、FR6 | 无合法卡组仍能浏览和获准观战，参与时有明确选组或构筑指引               |
| AC18 | FR5、FR8 | 两标签页操作、延迟响应、引导失败、服务重启均不产生双占用或假恢复       |
| AC19 | UI       | 320、390、768、1440 宽度均可完成主要任务，无水平滚动和焦点遮挡         |
| AC20 | UI       | 键盘与读屏能识别房间状态、失效原因和确认结果，刷新不打断正在操作的控件 |
| AC21 | FR9      | 两模式公开供给隔离；跨模式查号需明确接受，恢复和再战保留实际模式       |
| AC22 | FR9      | 仅有 PT 超限的卡组仍可用于娱乐，其他构筑错误被拒绝，标准开局重验 PT   |
| AC23 | FR3      | 房间号留空自动生成，自定义同码并发仅一人成功，错误后保留表单供修改     |

## 7. 验证边界

本地验证覆盖准入事务、构筑规则、迁移和浏览器交互；测试入口及部署边界见[设计文档](community-lobby-design.md#9-实现与部署边界)。生产迁移、真实账号双端验收和玩家可用性评审尚未完成，本地结果不代表这些环节已通过。
