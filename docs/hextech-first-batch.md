# 海克斯首批效果与本地测试

> 文档类型：实现说明
> 适用范围：标准规则中的 8 项海克斯效果、本地双人调试入口、共享投影与状态恢复
> 当前状态：首批效果已接入；后续随机选择与正式联机入口见[真人选择流程](hextech-online.md)

## 开放范围

首批以用户提供的海克斯工作簿为依据实现下列条目。它们没有目标选择或起动费用，适合先验证玩家持有能力与既有 LIVE 计算的连接。

| 稀有度 | 海克斯         | 效果                           |
| ------ | -------------- | ------------------------------ |
| 银     | 草莓樱桃冰淇淋 | 玩家增加粉心 1、红心 1         |
| 银     | 芒果蓝莓冰淇淋 | 玩家增加黄心 1、蓝心 1         |
| 银     | 青提葡萄冰淇淋 | 玩家增加绿心 1、紫心 1         |
| 银     | 冰淇淋盲盒     | 玩家增加 2 棒                  |
| 金     | 原味冰淇淋     | 成功 LIVE 的玩家合计分数增加 1 |
| 银     | 强欲之壶       | 取得时抽 2 张                  |
| 金     | 强强欲之壶     | 取得时抽 3 张                  |
| 彩     | 强强强欲之壶   | 取得时抽 4 张                  |

加心、加棒和加分属于玩家总量，不对每名成员或每张 LIVE 重复应用。待机或空舞台不取消玩家加成；加分不能把失败的 LIVE 变为成功。壶沿用普通抽牌与更新规则，牌不足时尽量执行。

## 本地入口

进入“对局 → 双人调试”，展开“海克斯测试”，分别勾选双方需要验证的条目。未勾选时仍为普通对局。同一玩家不能重复配置同一项；测试配置允许同时选择多项，以检验组合。

双方完成换牌后、第一次通常阶段推进前，按先攻和后攻的顺序授予配置，随后进入原有对局流程。壶的额外抽牌不参与开局换牌。牌桌工具栏的“海克斯”展示双方已经取得的完整条目；公共日志记录取得来源，牌面可见性仍由普通区域投影控制。

“重开对局”保留本局测试配置，并在新局完成换牌后重新授予一次。创建未配置的新局不会继承上一局海克斯。对墙打准备页和正式联机房间不开放该测试控件；没有增加账号或卡组写入。

这是预设授予的效果测试入口；真人对局采用[回合选择流程](hextech-online.md)，不读取此处配置。

## 共享引擎设计

- `src/domain/hextech/catalog.ts` 是已完整支持条目的目录，以稳定 ID 驱动规则，名称只用于展示。当前版本为 `HEXTECH_V1`。
- `GameState.hextech` 缺席表示未启用。启用时保存持有实例、归属、取得回合，以及换牌前尚未消费的开局配置。实例身份用于防止同次取得重复执行；不保存可以派生的加成合计。
- `GameSession.createGame` 验证并复制开局配置；换牌处理器通过 `application/hextech/acquire.ts` 完成授予。不存在玩家可任意领取海克斯的命令。
- 常时效果由 `domain/hextech/modifiers.ts` 动态生成，汇入 `collectLiveModifiers`。使用 PLAYER HEART、PLAYER BLADE 和玩家 SCORE，来源显式为 `sourceHextechInstanceId`，不伪造卡牌实例。LIVE 清理只清理临时修正，不删除持有关系。
- 壶复用 `effects/draw.ts`，取得结果一次性写入权威状态。重复实例被拒绝；重复换牌命令沿用会话幂等处理。普通检查时机继续在完整动作后处理规则。
- `PlayerViewState.match.hextech` 投影已持有条目的公开说明，不携带待授予配置、牌堆顺序或额外手牌身份。后续接入的随机候选仅对本人可见，详见[真人选择流程](hextech-online.md)。共享 `GameBoard` 使用该投影显示持有列表，观战和回放没有领取按钮。
- `HextechAcquired` 公共事件记录实际取得的实例、定义及完整说明；公开移动日志继续只描述合法公开信息。recorder 能保存该事件和包含海克斯的 authority checkpoint。

## 恢复与验证边界

海克斯状态是可选玩法字段；缺席在当前格式中就是关闭，不是需要运行时迁移的旧形状。包含该字段的状态只接受当前版本、已实现定义、有效归属、合法取得回合和唯一实例。会话恢复与 authority checkpoint 复水都验证这些条件，不重放取得动作。首批效果本身没有数据库 schema 迁移；后续房间入口的迁移见[联机说明](hextech-online.md#持久化与本地部署)。

规则回归覆盖三种壶、重复提交与非法配置、抽牌中途更新、无牌可抽、双方可见性、实际 LIVE 成败与分数、活跃／待机成员的声援数量、跨回合清理、恢复和三回合自然获胜。浏览器使用测试卡池与接口夹具，覆盖手机与桌面的本地配置、换牌、持有列表及重开；卡图资源不属于这批验收范围。后续真人双端、观战投影与恢复的验证见[联机说明](hextech-online.md#验证与剩余范围)，不代表生产账号与历史页面端到端验收。
