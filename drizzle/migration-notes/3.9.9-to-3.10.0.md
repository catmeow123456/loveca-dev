# 3.9.9 -> 3.10.0 生产迁移说明

> 文档类型：人工发布 runbook（不是 Drizzle 可执行迁移）
> 适用范围：从 3.9.9 升级到 3.10.0
> 通用生产发布流程：[`docs/production-release-runbook.md`](../../docs/production-release-runbook.md)
> 专题说明：[`cloudbase-new-card-sync-production.md`](cloudbase-new-card-sync-production.md)、
> [`ranked-deck-classifier-production.md`](ranked-deck-classifier-production.md)、
> [`card-sync-jobs.md`](card-sync-jobs.md)、[`card-sync-hardening.md`](card-sync-hardening.md)

## 结论与部署边界

- 本版本包含三条新的结构迁移：`0031_add_card_sync_jobs.sql`、
  `0032_add_deck_classifier.sql`、`0033_harden_card_sync.sql`。从 3.9.9 升级时必须在停写窗口按
  Drizzle journal 顺序执行一次 `pnpm db:migrate`；不得手工粘贴单条 SQL、伪造迁移记录或使用
  `pnpm db:push`。
- `0031` 创建上游新卡同步任务与逐卡结果表；`0032` 创建卡组分类、样板、规则、发布、任务、assignment、
  人工锁定与展示设置；`0033` 为同步任务增加租约 fencing，并为新写入的卡号和非负数值增加约束。
- API、前端、迁移源码和种子导入脚本必须来自同一个 3.10.0 release SHA。迁移完成前不得启动新 API；旧 API、
  排位开局/结算、管理员写操作、卡牌同步脚本和其他数据库写入必须先停止。
- 上游新卡同步需要生产根目录 `.env` 中的正式 CloudBase 凭据，并继续复用现有 MinIO 配置。凭据只能注入 API，
  不得进入前端、Git、数据库、日志或发布记录。
- 卡组分类首次上线还需要仓库外种子 ZIP 的 dry-run、显式 apply、首次预览/发布和后台任务验收。迁移默认隐藏卡组环境，
  种子和首个 `ACTIVE` 发布未验收前不得向玩家开放。
- 本版本新增 8 张缪高2卡牌（按基础编号统计）的自动卡效实现，但不自动修改生产 `cards` 数据，不要求执行卡牌数据同步，
  也不要求上传这些卡牌的图片。上游新卡正式同步如需执行，必须在部署后另行预览并取得运营确认。
- 本版本不包含 Android APK/AAB。TWA `versionCode`、正式签名和 assetlinks 保持不变。

## 发布前检查

1. 固定 3.10.0 release SHA、`linux/amd64` API 镜像引用与 digest、前端产物来源、上一版生产 API 的不可变
   RepoDigest、操作者和回滚负责人。确认该 SHA 的作者 `main` `Quality Gates`、候选镜像 runtime 检查和
   `Release Tag Integrity` 均按生产发布 runbook 通过。
2. 确认生产当前运行版本为 3.9.9，数据库已经按顺序应用至 `0030_add_global_battle_timeout_config`，且尚未部分执行
   0031、0032 或 0033。如果同步任务表、任一卡组分类表或相关 Drizzle 记录已经存在，停止本流程，先单独核对该环境的
   真实迁移历史。
3. 确认生产从未执行开发期已经删除的旧
   `0033_add_hidden_deck_classifier_display_mode.sql` 或
   `0034_add_deck_environment_display_sections.sql`。卡组分类结构只允许由最终的单一 0032 创建。
4. 创建并验证完整 PostgreSQL 备份，记录时间、文件位置、校验值和恢复命令。公开卡图 bucket 也应有可用快照；如果
   计划在本窗口执行正式新卡同步，还必须确认对象存储容量、写入权限和对应回滚边界。
5. 在生产仓库根目录的非 Git `.env` 中准备：

   ```dotenv
   CLOUDBASE_ENV_ID=
   CLOUDBASE_SECRET_ID=
   CLOUDBASE_SECRET_KEY=
   ```

   只接受以上正式变量名。确认 `MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_BUCKET`
   等现有生产配置仍有效。不得回显任何凭据值。
6. 将外部种子包放入发布机上的受控路径并设置为仅部署账号可读。固定交付事实为：

   ```text
   文件名：loveca_deck_classifier_codex_package.zip
   文件大小：79,461 bytes
   SHA-256：629fcf85c71080b20427e31457563117b2a44d28e8408c7320d9d930508a2380
   ```

   不得使用 `loveca-ranked-volatility.zip` 或本地 fixture 代替生产种子。
7. 核对 release SHA 中的最终迁移文件和 journal。当前审查值为：

   ```text
   004f7325dac76e9cc26dc468c98284b8ed834794c6808c0ee92106f442e150a4  drizzle/0031_add_card_sync_jobs.sql
   7ac9cf3967f169fafd53668d745ed7c0f1335e53e20ab5d1ec2d89b14593869a  drizzle/0032_add_deck_classifier.sql
   36c3467b0a96ba81d9318f8d15a436230dd7749326ad5f95aa405f19c52ec18e  drizzle/0033_harden_card_sync.sql
   ```

   部署时必须针对实际 release commit 重新计算；任一值变化都应停止并重新审查。
8. 将平台先切换为 `RESTRICTING_NEW_GAMES`，等待存量对局和后台写入收束，再进入 `MAINTENANCE`。确认未登录页面、
   深链和已安装 PWA 都显示维护状态后，停止旧 API、排位结算、评分修订、回放清理、卡牌同步脚本及其他写入任务。

## 停机迁移与种子导入

1. 在 3.10.0 release SHA 的完整源码、锁文件、devDependencies 和生产 `DATABASE_URL` 上执行：

   ```bash
   pnpm install --frozen-lockfile
   pnpm db:migrate
   ```

   生产不得重新执行 `docker/init.sql`。`docker/init.sql` 只用于全新空白演练数据库的初始化。
2. 保持旧 API 停止，按两份专题说明执行迁移后只读核对。至少确认：
   - `card_sync_runs`、`card_sync_run_items` 和 8 张卡组分类相关表均已创建；
   - journal 最新顺序为 0031 → 0032 → 0033；
   - `deck_classifier_settings` 恰好一行，卡组环境为 `HIDDEN / false / false / false`，卡牌使用率为
     `PLAYER_EQUAL / true / false / false`，高排名人数为 `30`，`draft_revision=0`；
   - 0033 的三个租约字段存在；租约代际约束已验证，四个 `cards_*` 约束保持预期的 `NOT VALID` 状态；
   - `management_audit_logs` 已接受 `DECK_CLASSIFIER` 等本版管理 scope；新卡同步的操作者、请求、任务状态和逐卡结果
     记录在 `card_sync_runs` / `card_sync_run_items`，不依赖额外的 audit scope。
3. 对种子 ZIP 先执行不连接数据库的 dry-run：

   ```bash
   pnpm deck-classifier:import-seed \
     --zip=/secure/path/loveca_deck_classifier_codex_package.zip
   ```

   输出必须为 41 个分类、366 个样板、343 个启用样板、23 个 provisional 停用样板、2 条严格规则、2 条忽略的
   软签名，且 `apply=false`。数量、版本或校验不符时停止。
4. 选择并记录真实的平台管理员或赛季管理员 UUID 作为审计操作人；经运营确认后才执行：

   ```bash
   pnpm deck-classifier:import-seed \
     --zip=/secure/path/loveca_deck_classifier_codex_package.zip \
     --apply \
     --actor-user-id=<已核对的管理员UUID> \
     --reason=首次生产导入卡组分类种子
   ```

   apply 必须返回 `committed: true`。随后确认数据库数量为 41／366／343／23／2、`draft_revision=1`，并存在
   `SEED_PACKAGE_IMPORTED` 成功审计。导入后卡组环境仍必须是 `HIDDEN`。

## 同版部署与发布后验收

1. 部署与 3.10.0 release SHA 一致的不可变 API 镜像和同一 SHA 的前端静态产物。生产机只拉取
   `linux/amd64` 镜像并以 `--no-build` 启动；不得把新前端与旧 API、新 API 与旧数据库混用。
2. 在解除维护前检查：

   ```bash
   docker compose ps
   docker compose logs --tail=200 api
   curl -fsS https://<生产域名>/api/health
   curl -fsS https://<生产域名>/api/ready
   ```

   日志不得出现迁移缺失、worker 循环异常、重复 RUNNING 任务、凭据内容或卡组分类设置读取失败。
3. 在 API 容器中只检查 CloudBase 变量是否存在，不打印值：

   ```bash
   docker compose exec -T api sh -lc '
     test -n "$CLOUDBASE_ENV_ID" &&
     test -n "$CLOUDBASE_SECRET_ID" &&
     test -n "$CLOUDBASE_SECRET_KEY"
   '
   ```
4. 平台管理员第一次只执行“上游新卡同步 → 检查新卡”。核对候选、阻断项、warning 和脱敏边界；不要把首次验收直接变成
   正式同步。正式同步会写 PostgreSQL 和版本化卡图，必须另行二次确认。
5. 在卡组分类管理中检查 41 个分类、366 个样板、23 个停用 provisional 样板和 2 条严格规则，执行全量预览。确认结果
   后发布首个版本，并等待后台任务明确为 `SUCCEEDED`、发布明确为 `ACTIVE`；HTTP 202 不代表完成。
6. 设置并验收代表卡、分类色、饼图回退、表格与三组统计。在分类和代表卡验收完成前，保持赛季卡组环境完全隐藏；卡牌使用率
   继续按其独立设置验收，不能被卡组环境开关连带隐藏。
7. 对玩家侧执行最小 smoke：登录、卡组读取、卡图、普通房间、公共牌桌、排位候场和一局受控对局；另外核对排位玩家查询、
   卡组/卡牌环境各自的 TAB 与计权、高排名样本、投降/操作超时/断线终局，以及新起动能力高亮与本批 8 张卡效的基础流程。
8. 完成数据库不一致查询、玩家侧验收和日志检查后，才将平台恢复为 `NORMAL`。如果暂不开放卡组环境，可以保持该模块完全隐藏
   并先恢复平台其他功能。

## 回滚边界

- 迁移前失败：数据库尚未变化；保持维护与停写，修正环境或产物后重新进入流程。
- 迁移或种子 apply 失败：保持全部写入停止，不部署 3.10.0，不手工修改表、约束或 journal。保留日志并核对事务状态；
  需要回到迁移前状态时，只使用已验证的发布前 PostgreSQL 备份。
- 已迁移但新应用故障：保持 `MAINTENANCE` 和卡组环境 `HIDDEN`。完整回退应同时恢复发布前数据库备份、上一版 API
  RepoDigest 和前端产物。若经单独评估暂时保留 0031–0033 并回滚应用，必须记录数据库已向前迁移，禁止使用新卡同步和
  卡牌修改入口，并按专题说明核对旧应用与新增约束的兼容边界。
- 首次分类发布失败：既有 `ACTIVE` 版本不受影响；首次发布时没有旧版本可回退，但玩家端保持隐藏。修正草稿或任务后重新预览，
  不得直接改写 release snapshot、assignment 或迁移记录。
- 正式新卡同步部分成功：已写入的 `DRAFT` 卡牌和已引用卡图不会随应用回滚自动删除。停止继续同步，按任务记录逐卡复核；
  不得批量删除卡牌或对象。
- GitHub tag、Release 和不可变 `v3.10.0` / `sha-*` 镜像不得覆盖或重写。`latest` 回滚使用提升前记录的旧 digest，
  生产 API 回滚优先使用部署前从实际旧容器捕获的不可变 RepoDigest。
