## 迁移内容

按 Drizzle journal 顺序一次执行：

1. `0031_add_card_sync_jobs.sql`：新增上游卡牌同步任务和逐卡结果表。
2. `0032_add_deck_classifier.sql`：新增卡组分类、样板、规则、发布、任务、assignment、人工锁定和展示设置。
3. `0033_harden_card_sync.sql`：增加同步租约 fencing，并为新写入的卡号和非负数值增加约束。

禁止手工执行单条 SQL、伪造 journal、使用 `pnpm db:push` 或重新执行 `docker/init.sql`。

本版本的 8 张新卡效只改应用逻辑，不自动修改生产 `cards` 数据，也不要求同步卡图。CloudBase 正式同步是独立运营动作，不属于本迁移窗口。

## 执行

### 1. 迁移 schema

```bash
cd /root/loveca
pnpm install --frozen-lockfile
pnpm db:migrate
```

确认 journal 最新顺序为 0031 -> 0032 -> 0033，并核对：

- `card_sync_runs`、`card_sync_run_items` 和 8 张卡组分类相关表存在。
- `deck_classifier_settings` 恰好一行。
- 初始卡组环境为 `HIDDEN / false / false / false`。
- 卡牌使用率为 `PLAYER_EQUAL / true / false / false`，高排名人数为 30。
- 初始 `draft_revision=0`。
- 0033 的租约字段和约束存在。

### 2. 校验并导入种子

先做不连接数据库的 dry-run：

```bash
pnpm deck-classifier:import-seed \
  --zip=/root/loveca_deck_classifier_codex_package.zip
```

结果必须为 41／366／343／23／2，且 `apply=false`。随后使用已核对的管理员 UUID 执行：

```bash
set -a
. ./.env
set +a

pnpm deck-classifier:import-seed \
  --zip=/root/loveca_deck_classifier_codex_package.zip \
  --apply \
  --actor-user-id=<管理员 UUID> \
  --reason=首次生产导入卡组分类种子
```

该脚本不会自动读取根目录 `.env`，所以 apply 前必须显式导出环境变量。完成后确认：

- `committed=true`。
- 数量仍为 41／366／343／23／2。
- `draft_revision=1`。
- 存在成功的 `SEED_PACKAGE_IMPORTED` 审计。
- 卡组环境仍为 `HIDDEN`。

### 3. 部署和验收

按通用 runbook 部署同一 SHA 的 API 与前端，验证健康检查、日志、版本 SHA 和基础业务流程。首次验收只允许“检查新卡”，不要执行正式卡牌同步。

在卡组分类后台确认种子数量和展示设置；完成分类、代表卡和首个发布验收前保持卡组环境隐藏。HTTP 202 只表示任务已接收，必须等待任务 `SUCCEEDED` 且发布变为 `ACTIVE`。

## 回滚边界

- 0031-0033 前失败：恢复旧应用即可。
- schema 迁移或种子 apply 失败：保持维护和停写，不手工改表或 journal。
- 有迁移前备份：可恢复数据库、旧 API 镜像和旧前端。
- 无迁移前备份：不得把旧 API 直接接回已变化的数据库；保持维护并向前修复。
- 分类首次发布失败：保持玩家端隐藏，修复草稿后重新预览和发布，不直接改 release snapshot 或 assignment。
- 正式新卡同步若在其他窗口部分成功，不能靠应用回滚删除已写入的卡牌或对象；必须按同步任务逐卡处理。
