# 普通与娱乐构筑规则迁移

适用迁移：`0044_add_casual_rule_modes.sql`。本说明不代表生产迁移或部署已经执行。

- 房间沿用既有 `environment_id`：`CASUAL_TABLE_V1` 为普通，`CASUAL_UNLIMITED_PT_V1` 为娱乐；新增数据库约束，运行时拒绝未知环境，不增加旧格式双读。
- 新增 `match_records.casual_rule_mode`，新自组真人对局明确写入 `NORMAL`／`UNLIMITED`。排位、主题牌桌、对墙打及 AI 调试使用空值，保留原来源与活动身份。
- 迁移将既有 `ONLINE_ROOM`／`PUBLIC_TABLE` 真人历史回填为普通，排除有主题分配记录的对局。既有规则只允许普通构筑，因此无需通过 PT 数值猜测模式。
- 创建、找人和定向加入协议增加必填 `ruleMode`；前后端需要一起部署。旧页面提交缺字段会收到参数错误并要求刷新；已有房间依旧由服务端的实际环境决定。

部署应先限制新准入，排空运行中房间并停止旧写入，备份后对副本执行迁移与校验，再迁移并部署对应前后端。不要在承载旧服务的运行库上单独开放娱乐准入。校验历史回填、活动记录空值、房间环境约束及普通／娱乐隔离；回退前先排空新增娱乐房间并备份新历史，不能直接丢弃模式列。

本地验证使用 `tests/integration/casual-rule-migration-postgres.test.ts` 的随机隔离 schema，不修改应用账号或现有房间。
