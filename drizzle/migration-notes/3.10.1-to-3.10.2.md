# 3.10.1 -> 3.10.2 生产迁移说明

> 文档类型：人工迁移说明（不是 Drizzle 可执行迁移）
> 适用范围：从 3.10.1 升级到 3.10.2
> 当前状态：发布准备中；尚未在生产执行
>
> 本文只记录 3.10.2 特有的数据迁移。通用停机部署流程见
> [`docs/production-release-runbook.md`](../../docs/production-release-runbook.md)。

## 迁移内容

按 Drizzle journal 顺序执行 `0037_add_matchmaking_audio_preferences.sql`：

- 在 `profiles` 表新增 `matchmaking_bgm_enabled`，类型为 `boolean`，默认值为 `true`，且不允许为空。
- 在 `profiles` 表新增 `matchmaking_match_sound_enabled`，类型为 `boolean`，默认值为 `true`，且不允许为空。
- PostgreSQL 会把默认值应用到既有档案；本迁移不删除或改写其他业务字段。

禁止手工执行 SQL、伪造 journal、使用 `pnpm db:push` 或重新执行
`docker/init.sql`。

本版本不新增生产环境变量，不需要卡牌数据或卡图重同步，也不涉及对象存储写入。

## 迁移前门禁

- 应用确认为 3.10.1，Drizzle journal 已到 `0036_add_theme_deck_choice`，且未部分执行 0037。
- API、前端和迁移源码来自同一 v3.10.2 release SHA。
- 候选 `ghcr.io/catmeow123456/loveca-api:v3.10.2` 镜像已按通用 runbook 第 2 节通过固定 `linux/amd64` 平台、runtime 入口语法与 production-only 运行时 import 检查。
- 平台已经进入 `MAINTENANCE`，旧 API、前端和所有数据库写入任务已停止。
- 已创建迁移前数据库备份。若负责人明确放弃备份，必须在部署记录中写明“迁移后只能向前修复”。

## 执行

### 1. 迁移 schema

```bash
cd /root/loveca
pnpm install --frozen-lockfile
pnpm db:migrate
```

确认 Drizzle journal 最新项为 `0037_add_matchmaking_audio_preferences`，并核对：

- `profiles.matchmaking_bgm_enabled` 与 `profiles.matchmaking_match_sound_enabled` 均存在、类型为 `boolean`、`NOT NULL` 且默认值为 `true`。
- 既有 `profiles` 行的两个字段均不为 `NULL`；迁移后尚未主动修改偏好的用户保持两个开关开启。

可在生产数据库中执行只读核验：

```sql
SELECT column_name, data_type, is_nullable, column_default
FROM information_schema.columns
WHERE table_schema = 'public'
  AND table_name = 'profiles'
  AND column_name IN (
    'matchmaking_bgm_enabled',
    'matchmaking_match_sound_enabled'
  )
ORDER BY column_name;

SELECT
  count(*) FILTER (WHERE matchmaking_bgm_enabled IS NULL) AS bgm_null_count,
  count(*) FILTER (WHERE matchmaking_match_sound_enabled IS NULL) AS match_sound_null_count
FROM profiles;
```

### 2. 部署和验收

按通用 runbook 部署同一 SHA 的 API 与前端；前端在生产机停机后从同一 checkout 构建。
新 API 的登录、会话刷新和档案接口会读取新增字段，因此必须先完成 0037，再启动 v3.10.2 API，且前后端应同版上线。

最小业务 smoke：

- `/api/health`、`/api/ready` 通过；`version.json` 的版本与 commit SHA 正确。
- 登录、刷新会话和读取个人中心正常，返回两个候场音效偏好字段。
- 在个人中心分别关闭、开启候场背景音乐和匹配成功提示音，刷新页面后设置保持一致。
- 公共牌桌、赛季排位和娱乐模式候场分别遵守音效设置；关闭设置时不播放对应声音。
- 手机端打开卡牌详情再关闭时页面不发生滚动跳动。
- 手机端新手教程的双目标引导无遮挡，目标与说明框位置正确。
- 平台状态与站点快照读取正常后恢复 `NORMAL`。

## 回滚边界

- 0037 执行前失败：恢复旧 API 与旧前端即可。
- schema 迁移或应用部署失败：保持维护和停写，不手工改表或 journal。
- 有迁移前备份：恢复数据库、v3.10.1 API 镜像和旧前端，再执行健康检查与最小业务 smoke。
- 无迁移前备份：不得把旧应用直接接回已变化的数据库；保持维护并向前修复。
- 已发布的 `v3.10.2` tag 与镜像 tag 不得覆盖；修复应发布新的 patch 版本。
