# AI 对战数据库决定归档

> 文档类型：迁移说明
> 适用范围：`0041_add_ai_battle_evidence.sql`、AI_DEBUG 诊断材料导出
> 当前状态：待目标环境按发布流程执行；本地测试不代表生产迁移

`0041` 新建 `ai_battle_evidence_entries`，仅含自增顺序、关联 `match_records.match_id` 的对局 ID 与不限定结构的 `entry JSONB`。`match_id,id` 索引用于固定上界分页导出，外键随对局根记录删除时级联清理。没有旧数据回填、现有表重写或读时兼容；迁移前的 AI 调试局只有原有回放、费用及可能存在的本机归档。

迁移应先于新 API 部署，按既有停机流程停止旧写入、备份、执行 `pnpm db:migrate` 并核对新表、索引和外键。`drizzle-kit generate` 基于先前手工迁移后的旧快照曾把 0038–0040 的已实施差异也列入草稿；最终 `0041` SQL 仅保留新表、外键与索引，避免重放旧 DDL。测试环境需用一局 AI_DEBUG 核对 HEADER、SOURCES、决定事件和 END 的顺序、脱敏、跨管理员导出，以及服务重启后的历史 JSONL 导出。

新版本运行需要该表：若未迁移，建局时数据库归档初始化会失败并回滚本次创建，不能静默开一局无法持久记录的对战。归档写入中断时保留已经提交的前缀；缺少 END 或导出清单 `completeThroughEnd=false` 表示不能确认完整。回退到旧版本前停止新写入并备份新表；旧版本不会读取它，回退不应删除已经采集的材料。正式生产迁移和部署需另行授权。
