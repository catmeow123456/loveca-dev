# 对局回放数据保留策略

> 文档类型：迁移运行说明
> 适用范围：`drizzle/0011_add_match_replay_retention.sql` 与配套回放数据清理脚本
> 当前状态：迁移已生成，尚未在生产执行

## 目标

默认只保留最近 10 天的完整对局回放。超过窗口的已封存对局保留 `match_records`、参与者和卡组来源/名称等元信息；卡组明细会清空，时间线、检查点、公开/私密事件和决策记录会删除，并标记为 `METADATA_ONLY`。

正在进行或未封存的对局不会被清理。

排位对局还有一项数据完整性前置条件：清理前必须已在 `ranked_deck_observations` 保存双方两席、且赛季/用户/座位与 `ranked_matches` 一致的精简卡组观察事实。该事实只服务赛季环境统计，不替代原始回放；满足条件后，原始主卡组、能量卡组和卡牌摘要仍会按本策略清空。非排位对局不受这项额外保护影响。

## 执行

必须先停止会产生历史写入的服务、备份数据库，并先执行 dry-run：

```bash
DATABASE_URL=... pnpm exec tsx drizzle/data-migrations/purge-expired-match-replay-data.ts --dry-run --retention-days=10 --batch-size=100
```

确认报告中的对局数和子记录数，并确认 `blockedRankedMatchCount=0` 后，再执行：

```bash
DATABASE_URL=... pnpm exec tsx drizzle/data-migrations/purge-expired-match-replay-data.ts --apply --yes --retention-days=10 --batch-size=100
```

该操作会永久删除回放子记录，不能依靠应用层恢复。完成后应执行 `VACUUM (ANALYZE)`；若磁盘空间必须立即归还给操作系统，再在低峰期评估 `VACUUM FULL` 或表级重建的停机影响。

如果 `blockedRankedMatchCount>0`，apply 会在删除开始前整体失败。应保持原始明细不动，先按 `drizzle/migration-notes/ranked-season-environment.md` 回填或修复排位观察事实，再重新 dry-run；不得为了释放空间绕过保护或静默跳过这些排位对局。

管理员历史列表和详情接口仍会返回元信息；普通玩家历史列表只展示最近 10 天。旧对局的时间线、回放和管理员导出接口返回 HTTP 410 `MATCH_RECORD_REPLAY_DATA_PURGED`。
