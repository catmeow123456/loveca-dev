# 3.10.5 → 3.10.6 部署迁移说明

> 文档类型：专题说明
> 适用范围：从已完成 3.10.5 迁移的环境升级至 3.10.6
> 当前状态：发布材料；不表示生产迁移、部署或 AI 对战开放已经完成

## 数据库

本版新增两项已登记的 Drizzle 迁移，必须在新 API 启动前执行：

- `0039_add_ai_debug_match_origin.sql`：扩展对局来源 CHECK，允许 `AI_DEBUG`。旧来源及未知来源的校验边界见 [AI 调试对局来源](ai-debug-match-origin.md)。
- `0040_add_ai_battle_billing.sql`：新增可空 `match_records.ai_billing` JSONB，并限制非空计费只属于 AI 调试对局。旧记录保持 NULL，不从历史材料回填费用；执行与校验见 [AI 对战计费迁移](ai-battle-billing.md)。

按 [生产部署 Runbook](../../docs/production-release-runbook.md) 进入维护、停止写入并备份，先在备份副本验证迁移，再对目标库执行 `pnpm db:migrate`。确认没有进行中的旧 AI 对局；两项迁移不要求一次性数据转换、种子导入或历史 checkpoint 重写。不要使用 `db:push`、重新执行历史 SQL 或在运行时补字段。

从更早版本升级时，先完成 [3.10.4 → 3.10.5](3.10.4-to-3.10.5.md) 及其前置迁移；本说明不能替代目标库迁移记录核对。

## 配置与产物

- API 镜像新增 `assets/ai-battle`，包含精选目录、规则与策略手册，并继续携带 `assets/decks`。运行时应使用与发布提交一致的资产；无需新增对象存储 bucket、上传资源或同步卡库。
- AI API 上游 URL/Key 复用平台 AI 配置与既有加密主密钥、主机白名单。没有环境凭据 fallback，旧 `AI_BATTLE_BASE_URL` / `AI_BATTLE_API_KEY` 不自动迁入数据库。配置变更只影响新局，已有局冻结原配置。
- `.env.example` 增加 `AI_BATTLE_MODEL` 与 `AI_BATTLE_TEMPERATURE` 示例；网页模型由每局显式选择，支持列表以 [模型注册表](../../src/online/ai-battle-model-registry.ts) 为准。不得把默认示例当作所有上游均可用的保证。
- 本地 Codex、会话缓存/换线程与完整归档均为显式启用的本机开发能力，生产不得开启 `AI_BATTLE_LOCAL_CODEX` 或 `AI_BATTLE_LOCAL_ARCHIVE`。标准 API 镜像不包含本机 CLI 或登录凭据；配置边界见 [本地接入说明](../../docs/ai-battle/local-codex.md)。
- 首页常用入口偏好保存在浏览器 localStorage，无账号数据回填。前后端应成套更新，旧 AI 创建请求不补缺省模型或思考参数。

## 部署验收与回退

完成两项迁移的字段及 CHECK 校验后，按 Runbook 使用已验证的 `linux/amd64` 不可变 API 镜像，在停机窗口构建前端并部署，核对版本、入口语法、运行时导入和健康状态。

AI 对战保持管理员调试范围，生产开放另行确认。获准开放时才执行平台配置和真实模型调用验收，核对对局来源、原始 usage、累计费用与历史读取；发布 CI 不代表真实模型策略质量或生产环境已验收。当前构筑与窗口限制见 [支持矩阵](../../docs/ai-battle/support-matrix.md)。

回退前停止写入并保留数据库备份。存在 `AI_DEBUG` 记录时不得直接把旧版本接回并误标来源；不要删除已采集的计费字段来掩盖未确认用量。按两项迁移专题与 Runbook 判断数据恢复或向前修复路径，不覆盖公开 tag 或镜像。
