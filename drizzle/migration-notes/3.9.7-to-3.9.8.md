# 3.9.7 → 3.9.8 生产迁移说明

> 文档类型：人工发布 runbook（不是 Drizzle 可执行迁移）
> 适用范围：从 3.9.7 升级到 3.9.8
> 通用生产发布流程：[`docs/production-release-runbook.md`](../../docs/production-release-runbook.md)
> 主题牌桌专题：[`drizzle/migration-notes/theme-table-v1.md`](theme-table-v1.md)

## 结论与部署边界

- 本版本包含 `0026_add_theme_table_v1.sql` 与
  `0027_add_player_battle_entry_visibility.sql`。从 3.9.7 升级时必须在停写窗口执行
  `pnpm db:migrate`，并确认两条迁移均登记成功。
- `0026` 新增主题赛季、服务端预组版本、对局组合和不可变分配记录，并扩展公共牌桌票据、预留与玩家占用的
  `THEME` 环境身份。迁移不会创建默认主题赛季、预组、组合或分配，也不会自动开放主题候场。
- `0027` 为赛季排位与主题赛季增加独立的玩家入口开关。新列默认可见；由于主题牌桌仍处于开发/内测基线，
  本次生产部署必须在恢复流量前显式保持主题入口关闭，且不得创建或激活生产主题赛季。
- API、前端和迁移必须来自同一 3.9.8 release SHA。旧应用不识别 `THEME` 票据或分配；在 3.9.8 API 与前端
  完成部署和 smoke 前，不得生成主题运行数据。
- 本版本扩展 Loveca Excel / CloudBase 同步工具，使其可按卡牌类型同步成员费用、BLADE、LIVE 分数，并支持
  以源图内容哈希刷新指定卡图文件名。这些是运维工具能力，不是本版本的必执行数据步骤；本次发版不得重复执行
  卡牌数据 apply、卡图重传或对象存储写入。以后如需单独同步，必须先 dry-run、审核逐字段差异并另行授权。
- 本版本不包含 Android APK/AAB。Android 版本字段、正式签名和 assetlinks 保持不变。

## 发布前环境、备份与维护窗口

1. 记录 3.9.8 release SHA、API 候选镜像标签与 digest、固定生产平台 `linux/amd64`、前端产物来源、
   GHCR `latest` 起始快照、操作者和回滚负责人。确认 exact-SHA `Quality Gates`、候选镜像 runtime 检查和
   `Release Tag Integrity` 均按发布 runbook 通过。
2. 确认 3.9.7 生产数据库已经按顺序应用 `0001` 至 `0025`，并审查 `0026`、`0027` 与 Drizzle journal；
   不得修改已共享迁移或使用 `pnpm db:push`。
3. 停止旧 API、公共牌桌与排位开局、联机房间创建、赛季管理和其他数据库写入，等待在途事务收束。迁移会替换
   公共牌桌票据/预留及玩家占用的 check constraint，不应与旧进程并发执行。
4. 创建并验证完整 PostgreSQL 备份，记录备份位置、校验结果和恢复命令。至少单独核对
   `public_table_tickets`、`public_table_reservations`、`gameplay_participations` 与 `site_status_config`。
5. 本版本没有新增生产环境变量。若未来另行执行卡牌同步，仍须单独准备生产 `DATABASE_URL`、CloudBase 凭据和
   MinIO 配置，并遵循卡牌同步专题文档；这些凭据和操作不属于本次迁移窗口的默认输入。

## 停机迁移与部署顺序

1. 在 3.9.8 release SHA 的完整源码、锁文件、devDependencies 和生产 `DATABASE_URL` 上执行：

   ```bash
   pnpm db:migrate
   ```

   不得使用 `pnpm db:push`，不得手工补写 Drizzle journal。

2. 在仍保持停写时，显式关闭尚未完成生产验收的主题入口；如果 `site_status_config` 尚无默认行则创建，已经存在时
   只修改主题入口，不覆盖排位入口或其他站点状态：

   ```sql
   INSERT INTO site_status_config (
     id,
     lifecycle,
     ranked_entry_visible,
     theme_table_entry_visible
   )
   VALUES ('default', 'NORMAL', true, false)
   ON CONFLICT (id) DO UPDATE
   SET theme_table_entry_visible = false,
       updated_at = now();
   ```

3. 只读核对迁移结果与空主题基线：

   ```sql
   SELECT version_key, lifecycle, environment_id
   FROM theme_table_versions
   ORDER BY created_at;

   SELECT
     (SELECT count(*) FROM theme_prebuilt_deck_versions) AS deck_version_count,
     (SELECT count(*) FROM theme_matchup_pair_versions) AS matchup_count,
     (SELECT count(*) FROM theme_table_assignments) AS assignment_count;

   SELECT ranked_entry_visible, theme_table_entry_visible
   FROM site_status_config
   WHERE id = 'default';

   SELECT queue_kind, count(*)
   FROM public_table_tickets
   GROUP BY queue_kind
   ORDER BY queue_kind;
   ```

   生产首次应用本版本时，主题赛季、预组、组合、分配及 `THEME` 票据预期均为 0；
   `theme_table_entry_visible` 必须为 `false`。任何非预期主题数据都应阻塞部署并核查来源。

4. 部署与 release SHA 一致的 `ghcr.io/catmeow123456/loveca-api:v3.9.8`（或发布记录中的不可变 digest）和
   同一 SHA 的前端静态产物。生产机只拉取镜像并以 `--no-build` 启动，不重新构建 API。
5. 检查 `/api/health`、首页、`version.json`、PWA manifest 与图片代理；确认普通房间、公共牌桌和排位入口、
   候场、开局与结算继续工作，主题入口对普通玩家不可见。
6. 本版本只修正 `PL!N-bp4-002-P/R` 费用 9「中须霞」跨玩家检视与公开选择流程，不需要生产卡牌数据同步。
7. 全部 smoke 正常后再恢复写入。主题活动仍保持关闭；真实预组试打、跨进程恢复、断线裁定、完整指标/告警和
   双浏览器验收完成并另行批准前，不得开放生产主题赛季。

## 回滚边界

- 数据库迁移前失败：数据库尚未变化；修复环境后可以重新进入维护窗口。
- 数据库迁移失败：保持全部写入停止，不部署 3.9.8，不手工补表、约束或 journal；根据失败点向前修复，或恢复
  迁移前 PostgreSQL 备份。
- 数据库迁移成功而新应用部署失败：保持停写和主题入口关闭。若确认没有任何 `THEME` 票据、预留、分配或主题管理
  写入，可先修复并重新部署同一 3.9.8 SHA；如必须整体回到 3.9.7，恢复迁移前数据库备份并同时回滚 API 与前端。
- 主题运行数据一旦产生，不得直接启动 3.9.7 接受流量，也不得手工删除主题表或改写约束来兼容旧应用；应停止写入，
  审核数据保留需求后选择修复 3.9.8 或从已确认的备份整体恢复。
- GitHub tag、Release 和不可变 `v3.9.8` / `sha-*` 镜像标签不得覆盖或重写；`latest` 回滚使用提升前记录的旧
  digest，生产 API 回滚优先使用部署前从实际旧容器捕获的不可变 RepoDigest。
