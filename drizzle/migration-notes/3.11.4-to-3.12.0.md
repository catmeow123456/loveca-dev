# 3.11.4 → 3.12.0 部署说明

> 文档类型：专题说明
> 适用范围：从已完成 3.11.4 迁移的环境升级至 3.12.0
> 当前状态：发布材料；不表示生产迁移或部署已经执行

## 数据库迁移

相对 `v3.11.4`，本版新增 `0045_add_bp7_sealed.sql`。按[生产部署 Runbook](../../docs/production-release-runbook.md)在停机窗口备份后执行 `pnpm db:migrate`。该迁移为休闲桌增加开盒战环境与状态约束，并为桌位增加私有牌池、草稿版本和再战邀请字段；普通旧房间保留原环境 ID。

除结构迁移外，开盒战（七弹）升级还必须停写并对历史 checkpoint 执行显式规则集迁移：先 dry-run 审查扫描数与变更数，确认备份与停写后用 `--apply --yes` 显式应用，再次 dry-run 应显示 `changed: 0`。命令、原子回滚、版本边界及与旧压缩迁移的区别见[开盒战（七弹）迁移说明](../../docs/online-mode/bp7-sealed.md#数据迁移)，执行入口为 `drizzle/data-migrations/add-bp7-ruleset-checkpoints.ts`。

建桌与定向加入协议新增必填 `format` 与 `spectatorEnabled` 字段，须协调部署同一发布提交的 API 与前端。迁移和新服务开放前先限制新准入、排空运行中房间并停止旧写入；旧页面发出的缺字段请求会收到校验错误，需刷新到新前端。

未完成 `0044` 及此前迁移的环境，应先核对[上一版部署说明](3.11.2-to-3.11.3.md)及实际数据库状态，不能仅凭应用版本推断迁移进度。卡牌数据同步仍按独立流程处理，本次发布不执行同步。

## 环境、资源与验收

本版没有新增环境变量、Docker 配置、对象存储 bucket 或前缀约定。开盒战为模拟牌池，不涉及账号卡组写操作。

部署后除 Runbook 常规检查外，核对历史回放经规则集迁移后可正常复水、普通历史对局回放不受影响、开盒战建房与匹配流程（选牌、草稿恢复、再战、重新开盒）及私有牌池在对手与观战视角的隔离。
