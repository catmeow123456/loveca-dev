# 3.10.6 → 3.10.7 部署迁移说明

> 文档类型：专题说明
> 适用范围：从已完成 3.10.6 迁移的环境升级至 3.10.7
> 当前状态：发布材料；不表示生产迁移、部署或 AI 对战开放已经完成

## 数据库

本版新增 `0041_add_ai_battle_evidence.sql`：创建按对局关联的 AI 决定材料归档表及导出索引。新 API 在创建 AI 调试局前要求该表存在，因此必须先按[生产部署 Runbook](../../docs/production-release-runbook.md)停止写入、备份并执行 `pnpm db:migrate`，再部署新 API。迁移不回填旧局、不重写旧表，也不需要一次性数据脚本。表、索引、外键、导出完整性与回退边界见[AI 对战数据库决定归档](ai-battle-evidence.md)。

若目标环境尚未完成 3.10.6 的 `0039`、`0040` 迁移，须先核对并执行[3.10.5 → 3.10.6 说明](3.10.5-to-3.10.6.md)；不能仅凭当前代码或版本号推断生产数据库状态。迁移和部署仍需单独授权，不在本次发布中执行。

## 配置、资产与验收

本版没有新增生产环境变量、对象存储 bucket、卡库同步或外部资源导入步骤。API 镜像更新 `assets/ai-battle` 构筑目录及策略手册；前端、API 和这些资产应使用同一发布提交。Excel 卡牌补齐入口仅用于本地测试库，不应对生产卡库执行。

按 Runbook 核对版本、不可变 `linux/amd64` 镜像、入口语法、运行时导入和健康状态。AI 对战仍为管理员调试能力；如目标环境已获准使用，可在迁移后用测试局核对持久归档与历史 JSONL 导出。归档随对局记录保留，容量和清理应纳入目标环境的运维观察；真实模型策略质量与生产开放不由发布 CI 证明。

回退前停止写入并保留数据库备份。旧 API 不读取新表；不要删除已采集的归档或将缺少 `END` 的导出视为完整。数据库回退与应用恢复按 Runbook 和迁移专题分别判断。
