## 结论与部署边界

- 本版本包含 `0021_add_match_emote_catalog.sql`、
  `0022_add_match_emote_catalog_previous_version.sql`、
  `0023_add_ai_effect_extraction_config.sql`、`0024_add_player_wallpapers.sql` 与
  `0025_add_match_emote_sticker_pack.sql`。从 3.9.6 升级时必须在停写窗口执行
  `pnpm db:migrate`，并确认 `0021` 至 `0025` 全部登记成功。
- 快捷表情协议新增目录版本和资源快照，旧客户端不会发送 `catalogVersion`。项目不提供旧 payload
  fallback 或 dual-read，因此 API 与前端必须使用同一 3.9.7 release SHA 构建并在同一停机窗口切换。
- `0021` 至 `0022` 建立六项初始快捷表情目录，`0025` 在保留迁移时 active 目录内容、启用状态和排序的
  前提下追加三项表情，最终默认目录为九项。数据库迁移只登记内容寻址对象键，不会向 MinIO 上传文件。
- `0023` 只建立默认禁用的 AI 卡效提取配置和追加式审计表，不迁移旧
  `DASHSCOPE_BASE_URL` / `DASHSCOPE_API_KEY`，也不会自动保存、启用或调用生产上游。
- `0024` 只增加玩家壁纸配置、私有资源事实、北京时间每日额度、持久幂等和管理员审计结构；不会创建
  玩家配置或写入壁纸对象。生产仍须准备独立私有 bucket，并完成容量、备份、孤立对象清理和内容运营确认。
- 本版本只改进卡牌同步工具和卡牌管理接口，不包含生产卡牌基础数据、卡图或卡效数据 apply；不得运行卡牌同步
  apply、对象存储卡图重传或 `pnpm db:push`。仓库中的 DeckLog YAML 只作为离线示例卡组。
- 本版本新增 `PL!-PR-023` 费用 11「绚濑绘里」、`PL!HS-PR-038` 费用 4
  「赛拉丝·柳田·利林费尔德」与 `PL!N-PR-033` 费用 9「中须霞」的卡效，并修正既有卡效、
  有效 BLADE HEART 判定及展示；这些改动不需要额外数据库迁移或生产卡牌数据 apply。
- 本版本不包含 Android APK/AAB。Android `appVersionName` / `appVersionCode` / `appVersion`、
  签名与 assetlinks 保持不变。

## 发布前环境与备份

1. 记录 3.9.7 release SHA、候选 API 镜像标签与 digest、固定生产平台 `linux/amd64`、前端产物来源、
   GHCR `latest` 的发布起始快照、操作者和回滚负责人。确认 exact-SHA `Quality Gates`、候选镜像 runtime
   检查和 `Release Tag Integrity` 均按发布 runbook 通过。生产实际镜像引用、image ID 与可重新拉取的
   RepoDigest 只在真正部署前从现有 API 容器捕获；无法取得可靠回滚目标时停止部署。
2. 为快捷表情资源确认 `MINIO_ENDPOINT`、`MINIO_PORT`、`MINIO_ACCESS_KEY`、
   `MINIO_SECRET_KEY`、公开 `MINIO_BUCKET` 与 `MINIO_USE_SSL` 指向生产对象存储。
3. 准备与公开卡图 bucket 不同的 `MINIO_WALLPAPER_BUCKET`。该 bucket 必须私有、不得允许匿名
   `s3:GetObject`，S3 API 应只允许 API 或可信网络访问；确认 API 凭据具备创建、读取、写入和删除权限。
4. 根据生产 API 的 CPU、内存和 Sharp 压测结果确认
   `PLAYER_WALLPAPER_PROCESSING_CONCURRENCY`、`PLAYER_WALLPAPER_PROCESSING_TIMEOUT_SECONDS`
   与 `PLAYER_WALLPAPER_RETIRED_RETENTION_HOURS`。同时冻结对象存储容量告警、备份、孤立对象扫描、
   删除账号和退役资源保留政策，以及投诉和管理员移除流程。
5. 若本次启用管理员 AI 卡效提取，为生产生成独立 32 字节
   `AI_EFFECT_EXTRACTION_ENCRYPTION_KEY`，配置精确的 `AI_EFFECT_EXTRACTION_ALLOWED_HOSTS`，并审查
   公开 HTTPS 上游是否符合部署策略。请求超时、响应、卡图和并发上限为代码中的固定安全边界。数据库备份
   必须与主密钥分开保护。若尚不启用，保持默认配置禁用，可以暂不提供主密钥，但不得保存或启用生产 AI 配置。
6. 停止旧 API、联机开局和对局写入、快捷表情目录管理、卡牌管理写入及其他数据库写任务，等待在途事务收束。
   创建并验证完整 PostgreSQL 备份；分别记录公开对象 bucket 和玩家壁纸私有 bucket 的备份或快照位置与恢复命令。

## 停机迁移与部署顺序

1. 在 3.9.7 release SHA 的完整源码、锁文件和生产 MinIO 配置上，先上传并校验当前种子清单中的十个
   内容寻址 WebP 对象：

   ```bash
   pnpm emotes:seed-assets
   ```

   该命令只上传缺失对象；任一 hash、尺寸或同键内容冲突都必须中止发布，不能继续执行数据库迁移。

2. 在同一 release SHA、完整源码、devDependencies 和生产 `DATABASE_URL` 上执行：

   ```bash
   pnpm db:migrate
   ```

   不得使用 `pnpm db:push`，不得修改已共享 SQL、Drizzle snapshot 或 journal。

3. 只读核对最终目录、AI 配置和壁纸空基线：

   ```sql
   SELECT count(*) AS asset_count FROM match_emote_assets;

   SELECT c.active_version_id,
          v.previous_version_id,
          jsonb_array_length(v.entries) AS item_count,
          count(*) FILTER (WHERE (entry.value->>'enabled')::boolean) AS enabled_count
   FROM match_emote_catalog_config c
   JOIN match_emote_catalog_versions v ON v.id = c.active_version_id
   CROSS JOIN LATERAL jsonb_array_elements(v.entries) entry
   WHERE c.id = 'default'
   GROUP BY c.active_version_id, v.previous_version_id, v.entries;

   SELECT id, revision, enabled, base_url, model_id,
          encrypted_api_key IS NOT NULL AS api_key_configured
   FROM ai_effect_extraction_config;

   SELECT
     (SELECT count(*) FROM player_wallpaper_configs) AS config_count,
     (SELECT count(*) FROM player_wallpaper_assets) AS asset_count,
     (SELECT count(*) FROM player_wallpaper_publication_days) AS publication_day_count,
     (SELECT count(*) FROM player_wallpaper_idempotency) AS idempotency_count,
     (SELECT count(*) FROM player_wallpaper_admin_audit_logs) AS audit_count;
   ```

   从未执行本批迁移且未进行管理员目录编辑的 3.9.6 环境，预期快捷表情资源事实为九项、active 目录九项且九项
   启用；AI 配置为 `default / 1 / false / 空 / 空 / false`；五项玩家壁纸计数均为 0。

4. 确认私有壁纸 bucket 已存在且没有匿名读取策略；从 API 运行网络验证凭据可读写，并在检查后清理测试对象。
5. 部署与 release SHA 一致的 `ghcr.io/catmeow123456/loveca-api:v3.9.7`（或发布记录中的 digest）和
   同一 SHA 的前端静态产物。生产机只执行镜像拉取与 `--no-build` 启动，不重新构建 API。
6. 检查 `/api/health`、首页、`version.json`、PWA manifest 与图片代理。确认 `/api/config` 返回九项启用的
   快捷表情目录，并以管理员身份核对快捷表情目录、AI 配置就绪状态和卡牌管理分页/批量状态接口。
7. 使用测试账号完成一次快捷表情双方发送，确认消息包含目录版本、资源快照和静态/动画资源；完成一次纯色壁纸保存与
   恢复默认。若生产运维前置已全部批准，再使用受控测试图片验证宽屏/紧凑生成、本人鉴权读取、跨账号拒绝、每日额度、
   管理员移除和退役对象清理日志。
8. 完成登录、卡组读取/保存、离线示例卡组开局、普通联机房间、公共牌桌、排位候场/结算和一局基础对战 smoke。
   全部结果正常后再恢复新对局入口与其他写任务。

## 回滚边界

- 种子对象上传失败：数据库尚未变化；修复对象存储配置后可重复执行上传。已成功上传的内容寻址对象可以保留。
- 数据库迁移失败：保持全部写入停止，不部署 3.9.7，不手工补表或修改 Drizzle journal；根据失败位置向前修复，
  或恢复迁移前 PostgreSQL 备份。
- 数据库迁移成功而新应用部署失败：继续保持停机。由于快捷表情协议没有旧 payload fallback，不能只启动 3.9.6
  API 或前端接受新写入；优先修复并部署同一 3.9.7 SHA。
- 若必须整体回退到 3.9.6，停止所有写入，恢复迁移前 PostgreSQL 备份，并同时回滚 API 与前端。已经上传的快捷表情
  内容寻址对象可以暂时保留；确认没有历史目录引用前不得删除。私有壁纸对象必须按备份、数据库引用和保留政策处理，
  不得仅因应用回滚而批量删除。
- AI 主密钥或上游 Key 泄露时，应在部署 Secret 与提供方分别轮换；运行时不保留旧 Key fallback。数据库密文只有在
  原主密钥可用时才能恢复。
- GitHub tag、Release 和不可变 `v3.9.7` / `sha-*` 镜像标签不得覆盖或重写；`latest` 回滚使用提升前复核并记录的
  旧 digest，生产 API 回滚优先使用部署前从实际旧容器捕获的不可变 RepoDigest。
