# 3.10.7 → 3.11.0 部署说明

> 文档类型：专题说明
> 适用范围：从已完成 3.10.7 迁移的环境升级至 3.11.0
> 当前状态：发布材料；不表示生产部署、烟测或 AI 对战开放已经完成

## 数据库、卡库与配置

相对 `v3.10.7`，本版数据库 schema、SQL 迁移、卡牌同步脚本及对象存储约定没有变化，无新增数据库迁移、一次性数据转换、卡库同步或资源导入步骤。AI 决定材料仍使用既有 `ai_battle_evidence_entries` 表；读取修复按数值 ID 排序，无需改造旧归档。若目标环境尚未完成 `0041` 或此前迁移，须先核对[3.10.6 → 3.10.7 说明](3.10.6-to-3.10.7.md)，不能仅凭应用版本推断数据库状态。

新增可选部署变量 `AI_BATTLE_MODEL_REQUEST_TIMEOUT_MS`，同时作用于 API 与本地 Codex 模型请求。未设置或为 `0` 时不设置固定请求截止时间；正整数毫秒值才启用截止时间，停止对局、任务失效和实验总时长仍可取消请求。配置随新模型实例冻结，部署配置调整后应重启 API。原有本机模型调用、用量和实验预算不随发布修改，详见[运行与观测说明](../../docs/ai-battle/runtime-and-observation.md)。

## 前后端协调更新

按[生产部署 Runbook](../../docs/production-release-runbook.md)停止新对局、等待正在进行的对局结束，再成套更新同一发布提交的 API 和前端。本版增加 `ACK_CARD_ENTRANCE` 命令、演出等待投影及可选 checkpoint 演出运行态；不能只更新一侧，也不要在正在演出或处理卡效时强制切换运行时。

前端须发布完整 `client/dist`，包含登记的二十五张卡牌人物资源、眼部图集、字体、动态模块与 Service Worker。素材按对应角色加载，不需要上传 MinIO 或卡牌管理。个人「登场动画」默认开启并记忆在本站浏览器；没有新增平台总开关、数据库字段或管理员配置。模式范围、双方确认、服务器超时及生产烟测步骤见[登场演出部署与验收](../../docs/card-entrance-production-rollout.md)。没有演出运行态的历史存档不补播；保存了等待状态的新存档恢复原实例与截止时间，过期后由服务器继续结算，不需批量转换历史记录。

## 验收与回退

按 Runbook 核对 exact SHA、不可变 `linux/amd64` API 镜像、入口语法与生产依赖运行时导入；部署后验证普通玩家双席播放／跳过／关闭、卡效续行、超时和刷新恢复，以及窄屏、减少动态和角色资源加载。AI 双席调试及只读观战沿用现有管理员权限与隐藏信息边界；如目标环境已获准使用，再进行测试局验收。真实模型策略强度、生产开放和真实双端网络验收不由发布 CI 证明。

回退前停止新对局并让活跃局结束，成套恢复旧 API 与前端；不要将含新演出运行态的活跃 checkpoint 交给旧 API 继续写入。本版没有新增数据库结构回退步骤，保留既有 AI 归档。迁移、生产部署、健康检查与回滚仍按 Runbook 单独执行。
