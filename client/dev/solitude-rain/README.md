# Solitude Rain 可操作预览

对象：`PL!N-bp8-026` 分数 6「Solitude Rain」，`effect_new_card` 工作树。正常对局源码已接入；这个内存牌桌用于反复调画面，尚未部署，也未通过真实账号完成远程联机验收。

在工作树执行 `pnpm --dir client exec vite --config dev/solitude-rain/vite.config.mjs`，地址 `http://127.0.0.1:5194/`。先检查端口空闲；`strictPort` 会在占用时退出，不停止其他服务。服务器使用独立 Vite 缓存、真实 `GameBoard`、`GameSession`、规则命令和玩家投影；没有 API 代理或账号写入。

操作：双方各点一次 **Live Start!** → 把手牌歌曲拖到 LIVE 空位（窄屏也可点手牌再点「里侧放置」）→ 双方依次 **确认完成** → 选分数 6「Solitude Rain」→ 点雫或彼方完成目标选择并转换。选择候选本身就是正式确认命令，无需再点一次。演出结束后，果林的后续效果可选择「不发动」，然后可继续声援/判定。尚未选中本曲或目标时不会播放。

工具栏可重置、切换 0/4/5 初始红蓝心、两张歌曲场景、减少动态或双方视角；第一次真实结算后可重播该次公开结果、0.3 倍慢放、480/830/1160/1650ms 定格（雨幕、收拢、合色、结算反馈），点击「关闭镜头」收回。重播不提交规则命令，不加心或分数。两首歌曲顺序发动后仍按原规则分别选目标；第二首若选相同成员且没有新增红蓝，则转换 0、无加分。

`cards.json` 只包含本次指定导出的 5 张卡，卡文与印刷属性原样保留。测试初始局面用既有 `MEMBER_ORIGINAL_HEART_REPLACEMENT` 为雫和彼方各设定红蓝心及 7 个原有紫心，明确是夹具，不改印刷卡数据/卡效。紫心存在不代表满足本次转换门槛。牌桌图片从工作树既有只读共享图片复制到独立预览目录，对应导出 `imageFilename`，未修改共享图片或初始化子模块。正式演出不读取这些预览文件，也不额外加载成员卡图。

第八版保持 1.9 秒总长与十二条雨道、三十六段错位雨丝。雨全程连续下落，1300–1560ms 继续运动并淡出。80–1380ms 红蓝软边舞台灯向开放侧卡沿收拢，交集一部分露在暗色桌面上，紫色更饱和；两侧红蓝随后稍减弱，约 300ms 内明确呈现合色并衔接 1260ms 标准紫 HEART，1520ms 按权威结果显示标准分数。卡面局部受光上限约 34%，保持人物和文字清楚。顶行目标从下方开放区域受光，中央雨道也跟随该侧。雨丝采样同一光场，在交集内染紫、离开后恢复原色，没有额外光球、光圈或倒影。实现和正常接入见[演出说明](../../src/components/game/song-animation/solitude-rain/README.md)。

本轮仅改变绘制，验收重点是真实卡牌放置、选彼方完成转换后的 1 倍速合色、雨丝受光及后续恢复，并核对双方视角、390px 窄屏、客户端类型和帧间隔。当前证据保存于 `output/playwright/solitude-rain/`，使用 `v8-` 前缀；旧版截图与 `draft` 文件仅作历史或调试证据。工具栏「测试选项」可查看最近一次普通 1 倍速重播的 RAF 间隔和 Canvas 绘制耗时；慢放、定格、减少动态和正式对局不采样。采样不含 React 提交与最终合成耗时，也不能保证所有设备性能。

既有演出/加载 18 项测试覆盖 0/4/5、原有紫心、其他成员、后续新增红蓝、原贡献失效、顺序发动、公开投影及 ACK/超时恢复；更早接入回归还覆盖本卡规则、固定贡献快照、仆光与共用反馈。第六版通过正常客户端构建、双方视角、窄屏和减少动态检查，第七版通过连续雨流的实际操作与类型检查。这些是此前验证，未写成本轮全部重新执行。
