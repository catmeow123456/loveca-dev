# 11费妮可 · 名侦探的线索收藏

`PL!-bp8-009` 费用11「矢泽日香（矢泽妮可）」的起动专属反馈已接入共享 `GameBoard`，同基础编号全罕度启用。不新增登场动画，不改变起动、常时或授予能力的规则。

## 视觉与素材

视觉取自 `PL!-bp8-009-SEC` 的侦探服、放大镜、红色双马尾蝴蝶结与偶像手势。动画把叠入的成员作为“线索”归档，是卡面联想，不声称角色有侦探背景设定。人物的偶像定位参考[官方 SIFAC 成员介绍](https://www.jp.square-enix.com/lovelive-sifacns/member.html)。

- 0–288ms：本次成功叠入的公开成员卡装入奶油色线索夹，飞到妮可附近。对方视角从匿名手牌区域起飞；线索夹不附加英文标签。
- 180–876ms：有金属边、玻璃折射和卡面局部放大的镜片扫过卡牌右上费用区；新增费用种类带一笔桃色侦查圈。
- 756–1104ms：线索夹折起、收拢至妮可下方；948–1392ms 用红色蝴蝶结收尾，不显示收录文字或提示底框。没有永久标记，也不额外重复加费、HEART 或 BLADE 提示。
- 减少动态：只在来源卡附近短暂显示蝴蝶结，840ms 收尾。无声音、全屏遮罩、操作屏蔽或双方等待。整体时间线按初版的1.2倍统一延长，各段相对节奏不变。

夹子、放大镜与蝴蝶结由 Canvas 绘制，无需下载专用运行素材。成员卡只使用本次结算后公开的卡号，交给原有 `getCardImagePath`；图片慢加载／失败时以线索夹和公开姓名替代，不等待图片、不在稍后补播。SEC 原图仅存于 `client/dev/nico/images/` 用于夹具牌桌，没有裁切、去字或人物重绘。

## 权威与边界

规则数据使用 `references/cards_export_2026-10-31.json` 对应的既有实现。projector 从 `countDistinctMemberEffectiveCostsBelowSourceMember` 派生舞台来源的公开 `nicoEvidence.costKinds` 与舞台生命周期，不新增持久规则字段。前端不按印刷费用或下方张数重新算奖励。

`getNicoEvidencePresentation` 只认前一投影处于妮可私密选手牌步骤、同一个舞台来源仍存在、下一投影实际新增一张公开下方卡。候选手牌不进入演出；不放置、空手、无效选择、借用妮可起动的其他成员均保持普通反馈。重复费用仍展示收录，但没有新增种类的强调；数值始终由原有权威修正反馈展示。

使用既有特效开关与模式范围（本地调试、远端调试、对墙打、联机；观战／历史回放不播放）。初次挂载、切换视角、回退序号和 presentation epoch 重置不补播；来源离场、下方卡移除或来源重登会撤掉旧演出。没有修改 workflow、费用步骤、确认、ACK 或定时结算。

## 可操作验证

在仓库根目录运行 `pnpm exec vite --config client/dev/nico/vite.config.mjs`，使用独立 `http://127.0.0.1:5194/`，不连接账号或后端。

点击舞台妮可，再点击起动按钮，选择手牌成员。绘里与凛同为2费，真姬9费、希7费；每回合两次，重置可重复。工具栏提供慢放、定格、已有2费线索、R+（仅夹具借用SEC卡图）、从手牌拖妮可登场和减少动态。镜头预览共用正式绘制组件，但不修改对局。

相关测试：`tests/integration/pl-bp8-009-nico.test.ts` 覆盖全罕度、双方私密选择／公开结果、费用种类、跳过／空手、来源清理及借用能力；同场回归 `ai-animation-projection.test.ts`、`ll-bp8-001-nico-ai-seras.test.ts`。浏览器实际选择已验证普通／重复费用与减少动态，窄屏使用390px。真实双客户端联机及生产部署未在本次验收。
