# 9 费桂城泉：月下邀演

`PL!HS-bp8-008` 费用9「桂城泉」全罕度起动返场首版。以白色花瓣与邀演动作作为视觉线索；「月下邀演」是试作名，当前视觉按用户反馈采用自然的柔白流光。运行时只有代码绘制的光影和实际公开卡面，没有新增人物重绘、音效或下载纹理。常时待机保护已接入卡角白花护符，见[白花守护](../../izumi-protection/README.md)。

## 动作与衔接

来源泉轻抬，柔白流光从泉扫向被选中的成员；成员微微俯身，退向自己真实休息室的位置，再返回。沿用原来多层渐变、柔边与少量白色花瓣的流动方式；不绘制银月、中央月牙或定向聚光，避免产生外部光源牵拉卡牌的观感。普通目标约1秒回到原槽并转正；目标已有登场人物素材时，回流指向桌面中央，第820ms开始原人物演出，柔光到第1000ms收尾，重叠180ms。人物展示与完整卡牌落场的2.74秒不变，总长约3.56秒。13费与15费赛拉丝仍使用各自登记的素材。

离场卡面使用未旋转的布局宽高，旋转只决定姿态，避免横置转正过渡的外接框被误当作卡面尺寸。手机横置时复用舞台的列宽约束；出发保持原尺寸并渐缩，普通返场回到转正后的实际尺寸，不在俯身时额外放大。

9费泉自身没有登记独立人物登场。其他卡的普通登场、赛拉丝检视与锁链保持原有流程。减少动态时普通返场只保留160ms局部柔光，不移动卡牌；有既存人物素材的目标走共用短展示。

## 权威边界

单卡 workflow 完成弃牌费用、离场及同一实体原槽返场后，才调用 `captureIzumiReplay`。离场／返场仍是一个不可拆的动作，不改变次数、费用、方向、生命周期与诱发事件；结束原起动后，在处理其产生的新 pending 前复用 `entranceRuntime`。没有目标、非法选择或返场未成功时不创建演出。

公开投影 `match.entrance.izumiReplay` 只含来源与目标公开对象、归属席位、原槽和原方向。前端从当前公开顶层舞台成员取得图面与几何，不自行判断目标资格，不读取牌库或私密卡。成功窗口的 `seenSequence` 避免紧接着再捕获一次普通登场；后续登场能力在双方ACK或原超时机制后只继续一次。

复用特效开关、模式范围、双方等待／本地单操作者确认、跳过、遮挡及恢复语义。目标声明专属移动所有权，泉仅在轻抬期间遮挡；完成、跳过、取消、布局改变、目标失效和加载失败均释放。新增前奏给原权威预算加1秒，不新增服务器计时器。泉在公开舞台时预热公开小卡面；播放前图片解码与原人物素材共用最多2秒等待，迟到结果不重播。关闭演出不跳过任何规则选择。

## 可操作预览与验收

仓库根运行 `node client/node_modules/vite/bin/vite.js --config client/dev/seras/vite.config.mjs`，打开 `http://127.0.0.1:5193/?izumi`。点击左侧9费泉 → 发动起动 → 弃1张手牌 → 选择中间13费赛拉丝；返场演出后进入实际检视。点“泉返场测试”重新准备牌局，可反复操作。“测试选项 → 泉 · 普通返场”或 `?izumi&plain` 以另一张泉验证无人物素材的原槽返场。预览是共用GameBoard与内存GameSession，正常命令及投影触发；仅初始牌局与图片入口固定，不调用账号或后台API。R分流测试沿用SEC公开图，不声称使用了R卡图。

源码已接入共用正常对局路径，当前柔白流光版本已获用户确认，尚未部署。预览端口无需重启其他环境；实际后端要加载新workflow后才具备此公开窗口。
