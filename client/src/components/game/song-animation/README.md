# 「我们是合而为一的光芒」LIVE 成功演出

> 文档类型：专题说明
> 当前状态：已接入共用 GameBoard 的可操作对局；观战与历史回放不播放

对象为 `PL!-pb2-039-L`，分数 9「我们是合而为一的光芒」。仅在轮到本曲 LIVE 成功效果处理时播放，胜者阶段不播放莲花。可操作的本地牌桌与运行方式见 [预览入口](../../../../dev/bokuhika/README.md)。

## 视觉与组件契约

演出约 3.2 秒：九位成员采用 BP5 P 罕度的仆光服装肖像，依规则评估名单显色，两层各九片曲面花瓣错峰展开，歌曲卡从花心显露；计入加分的成员各自沿弧线向花心送出明亮光团，最后整体淡出。未计入者保持暗灰，不发出光团。歌曲卡保持完整横版、正面视角，比初版放大 20%。不显示下方歌名或说明文字，不新增音效。

`BokuhikaScene` 接收公开卡面地址、成员身份与加分结果、毫秒时间，绘制确定性帧；外部负责播放、暂停、重播、跳过及触发资格。组件不读取规则状态、不提交命令、不计算分数。`onReady` 在资源准备好或降级后触发，卸载释放回调、监听和 WebGL 资源。花瓣为 WebGL 参数曲面，具有深度遮挡、法线光照和细脉；肖像与 Canvas 弧形光迹构成外围九人图例。减少动态或 WebGL 不可用时，显示静态卡面及最终成员亮暗状态。

`bokuhikaContributionFromNames` 将规则评估的标准名称映射到肖像；遇到未知身份、重复身份、名单与分数不一致时返回空，不补亮或重算。`bokuhikaSuccessCueKey` 识别本曲已选中的成功效果确认步骤；顺序发动无确认面板时仍以权威演出信息为准，待选顺序和其他卡效果不触发。双人成员身份分配、同名去重与声援范围由现有规则负责。

## 接入与结算顺序

规则端单卡 workflow 在本曲进入 `CONFIRM_ONLY_EFFECT` 时生成 `EntranceWait.bokuhikaSuccess`，仅携带公开来源卡、统一身份名单与预期加分；projector 将其投影为公开对象 ID。客户端 `getBokuhikaPresentation` 验证当前确认步骤及公开卡面，`CardEntranceLayer` 播放 `BokuhikaPlayback`。无需读取权威快照、手牌或卡组，也不从场上头像自行计算分数。卡号按基础编号覆盖各罕度。

顺序为「选中本曲成功效果 → 莲花 → 原有继续处理确认 → 原规则加分」。待选效果队列不播放；显式选择其他效果时不播放；演出和跳过都不确认卡效。「顺序发动」仍自动结算：每个仆光效果应用后播放对应莲花，再继续原批次，不额外插入手动确认；使用既有 `resumePendingEffects` 在 ACK 或超时后继续一次。

复用既有登场特效开关、模式范围、ACK、超时与交互锁。对墙打/本地单视角完成即可释放等待，联机等待双方；加载最多 2 秒、正常播放 3.2 秒、权威等待最多 6 秒。关闭特效或不支持身份时直接确认演出结束，保留规则确认；减少动态显示 550ms 静态卡面及成员亮暗状态。重复快照不重播，完成或超时后的窗口不会因恢复而补播；尚未完成的窗口只在原有截止时间内等待。观战和回放保持既有只读展示。

歌曲横图与九人肖像位于 `assets/`，由客户端静态导入，正式构建与独立预览使用同一份素材。验收覆盖 `tests/integration/bokuhika-presentation.test.ts`（包含服务端 SOLITAIRE 命令链路）、`tests/unit/bokuhika-score-presentation.test.ts` 及既有仆光规则测试。
