## 声援点亮

`getCheerCardBladeHeartResolution` 在既有有效判心计算中同时返回实际授予的 abilityId，继续按有效费用、无任何 BLADE HEART、最后有效授予及后续改色处理。projector 只为当前公开声援对象输出 `cheerBladeHeartGrantAbilityIds`，不输出私密来源卡身份。DRAW、SCORE、原生橙判心及其他能力授予均不会误播；本技能授予后有效色已非橙色时只播放普通跳心。

`JudgmentPanel → useCheerRevealMotion → playCheerMotion` 使用同一帧时钟、翻牌批次与标准心图标。符合条件的来源卡先由清晰的橙金边框和暖光包裹，四道细光从卡缘汇向中央，标准橙心从光芯中凝成，再带短尾沿既有曲线路径飞入对应判心统计。心图标在卡面中部生成，成形尺寸32–42px；边框在飞行期间渐隐，最多580ms。默认0.5倍速度下，从原有640ms窗口中分配约220ms用于凝心，余下约420ms用于飞行；最终抵达、统计更新和整批时长保持原样，不增加逐卡等待。凝心期间跟随来源卡的真实滚动位置，出发后固定轨迹起点。普通跳心不改变节奏；减少动态时只保留260ms短暂橙边和图标摘要淡入，直接呈现正确统计。

## 成功结算与播放边界

共享 `live-success-cheer-condition-source-score` workflow 保持原实现，仍按有效橙判心的卡片张数判定，原生橙心与历史声援按既有规则计入。满足条件后由原确认实际加分，并通过普通分数反馈显示；不创建本曲专属等待、额外ACK或全屏演出。手动和顺序发动直接按原流程继续，多个来源各自只加分一次。

点亮的纯绘制位于 `snowHalationIgnition.ts`，复用现有声援播放器的可见性、模式、开关、减少动态、滚动及卸载清理；关闭动画时直接显示正确统计，恢复历史声援不补播。观战和回放沿用现有只读范围。前端只消费实际授予来源与最终有效色，不重新判断费用或加分资格。
