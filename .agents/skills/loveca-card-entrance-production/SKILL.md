# Loveca 卡牌登场动效制作

把指定卡牌制作成可在真实对局中验证的专属演出。复用已确认的空间关系与播放机制，让人物素材和动作因卡而异。用户当前明确要求优先于本 skill 的默认设计；不要把彼方的参数或素材方案当成所有卡牌的强制模板。

## 按需读取

- 动画设计与规则反馈边界：[motion-system-design](../motion-system-design/SKILL.md)。本任务是已获用户授权的专属演出，不套用普通移牌的短时长上限。
- 设计、制作或调优人物动作时：[人物动作质量与验收](references/portrait-quality.md)。包含动作选择、眼部表情、形变边界、已验证案例及新窗口任务提示；只改落场或开关时无需加载。
- 调整对战开关或操作入口时：[battle-interaction-design](../battle-interaction-design/SKILL.md)。沿用现有 UI；明显改版才加载 [frontend-design](../frontend-design/SKILL.md)。
- 浏览器验收：[animation-verification](../animation-verification/SKILL.md)。
- 用户要求提交或起草提交说明时，使用 [prepare-for-git-commit](../prepare-for-git-commit/SKILL.md)。动画新增与调优沿用 `feat(animation): 中文摘要`，缺陷修复用 `fix(animation)`，仅共用结构重构用 `refactor(animation)`；不要另起“新增费用…本地演出”这种无前缀标题。正文核对基础编号、费用／分数、卡名、素材来源、复用边界、启用范围与实际验证，不机械堆满所有栏目。
- 新增卡牌、查找已接入样本的共用边界或判断是否需要扩展绘制能力时：[实现入口与复用检查](references/implementation-map.md)。
- 需要生成或编辑位图素材时，使用当前环境可用的 `imagegen` skill 与图像工具；CSS、网格形变和参数调整不需要生成图片。

## 卡牌与素材

先核对用户指定卡牌的基础编号、卡名、费用／分数和罕度。规则事实使用用户指定导出或已授权的本地数据；官方公开卡面可作为视觉参考。素材卡号与触发卡号可以不同，但必须记录对应关系，不能把借用的插画印刷绑定成触发对象。纯动画任务不顺带修改卡效规则或登记。

优先使用用户提供或官方公开的清晰卡面。文字较少的其他罕度或关联印刷可作候选，先确认人物、服饰与取景适合。没有无字原图时，明确是基于卡面的重绘，不称为官方原画或无损提取。

默认保留原卡实际展示的角色范围：不要裁成头肩，不为追求“全身”补出原图没有的腿脚。去除卡框、文字、图标与背景时，重点检查脸、手、发束、服饰和透明边缘；重建被文字遮挡的部分应尽量局部，记录明显差异。用户明确要求改变构图时按新要求处理。

编辑前先查看原图，生成后再查看结果，不靠文件名判断素材合格。遵守图像工具的引用图片方式；遇到拒绝，说明已知原因或不确定性，不能假称成功或通过换工具绕过拒绝。

素材可生成、备用姿态获准尝试、最终观感认可是不同状态。采用备选方案时记录与原卡的姿态差异，不能把允许尝试视为素材已通过；原姿态未恢复时明确保留这个限制。

未采用素材和独立试作留在用户指定的仓库外原型目录；本工作区已有同级 `animation-prototypes/` 可复用。先检查目录是否存在，不覆盖旧版本。只把实际运行依赖的素材放入源码，原型目录不成为运行时依赖。素材来源、局限写入对应功能说明，不另外复制一份流水账。

## 已确认的默认视觉语言

人物动作优先保留原卡姿态与人物特征、身体和接触关系以及运动自然度，再追求动作幅度与装饰效果。“正常速度下可感知”不等于每张必须有大幅或独立的肢体动作；小而连贯的动作可以成立，明显但机械的动作应返工。也不要反过来把所有新卡统一限制为微动。

先根据构图确定动作意图、带动关系和必须保持的接触，再选择单层微动或必要分层。不支持的转身、前伸或遮挡变化应调整动作设计，不能靠加大平面旋转硬凑。具体制作与自查按人物质量参考执行，不预设每张都拆出一只手臂。

- **视角是俯视平放桌面。** 卡牌离开桌面是朝向镜头的深度变化，不能把屏幕上移、再下移当作震起与落地。
- 人物演出以卡面角色和卡名为主，默认居中、卡名在下方；不加费用或自行编写的登场台词。发束、衣料等微动围绕素材设计，网格形变不能夸称真实角色动作。不要未经需求重启头肩裁切或补腿路线。
- 人物演出后，完整卡牌从画面中央飞向目标舞台，再沿深度方向压回桌面。飞行路径应可辨认；到达目标后的压落保持短促。飞向槽位的屏幕位移与触地的深度变化是两段不同动作。
- 冲击圈以落点为中心沿桌面向四周平面扩散，颜色可随角色调整。默认简洁，不做卡底“脚环”、明显倾斜的立体圆环或自动堆叠复杂纹章。
- 周围卡牌通过轻微放大、边缘倾斜和阴影变化表现被震起，再恢复原状；不要添加明显向上的屏幕位移。原横置方向应保留，落场来源自身不做邻卡反弹。
- 场地微震要短促、衰减，手牌与操作栏保持稳定。接触阴影不能盖暗真实卡面；光圈、碎光不应淹没主动作。

人物展示、淡出、飞行、压落和冲击在共用时间线内分别调节，不在组件和 CSS 中另写阶段时长。人物段可以紧凑，移动段应给玩家看清路径；不要为了缩短总时长把飞行做成瞬移。存在重叠时按时间线计算总时长，不能简单相加。调优时说清改了哪段、是否改变总时长，并同步清理计时器；用户只要求调一段时不要顺带改变已确认的其他部分。

## 游戏接入与复用

先读真实实现，再决定扩展位置。现有卡牌共用完整登记、人物绘制、播放及落场流程；素材动态导入绑定在登记内，加载与统一时间线入口见实现参考。新增卡牌时先扩展现有配置，只有实际结构差异才提炼新的绘制能力；角色资产、网格参数与色彩留在卡牌配置或专属表现层，不复制一整套控制器，也不预先搭建大而全的动画引擎。

- 触发依据是权威状态产生的成员登场事件和公开演出投影，不是拖拽开始、点卡或 React 猜测。按基础编号覆盖应支持的罕度；移动位置、横置、失败操作和重连历史不能误触发，合法离场后重新登场可以重播。
- 从玩家投影与已渲染公开对象取得目标、方向和尺寸；不得读取隐藏身份补齐动画。结束必须准确回到实际槽位及方向。
- 复用现有「登场动画」开关、队列与移动遮挡所有权，避免专属飞牌和通用移牌同时显示。当前联机、对墙打和 DEBUG 开放且默认开启，本机站点记忆开关；教程、AI 调试、观战和回放不播放。新增卡牌不自行扩大模式范围。
- 正式联机采用权威演出等待：合法登场与费用完成后，在安全的原子步骤边界暂停后续卡效；双方完成／跳过后才继续。关闭的一方立即确认本方结束，仍须等待另一方。不要仅隐藏弹窗，让自动卡效或对手操作提前发生；不拆费用或工作流原子步骤。复用共享 ACK、截止时间、排位计时和公共展示恢复语义，不给每张卡增加服务器暂停逻辑。技术失败、窗口变化、重置或终局时释放遮挡与回调；权威超时必须能独立于客户端继续。已结束的历史不能补播，撤销重做的旧确认不能释放新演出。
- 保留减少动态行为；只缩短主时间轴而漏掉落场、震动或邻卡动作，不算支持减少动态。

## 制作与交付

按用户本次目标推进素材、人物演出、真实对局接入，不固定要求每阶段重新审批。用户要求先看原型时先交原型；已授权直接接入时完成接入与必要验证。现有临时布局／预览栏已移除，不为新卡擅自恢复到玩家界面；若需独立调试工具，优先放仓库外原型目录。

验收按 animation-verification 执行，尤其检查：飞入与压落能区分、俯视空间一致、最终槽位与横置方向准确、邻卡与阴影完全恢复、开关中断后真实卡牌可见、历史事件不补播。根据改动覆盖双方公开视角、正常／失效来源、桌面／窄屏与减少动态；不支持的浏览器验证能力要明确说明。不要为了验收重置或推进用户正在使用的复杂对局。

人物观感与工程行为分别验收。人物先在实际尺寸、正常速度、无装饰光效下对照当前已认可样本，检查形状、接触、协调和收势，再检查真实桌面；测试通过、视频能播放或动作存在都不能代替自然度判断。多张制作优先完成一个代表样本的自查再扩展，不增加每一步都要用户批准的流程。

只运行受影响的 focused tests、类型检查与必要构建；纯美术调优以实际浏览器证据为主。交付说明素材来源与重绘局限、时间线、实测范围、启用边界及提交状态。更新对应功能说明；提交、推送与发布遵循用户授权，不因使用 skill 自动执行。
