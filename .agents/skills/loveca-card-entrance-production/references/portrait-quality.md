# 人物动作质量与验收

用于人物素材、动作设计与调优；播放机制和入口见 [implementation-map](implementation-map.md)。质量目标是让原卡姿态有可信的生命感，不以关节数量、转动角度或位移大小作为完成指标。用户明确指定的动作仍应实现；素材无法支持时说明限制，不能悄悄降级或强行扭曲。

## 动作先于分层

看过卡面后，用几句话说明动作意图、带动部位、需要稳定的区域和接触点。例如持麦角色可以轻靠近麦克风，托腮角色可以头手协调轻倾，拥抱角色可以保留搭手轻靠。动作应来自当前姿态，不为了覆盖“主动作＋跟随动作”清单而增加摆腰、抬手、扭头或回弹。

按素材支持程度选择实现：单层适合有限的整体协调与局部衣发微动；手臂确有独立运动需要时才分层，并补好遮挡和连接。多层也不等于完整骨骼或三维动作。向镜头前伸、明显转身等涉及透视与遮挡变化，不能仅用画面内旋转冒充；若当前素材不足，选取忠于原姿态、可成立的动作，或说明额外素材需求。

幅度与速度一起判断。同样角度，运动集中在很短的中段也会显得突然；先检查起止姿态、速度分布和身体协调，再决定是否缩小或扩大幅度。允许从接近最终姿态的位置开始，不要求先把手或身体大幅拉开再返回。

部位先后应符合动作意图。需要身体带动手臂时可让身体稍早起势，衣发随后收住；托腮的手与头、握持的手与道具应保持关联。不要把“身体提前固定毫秒数”或某一种缓动曲线变成所有角色的新模板。一次动作后可以停驻，不默认追加反向摆动和回弹。

## 形状与接触边界

- 脸部五官、完整手指和硬质道具保持比例与轮廓；允许整体移动或转动。麦克风、杖等必须检查整件物体，不能只看握持点。
- 袖口、腰部等软连接只覆盖适合过渡的区域。发梢、衣料遮罩不能扫到颈部、项链、脸、道具或同图中的其他人物；按实际像素位置核对，不因字段叫 hair 就假定它只作用于头发。
- 长道具的不同顶点不能继承不同身体权重而弯折。关节刚性跟随与袖口软连接分别处理；袖口的固定范围不得侵入手和道具。
- 托腮、握持、拥抱、搭手等关系在起始、中间和收势都要成立。接触处滑开、穿入或留下缝隙时，先修支点、对齐和联动，不能靠光效遮住。
- 头肩需要协调，但不强制加独立颈部运动。可用上身整体轻倾带动头肩；素材不支持时，不添加反向拧头来制造动作差异。

## 已验证案例怎样复用

以[当前登场说明](../../../../client/src/components/game/card-entrance/README.md)中的认可状态和[实际 profile](../../../../client/src/lib/cardEntranceProfiles.ts)为准，不照抄旧录屏或历史废案的参数。以下用于选择方法，不作为角度或时长模板：

| 案例 | 可复用的判断 |
| --- | --- |
| 彼方、恋 | 克制的局部微动可以形成完整演出，不因缺少大手势判定失败 |
| 花帆 | 同图包含后景人物，需检查所有头颈；扩大分层能力不能弥补错误的形变区域 |
| 岚珠、穗乃果 | 手与麦克风／杖保持整体；软连接范围和身体权重都可能破坏道具形状 |
| 凛与花阳 | 围绕接触关系设计双方动作，独立平移或不同幅度不一定更自然 |
| 赛拉丝 | 托腮动作需要保持头手关系；备用素材姿态与原卡不同是另一项限制，不能靠动作调参消除 |

遇到异常时按“姿态与对齐 → 支点和形变区域 → 部位时序 → 幅度 → 装饰效果”定位原因；这是排查顺序，不要求所有卡都走同样的动作方案。

## 人物观感验收

先把原卡与起始、关键中间、结束姿态对照，检查轮廓、手指、接缝和接触关系。关键帧用于找形变问题，不能单独证明正常播放自然。

再以实际展示尺寸、正常 1× 速度、弱化或关闭装饰光效的方式连续播放，和一个适合该构图、当前已认可的样本比较。观察整体动作是否连贯、是否局部突然加速、头肩与手臂是否像同一身体、衣发是否合理收势。分层和姿态不同的卡不要求达到同一位移幅度；不以放大、慢放或仅有差异像素作为动作合格证据。

可感知与自然度必须分别通过。没有明显形变不代表人物动作已成立；若需要盯着几个像素才能辨认变化，应继续调整动作关系与时序。可在相同尺寸、同一淡入淡出下并排展示动作版和冻结人物内部动作的静态版，避免把整体入场、光效或落场误算成人物动作。检查主要变化是否在人物清晰可见时发生，不能仅比较淡入前和结束后的姿态。

瑠璃乃与曜的已认可版本在保持头手接触、道具轮廓的同时，让手臂相对身体稍后收势。其可复用经验是协调不等于所有部位锁成一块；不能只把整体旋转放大，也不要求后续每张都复制同一手势。预览关键帧必须确认画布已绘制到目标时刻，点击后的按钮状态或文字先更新不代表画布也已更新。

纸片式孤立摆臂、反向拧头、颈部波纹、硬道具压扁／弯折、接触滑开、无意的抽动和反弹属于返工项。若看不出自然度是否改善，保留可对比的正常速度版本并如实说明，不能用“无报错”“已录屏”或测试数量代替判断。用户观感反馈优先于已有自查结论。

最后用真实桌面检查构图、卡名、落场、取消和终态。沿用已有 animation-verification，不在此复制工程用例清单；工程行为与人物观感分别报告。预览应导入真实运行时与配置，录屏标明对应版本；调参后更新展示入口，保留旧文件供对照。只有实际查看且可播放的预览才可报告已验证。

多张新卡先完成一个代表样本的上述自查，再扩展其余卡。这个顺序不新增用户审批点；已有授权内继续制作，批量交付时仍逐张判断。

## 新窗口任务提示

工作区、权威卡牌数据、目标卡及参考图由当次任务提供，提交范围也按当次授权。不要在提示词里复制固定 HEAD、历史参数或全套共用机制；指向当前 skill、登场说明及真实代码。人物要求可使用下面这段，再附本批特殊需求：

> 本批以自然、忠于原卡的角色演出为目标。希望正常速度下能感受到人物在行动，但不要求每张都有大幅或独立的肢体动作。自然度、人物形状和接触关系优先，不能为证明“有动作”强加摆腰、扭头、抬手或回弹。先根据原卡确定动作意图，再选择微动、必要分层或其他合适实现；小而连贯可以通过，明显但机械需要返工。阅读 loveca-card-entrance-production 及其人物质量参考，对照当前已认可样本完成正常速度、实际尺寸、无光效自查，再扩展同批其他卡。分别报告人物观感与工程验证，不用测试数量证明自然度。
