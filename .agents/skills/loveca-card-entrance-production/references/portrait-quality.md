# 人物动作质量与验收

用于人物素材、动作设计与调优；播放机制和入口见 [implementation-map](implementation-map.md)。目标是让原卡姿态有可信的生命感。设计需要逐卡判断，不能以完成动作清单、增加关节或达到位移阈值代替观感。

## 先判断这张卡适合什么

看过卡面后，用几句话说明想让人看见什么动作、哪些部位需要配合、哪些接触与遮挡需要保持。它是本卡的设计假设，不是必须凑齐的“主动作＋跟随动作”栏目。睡姿、托腮、持物、多人重叠等构图各有空间，不预设独立抬手、身体先动或三人一起动。

再判断素材是否支持：单层适合有限的整体协调与局部微动；独立肢体、多人或遮挡变化确有需要时才拆层、补底图或使用关节约束。现有二维形变不等于完整骨骼或三维动画，不能靠放大平面旋转实现明显转身、向镜头伸手。需要新姿态素材时说明代价；不支持原动作时提出可成立的替代，不悄悄降级。

幅度、速度和部位配合一起判断。小而连贯的动作可以成立，更明显的动作也可以成立；先观察起止姿态、运动集中在哪一段及接触是否可信，不把问题简化为调大或调小一个角度。可一次收势后停驻，不默认追加反向摆动。固定延迟、统一缓动和全员同步都不是自然度保证。

返工先定位姿态、连接、遮挡或时序的问题，保留仍成立的部分。手臂像转轴、身体被拉长，并不一定能靠改缓动或减幅解决；也不要把冻结身体、只留眨眼自动视为修复完成。若改选动作，说明实际做成了什么。重复调同一方案仍不自然时，重新判断动作与素材是否匹配。

## 形状与接触边界

- 脸、完整手指和硬质道具保持比例与轮廓。检查整件道具及所有握持手；长道具的不同部位不能因身体权重不同而弯折。
- 遮罩选择的是像素，不是语义上的肢体。核对区域与软边界穿过的所有内容，包括后景人物、头颈、其他手臂、腿鞋。重叠处需要不同运动时，拆层补底或改选动作，不能仅调整同一遮罩的幅度。
- 袖口、腰部等软连接放在合适衣料内；肩肘腕的位置应对应实际连接，手和道具保持整体。托腮、握持、拥抱、搭手在起始、中间及收势时都应成立；不能靠光效遮住滑开、穿入或缺口。

## 眼部表情与眨眼

按原表情决定是否眨眼，闭眼笑、单眼闭合、眯眼或被头发遮住时优先保留；组合卡逐人判断。眨眼是表情选择，不是每张卡的必填动作，也不代替身体演出的判断。

优先从当前已认可的人物素材生成局部半闭眼／闭眼图集，保留原脸倾角、远近眼差异、眼角、肤色和刘海遮挡。闭合应由眼皮遮住眼珠，不压扁原眼睛，也不默认改成笑眼。每格要留足连续肤色覆盖原眼睛，睫毛和羽化边缘不能碰到裁切线；闭眼出现旧眼珠、双重睫毛、额外眼褶或刘海跳变时，先修图集与取样对齐。强倾斜脸不要被生成工具擅自摆正。

现有绘制使用原睁眼、半闭眼、闭眼三种姿态切换；跨姿态透明混合会留下眼珠重影，不用它掩盖对齐问题。复用人物时钟，在清晰展示阶段完成一次闭合与恢复；时机、停驻和睁开节奏按角色选择，不延长整段演出。减少动态保留原表情。多人窗口与图集坐标约定见[实现入口](implementation-map.md)。

检查半闭、闭合、恢复时的眼角与边缘，以及正常速度下的节奏。组合卡逐人核对眼皮跟随，不能跟错图层；具体坐标与加载约束见实现参考。

## 已验证案例怎样复用

以[当前登场说明](../../../../client/src/components/game/card-entrance/README.md)中的认可状态和[实际 profile](../../../../client/src/lib/cardEntranceProfiles.ts)为准，不照抄旧录屏或历史废案的参数。以下用于选择方法，不作为角度或时长模板：

| 案例 | 可复用的判断 |
| --- | --- |
| 彼方、恋 | 克制的局部微动可以形成完整演出，不因缺少大手势判定失败 |
| 岚珠、穗乃果 | 手与麦克风／杖保持整体；软连接范围和身体权重都可能破坏道具形状 |
| 凛与花阳 | 围绕接触关系设计双方动作，独立平移或不同幅度不一定更自然 |
| 瑠璃乃、曜 | 头手接触与道具轮廓保持，手臂可相对身体稍后收势；协调不等于全部锁成一块 |

选构图和接触关系相近的样本，借用它处理关系的方法，不照搬角度、延迟或整套动作。具体卡的调参过程、废案及本轮认可记录放仓库外原型；不因每次返工就扩充这张表。

## 人物观感验收

先看实际展示尺寸、正常 1× 速度的整段播放，弱化或关闭装饰光效。判断设计的动作是否在清晰展示阶段可见、身体是否连贯、接触是否可信、收势是否自然；不同构图不比较绝对位移大小。必要时并排显示同尺寸、同淡入淡出的冻结人物版，排除整体入场和光效造成的错觉。静止睡姿等设计可克制，但不能把未实现的动作描述成已完成。

再用原卡与起始、中间、结束姿态检查轮廓、手指、接缝和遮挡。定格、慢放和像素差异用于诊断，不单独证明自然。确认画布实际绘制到目标时刻，不能只看控制按钮已更新。若仍像机械摆杆、拉伸或抽动，回到动作与素材的关系；看不出改善时如实说明，保留正常速度对照。用户观感反馈优先于自查结论。

批量先做一个有代表性的可播放样本校准方向，再逐卡判断；不把样本动作铺到整批。按用户已有授权推进，不增加逐步审批。预览导入真实运行时与配置，调参后更新入口，旧版本留在仓库外供对照。

最后按 animation-verification 检查真实桌面；人物观感与工程行为分别报告。逐卡做局部视觉检查，统一回归、类型检查和构建可集中到提交前；修改共享机制或发现新风险时提前补相应检查，不因换一张素材重复整套验收。
