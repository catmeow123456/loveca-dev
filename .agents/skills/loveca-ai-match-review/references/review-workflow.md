# 多局复盘与迭代工作流

按需使用：多局笔记、导出带终局附件、双 AI 试打后复盘、或用户已授权的改进实验。普通单局分析沿用 SKILL.md 的概览→阶段→关键决定路径。

## 1. 确定本局与材料

先确定 matchId、双方构筑／手册、先后手及用户要分析哪一席。优先读取指定日志和同局附件，不将不同局的终局、手册或账本拼在一起。材料以文件哈希和局号关联；不要把完整大日志复制到 Markdown 或技能中。

| 材料 | 回答的问题 |
| --- | --- |
| JSON／JSONL、EXPORT 清单 | 哪些决定与原始输入被保留，采集是否缺失或截断 |
| 同局权威最终投影、历史记录；CLI `result.json` | 是否自然结束、胜者、停止原因、成功 LIVE 与终轮分数 |
| 日志中的 SOURCES、REQUEST assembly | 当时实际冻结的规则、卡文、手册和模型配置 |
| 计费／运行状态 | 实际请求、缓存、未报告用量及预算停止，不能证明胜负 |

**游戏结果与证据完整性分别记载。** 最后决策可能早于获胜结算，日志 END 也只表示采集结束。若最后 SAMPLE 没有终局而同局权威附件明确终局，可以报告胜者，同时保留清单 `completeThroughEnd=false` 和公开事件缺口。没有权威结果时写“中断／终局未知”，不按当前比分推定胜者。`captureFailures` 也可能包含工具对不完整清单的计数，先核对原始清单和 CAPTURE_FAILURE 事件再归因。

框架记录、观战快照与历史回放的具体入口见[运行与观察](../../../../docs/ai-battle/runtime-and-observation.md)；只在确实缺材料时按已授权的本地入口导出。离线复盘不会因缺材料自动建局或付费重跑。

## 2. 用少量下钻完成归因

先用概览建立整局路线，再用 `--phases` 追踪各阶段入口→出口，最后针对转折决定查 `--brief`。冻结卡文／手册按 `--sources`、`--material`、`--card` 查询。多局独立概览可并行，关键决定按证据依赖继续查；不要先输出整局巨大 JSON，再为每个结论写临时提取脚本。

出现“说明保留但实际盖掉”“不合唱却设置多歌”或异常实体时，按以下链条查证：

| 环节 | 核对内容 |
| --- | --- |
| REQUEST | 当次 ref 对应的实例、卡文、数量上限与合法候选；重复卡不合并实体 |
| `--input model` | 原始 RESPONSE／MODEL_OUTCOME 正文、各次尝试、校验与失败事件 |
| `--input submit` | 最终来源 MODEL／FALLBACK／MECHANICAL、选择及物化后的命令实体 |
| `--input authority` | 接受、拒绝和命令记录；不把接受等同效果完全结算 |
| 后续 SAMPLE／公开事件／终局附件 | 选择带来的实际状态与得分；注明跨采样区间 |

`--input model` 返回事件数组，不会从 SUBMIT 反推原文，也不会把矛盾文本自动修成合法选择。例如 `--field 0.payload.outcome.text` 可查看首项 Codex MODEL_OUTCOME 的正文；先核对事件 stage，HTTP RESPONSE 的字段结构可能不同。重试或失败保留各自 materialId，不能拿第一次说明解释之后的兜底动作。

原始回答已经自相矛盾且引用、实体、命令一致，结论是**模型输出一致性错误**；即使数量合法，也不能淡化为普通风险偏好。框架引用、命令或状态实际偏离可复现时再定位代码；当前源码只能帮助解释路径，不能代替旧局原始证据。没有收到事实、收到但没使用、手册与卡文冲突、规则预算错误、随机失败和策略取舍分别记载。

## 3. 比较完整可执行路线

对替代方案至少核算：每步支付与剩余能量、手牌增减、槽位／登场限制、回收目标、指定色、总 HEART、活跃 BLADE、LIVE 开始／成功能力和结算时点。明确哪些能力尚未结算、声援仍未知，不用之后抽到的牌补路线。

特别保留三种差别：

- **周转与表演：** 不可达 LIVE 在本轮已放弃表演时可以合法周转；加入另一张 LIVE 拖垮原本可尝试的单曲是另一种问题。不能以“选了不可达 LIVE”统一判错或写拒绝规则。
- **成功与竞争：** 印刷成功概率／账面心刀只是局部参考；歌曲加分、合并需求、双方公开成功 LIVE 进度和同分规则决定能否挡住终局。盖牌阶段不能利用对手未揭示的歌。
- **准备与终点：** 自送后少人、结束时余能、同费用换手都需连同取歌、补场、补心、保留核心的用途分析；LIVE 开始能力可能改变设置时的印刷上限，已经发生的声援也不能被之后的待机倒改。

未进行权威分支重放的替代只标“费用／候选可核算，完整执行及结果待验证”。自然终局也只证明实际路线的结果；理论上限不是成功率，原局输赢不能证明替代必胜。

## 4. 累积笔记与下一轮

用户指定既有复盘文档时，维护样本索引、跨局结论及修复／验证状态，保留旧局检查时间、配置差异、来源和关键决定证据。新增局只记录改变结论的转折；同类问题合并代表证据，重复环境、完整逐回合过程和全部来源字段留在原始材料中按需查询，不逐局追加长篇分析。样本增多时正文只保留支持当前结论或版本对比的代表局和待验证分支，其余回查原始材料及 Git 历史。定期压缩正文，保留自然结束／中断、证据缺口与替代未验证的边界，不能把旧局观察改成新版本的验证结果；用户明确要求完整逐局报告时按其范围处理。

跨局比较还要保留对手、先后手、模型／思考配置、冻结手册版本和数据语言。没有策略变更的新增胜局不叫优化效果；不同模型、对手或资料来源的样本不能直接并成同一实验胜率。用量口径以实际 provider／本局计费字段为准，缓存与未缓存分列，不对已经表示未缓存的输入再次扣缓存。未知人民币费用保持未知，订阅 token 不换算成 API 人民币账单。

用户只要求积累复盘时，到笔记和证据归档结束。已授权优化时，从重复证据提出少量修改假设，冻结原版，记录改了什么、期待改善哪个行为、如何验证；规则／执行错误先做可复现核验，策略改进优先写相关构筑手册。试打使用[既有自对弈运行器与账本](../../../../docs/ai-battle/self-play.md)，本地订阅配置另见[本地 Codex](../../../../docs/ai-battle/local-codex.md)。不复制另一套建局、鉴权、计费或规则实现到本技能。

继续试打沿用用户已授权的模型、次数与总预算，核对实际服务进程及新局冻结预算；修改环境文件不代表在途局已变化。单局停止、未知用量或超过预算时保留中断样本，不自动增加轮数或抬高额度。改进验证以目标错误是否减少、完整路线是否兑现及人工实测为依据，小样本胜负只作观察。
