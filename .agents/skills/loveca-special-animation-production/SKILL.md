# Loveca 专属动画制作与接入

把角色或歌曲特色转化为玩家能看懂的规则反馈，并完成用户授权范围内的真实对局接入。效果能在预览页播放、代码已 commit、正常对局会触发，是三个独立事实；不要用其中一个代替另一个。

## 先确定本次交付

用户只要求方案时保持只读；明确要求先做原型时交付可反复观看、操作的原型，并说明尚未接入正常对局。用户已授权实施或正式接入时，完成源码接线、运行素材和验证，不默认停在预览页，也不为每阶段增加一次批准。仅在用户明确要求视觉认可后再接入时等待该认可。

核对本次工作树、分支、未提交改动与服务实际目录，遵守当前 `AGENTS.md` 的并行开发边界。端口只是环境入口，不是功能是否正式接入的标志；查看它实际使用的前后端代码和构建，不把“重启一个端口”当作接入步骤。

说明触发卡号、罕度范围和素材印刷之间的关系。全罕度或仅 SEC 由本次约定决定，动画限制不能改变同基础编号的规则覆盖。费用门槛、声音、时长与视觉母题也不沿用某次试作的临时偏好作为通用规则。

## 设计与素材

先从角色特征、道具、关系或歌曲意象中选定一个可辨认的主动作，再安排来源、传递、接收和收势；不要只替换颜色便称为角色专属动画。用户要求网络灵感或角色设定需查证时，优先官方人物介绍、歌曲与公开演出资料，区分来源事实和创作联想；规则资格仍以任务指定卡牌数据为准。

优先保留已确认的主演出，只修改用户指出的段落。普通登场与特殊换手、有效复制与无效弃牌等差异要可观察。素材制作、人物自然度、重绘说明与俯视落场用 [卡牌登场制作](../loveca-card-entrance-production/SKILL.md)，不要强迫歌曲或技能演出套用人物登场构图。只有制作人物动作时才读其中的人物质量参考。

正式资源由客户端构建可解析的 import、登记或已有资源分发路径提供。保留素材来源、取景与重绘局限，确保离开预览服务器仍能加载；不得依赖 `/song.png` 等仅由独立预览中间件提供的地址、个人绝对路径或仓库外临时文件。原型沿用现有位置，不为搬素材清理无关文件。

LIVE 卡方向须区分原始横图、牌桌纹理和区域旋转。先核对正式图片服务与共用卡牌组件的契约，必要时在预览素材入口归一化；不要为了单个预览修改全局图片方向。歌曲中央展示可用独立横图，牌桌继续采用既有方向规则。改变公共图片链路时验证真实手牌、换牌面板和 LIVE 区，而不只看中央演出。

## 原型与正式链路

预览与正式对局共用绘制组件、素材及时间线。需要可操作测试窗口时使用真实 `GameBoard` / `GameSession` / 命令与玩家投影，支持拖牌、发动效果及推进阶段；工具栏可以重置夹具、重播、减速和定格，手动重播不改变规则状态，也不能成为唯一触发入口。

接入前读取 [接入地图与验收要点](references/integration-map.md)，沿着“权威成功事件或效果边界 → 公开投影 → 共用播放器 → ACK／超时 → 原流程续接”逐段核对。React 不从手牌、卡组或完整权威快照推断复制资格、换手来源或加分人数；只使用规则端已确定的公开信息。

明确演出是在选择、授予、发动还是结算成功后发生。待选效果队列不等于已选中的效果；弃牌不等于成功取得能力；同槽覆盖不等于实际换手。先完成原有选择与不可拆的费用步骤，再在安全边界演出。持久绳结、能力标记等依附真实能力的存续状态，不能仅靠动画结束定时器移除。

复用现有设置、模式范围、遮挡、权威等待、跳过和超时，不为每张卡复制一套控制器或服务器定时器。演出结束不能冒充效果确认；手动确认和“顺序发动”要分别处理，自动批次应在演出后继续原批次，不额外制造确认，也不漏播或重复结算。降低动态、资源失败、切换窗口及来源失效时须能收尾；已结束窗口不因恢复历史而补播。

## 验收与交付

按 [动画验收](../animation-verification/SKILL.md) 选取能证明本次改动的浏览器和 focused tests，不为未修改的表现重复全套检查。原型定格只证明绘制；正常对局触发需要实际命令与投影证据。对墙打和联机服务层使用确定性测试检查各自的等待语义，测试夹具不能代替尚未进行的真实账号或生产验收。

交付前核对以下与本次变更相关的事项：

- 正常入口可触发；存在多个效果时仅在轮到目标效果时播放，自动顺序也可继续；观察演出前、结束后、确认后的规则状态，确认没有重复加分、抽牌或授予。
- 双方投影不泄漏隐藏卡；未满足条件、过期 ACK、跳过、超时及恢复不阻塞；原有模式与特效关闭分支仍有效。
- 正常速度观感、真实牌桌位置与方向、桌面和窄屏、减少动态符合本次要求；资源能通过正常客户端路径加载，结束后真实卡牌与控件恢复。
- 与当前代码版本对应的测试、类型检查和必要构建已通过；实际运行的后端已加载新 workflow。不能为验收擅自推进用户复杂对局、重建数据库或操作其他工作树服务。

更新对应功能说明的启用状态、触发与续接、素材来源和已验收范围。涉及 workflow 或公开字段时按 [卡效治理](../loveca-card-effect-governance/SKILL.md) 更新受影响的登记，不把纯动画写成新增规则效果。

提交按用户授权和 [提交检查](../prepare-for-git-commit/SKILL.md) 执行。正式接入后重写原型提交的标题和正文，删除“仅原型、未接入”这类过时声明；stage 时核对运行素材、新增源码和相关文档都在范围内，保留其他改动。合并与发布仍分别需要相应授权。

最终用简短文字分别交代：本次完成的是原型还是正常对局接入、在哪里实际验证、是否已提交。只在有部署证据时称“生产已生效”。本地服务会读取未提交文件，通过 Git 发布通常只包含已提交内容；仅当用户对此困惑时解释，不用端口名称替代功能状态。
