# Frontend Design

设计判断服务用户的任务、可读性与操作结果。独特风格是可以选择的表达方式，不是每次修改都要承担的目标。用户明确的方向、现有产品规范与实测证据优先于通用审美偏好。

## 先确定当前工作

- 明确使用者、当前任务、主要动作和必须同时看见的信息；从现有页面、代码、截图和用户反馈中推断，不为已经明确的条件重复提问。
- 新页面或明确重设计：选择与产品内容有关的视觉方向，再决定布局、层级与样式。
- 现有界面维护：继承已确认的字体、颜色、组件和交互。先修复本次问题，不因局部需求重做页面或强制加入新字体、装饰、动效。
- 密集界面：先判断哪些信息会改变用户当前的选择，再安排扫描顺序。由状态、操作或页面上下文已经表达的数量、标签和说明，不为展示完整数据而重复常驻；需要比较数量或追踪进度的任务则保留对应信息。
- 用户反馈「重、刻意、拥挤」时，先检查重复信息、嵌套容器、说明长度和控件占行，再调整颜色、边框与间距。局部减轻样式前，也要判断这一层内容或容器是否需要存在。

本仓库按需查阅[产品视觉系统](../../../docs/ui-design/product-visual-system.md)和[前端规范](../../../docs/ui-design/standard.md)。对战命令、隐藏信息与模式边界遵守对应领域约定；不要把 UI 外观修改扩展成规则变更。

## 决策与实现

- 复用语义 token 和已有组件；同一职责与密度下的控件保持一致，按信息层级区分主操作、次操作与静态摘要。复用组件不要求每段信息都有容器，也不要求所有选择项都有按钮的体量。只有出现实际复用或明确需求时才提取抽象。
- 一致性保留角色区别：信息标签、数量、可点击动作属于同一视觉体系，但静态信息不伪装成按钮，普通操作不随意借用危险或成功语义色。
- 用位置、分组和留白表达关系；颜色、边框、图标和动效应有可说明的信息用途。不为避免“模板感”加入无关差异。
- 模式或筛选会影响后续操作时，用稳定的图形、位置或选中形态辅助名称，并在当前任务中延续必要上下文。避免仅靠反复阅读小字辨别当前环境，也不只靠颜色；不熟悉的图标保留可见文字，不把某个图标当作通用含义。
- 不为视觉整齐隐式改变稳定排序、输入焦点或操作落点；需要排序、重组或动画时说明它支持的用户意图。
- 文案使用玩家或产品用户能够理解的名称、动作和结果；说明放在真正影响选择或后果的位置。控件名称与当前状态已能说明的内容不再附一段解释，规则提示也不在多个层级反复出现；保留权限、关键后果、错误恢复和不可操作原因。
- 长内容按任务选择换行、摘要或省略。列表中的次要文字应有稳定的空间预算；全文确有用途时，优先复用已有详情或轻量查看入口，支持触屏和键盘，不只依赖 hover 或 `title`。影响当前决定的关键内容不能为了缩短行高被截掉。

## 可读性与交互

- 对比度依据文字旁实际背景计算，包含透明表面、图像和祖先 opacity。复杂或可变背景可用字形轮廓或局部表面改善可读性，选择应保留用户确认的视觉风格；模糊、阴影或“看起来更深”不能代替测量。
- 遵循适用的 WCAG 要求：普通文字 4.5:1，必要的非文字控件信息 3:1；小字与细字应留出余量。禁用状态仍应可辨认，不能用整体淡化破坏重要信息。
- 目标尺寸按设备、密度和替代操作选择，核对 WCAG 2.2 的 24px AA 基线及例外；重要触屏操作优先争取更大热区。分别设计触控热区与视觉体量，足够的热区不要求大块填色、厚边框或多行说明；也不能以轻量为由让操作难以发现。
- 定义可用、hover、focus-visible、按下、禁用、等待、失败和完成状态中当前操作实际需要的部分。键盘、触屏与鼠标应有可完成的路径。
- 响应式布局应保留主要动作和核心信息；不要仅隐藏溢出或滚动条来掩盖尺寸问题。不要自行增加用户不需要的内部滚动。
- 手机弹层检查整段任务的长度与主操作位置。固定操作区不能遮住字段或错误提示；失败后保留可修改的输入与选择，并让用户看见原因。错误存在于 DOM 中不等于用户看得见。

## 使用研究与规范

用户要求调研、现有做法存在疑问或出现新的设计权衡时，再查相关研究、正式规范和权威产品指南。

- 区分规范性要求、研究结果与本项目的设计推论；研究中的条件和限制不能省略，也不能把一种配色或案例升级为普遍规则。
- 从案例提取它解决的识别、选择或反馈问题，再判断是否适合当前密度与风格；采用某个设计系统的组件外观本身不是方案成立的依据。
- 优先原论文、标准正文及官方设计系统，记录支持当前决策的具体来源；无需把一次任务的案例或完整资料复制进 skill。
- 美感与偏好通过产品语境、用户讨论和真实画面评估，不用“最佳实践”替代具体判断。

## 验证与交付

先在用户指出的视口与有代表性的数据下验证方向，再按影响补充主题、视口和异常状态。列表与表单要看实际有内容、长内容及错误反馈的画面，不能只看空态。使用真实浏览器截图检查可读性、重叠、裁切与层级，并对照用户指出的问题评估阅读负担、行高和操作发现性；流程通过或没有溢出不能代替这一判断。

对规则、权限、接口和脆弱交互写行为验证；纯外观调整优先使用浏览器与截图证据，不为匹配实现细节堆测试。交付说明实际变化、验证结果、设计取舍和仍未覆盖的边界。

临时截图、录屏与报告留在本地验证目录，不自动纳入暂存或提交；既有视觉基线按仓库规范与用户要求处理。需要读图验收不代表需要把生成的图片交付到仓库。
