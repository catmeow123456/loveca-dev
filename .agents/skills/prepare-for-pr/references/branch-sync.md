# 分支同步与冲突处理

适用：PR 基线同步、合并性检查、rebase 和作者 main 对照。只读审查不执行分支改写；完整准备按用户及既有授权完成必要同步，推送／远端历史改写另按授权范围处理。

- 核实当前分支、HEAD、目标 base 和 remote 的实际 URL；作者仓库为 `catmeow123456/loveca-dev`，不假定 `origin` 指向作者。完整准备需要更新远端基线时，禁用子模块递归并 fetch 所需目标 ref，记录实际 SHA；不默认 checkout 本地 main 再 pull。用户指定固定本地基线或排除联网同步时直接使用该基线。
- 作者远端 main 的独立副本复用当前仓库上级目录的 `loveca_main`，未经要求不另建 checkout；先核实该目录身份与工作树状态，再更新，保持其中 `llocg_db` 未初始化。目录不存在时不为普通比较自动创建副本，可用已核实的 refs 完成独立检查。
- 合并性检查可使用支持的 `git merge-tree --write-tree <base> HEAD`：保留输出并区分无冲突、真实冲突和命令／仓库错误。能力不可用时使用适合当前环境的检查方式，并说明未完成的合并验证；不因版本号不同中止所有工作。
- rebase 前保护暂存／未暂存／未跟踪修改，识别已有 rebase／merge 状态。能安全隔离时保留必要恢复点并继续，不把“工作树非空”一概当成阻塞；不能安全保留部分暂存或来源不明改动时先完成独立审查，再说明阻塞。不要默认 stash 全工作树或自动 pop 用户已有 stash。
- 对获授权的目标分支 rebase 到已核实 base，按双方真实意图和测试解决可确定的冲突。只有冲突涉及无法确定的产品／规则取舍、无法保护用户修改或会重写他人共享历史时，暂停相关步骤并询问具体问题；不能仅因出现冲突就把整个任务退回给用户。
- 同步后检查最终 diff、冲突标记及受影响验证，更新 PR 文案基线。不因 rebase 机械重复与代码变化无关的全量检查。
- 仅在已授权推送且确需更新重写后的个人分支时考虑 `--force-with-lease`，先核对远端预期旧 SHA，不能覆盖非预期前进；不对作者 main 强推。没有推送授权时，完成本地准备与文案并报告状态。
