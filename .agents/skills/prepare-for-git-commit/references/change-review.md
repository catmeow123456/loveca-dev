# 改动检查与验证

适用：提交或 PR 的代码／文档检查与完整准备。只起草文案时无需加载本参考。用户指定范围和 `AGENTS.md` 决定是否修改，下面的检查不额外授权写操作。

## 对照实际差异

- 提交检查以指定范围或暂存 diff 为准；PR 检查以目标分支 merge-base 到 HEAD 的 diff 为准。先理解行为变化，再按涉及模块读取 `docs/coding-standard/` 与 `docs/README.md` 指向的相关专题章节，不通读所有总文档。
- 检查本次是否改变规则不变量、命令／投影边界、权限、并发、输入校验、错误反馈或持久化契约。列出有证据的问题、位置与实际影响，区分实现缺陷、文档滞后和未验证项。
- 文档半径按 `docs/doc_writing_guide.md`：外部行为、接口、schema、部署或架构边界改变时更新对应权威说明；局部重构、命名或测试追加通常不要求修改 AGENTS、CLAUDE、总需求和总设计。只读审查指出差异，完整准备才在范围内更新。
- 新增长期文档核对已有承载位置及 `docs/README.md` 登记。临时 TODO／PLAN／过程清单按文档规范检查；用户明确要求或正式流程指定的材料适用其例外，不机械拦截。未跟踪草稿不自动纳入提交，也不擅自清理。

## 选择必要验证

- 复用同一实际代码版本上已完成的相关验证；只有新改动、失败或未解决风险才扩大或重跑。只读审查也可运行不修改被审文件的相关本地检查，无需额外索取验证许可；不自动修复文件或重置测试环境。
- 按影响运行 `pnpm test:run <相关测试路径>`；共享规则、调度、事件或投影修改覆盖相关回归。涉及类型或编译链路时选择根／server／client 对应 TypeScript 检查。全量测试、build 和 E2E 只在影响面或用户要求需要时运行；纯文档检查格式、链接和声明一致性即可。
- 不默认将 ESLint 作为提交／PR 前置门槛，也不因既有 lint 问题扩大修改；用户明确要求或本次改动涉及 lint 配置／行为时执行对应检查。
- 必需的集成环境先检查 `package.json`、`scripts/start-test-env.sh` 和实际运行配置，复用可用环境，不套用固定 localhost 端口或硬编码环境变量。只有本任务需要且允许初始化／重置本地测试环境时才运行 `pnpm test-env:start`；不擅自推进或重置用户复杂对局。
- 修复本次引入的失败；既有失败、环境缺失及无法执行的检查如实记录，不为使全库变绿而修改无关模块，也不把环境失败当成测试通过。
- 暂存区与工作树中同一文件内容不一致时，工作树测试不能证明暂存快照通过。保留两者，必要时在隔离的临时快照验证；无法验证目标快照则明确说明，不自动重暂存用户修改。
- 对实际提交／PR 范围检查空白错误；暂存修改用 `git diff --cached --check`，未暂存修改用 `git diff --check`。已提交的分支差异检查目标 base 到 HEAD；未跟踪文件需单独检查，不能用空 diff 证明其格式正确。

交付只列实际完成的验证与有影响的限制。测试通过证明对应行为和版本，不代表所有框架、生产环境或历史数据都已验收。
